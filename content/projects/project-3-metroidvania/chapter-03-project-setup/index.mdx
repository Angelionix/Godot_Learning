## 3.1 Подготовка к разработке

Прежде чем писать код, необходимо правильно настроить проект в Godot Engine. Качественная настройка на старте экономит часы отладки позже. В этой главе мы шаг за шагом создадим проект, настроим слои столкновений, Input Map, структуру каталогов, Autoload-менеджеры и аудио-шины. Каждый шаг важен для корректной работы всех систем, которые мы будем реализовывать в последующих главах.

<GoalsList>
1. **Создать проект** в Godot 4.x с Compatibility renderer
2. **Настроить 6 слоёв столкновений** для корректной работы Hitbox/Hurtbox системы
3. **Добавить 8 действий** в Input Map для управления игроком
4. **Создать структуру каталогов** согласно архитектуре из Главы 2
5. **Зарегистрировать 6 Autoload-менеджеров** в правильном порядке
6. **Настроить Audio Bus** с тремя шинами (Master, SFX, BGM)
</GoalsList>

## 3.2 Создание проекта

Откройте Godot 4.x и создайте новый проект:

1. Нажмите **New** в окне Project Manager
2. Имя проекта: `MetroidvaniaProject`
3. Рендерер: **Compatibility** — это оптимальный выбор для 2D-игр. Он обеспечивает хорошую производительность и совместимость, чего достаточно для нашего проекта. Forward+ и Mobile рендереры избыточны для 2D.
4. Укажите путь к папке проекта и нажмите **Create and Edit**

<Callout type="tip" title="Выбор рендерера">
Compatibility renderer — лучший выбор для 2D-игр в Godot 4.x. Forward+ предназначен для 3D-проектов с продвинутым освещением, а Mobile — для мобильных устройств. Использование Compatibility гарантирует, что все 2D-функции работают корректно и с максимальной производительностью.
</Callout>

Godot создаст базовую структуру с файлом `project.godot` и пустой сценой `untitled.tscn`. Сохраните сцену как `res://scenes/main.tscn` — это будет корневая сцена нашего проекта.

## 3.3 Настройка слоёв столкновений

Слои столкновений (Collision Layers) — это фундамент боевой системы нашей метроидвании. Правильная настройка слоёв гарантирует, что Hitbox игрока сталкивается только с Hurtbox врагов, снаряды не поражают самого стрелка, а триггеры переходов активируются только игроком.

Откройте **Project → Project Settings → Layer Names → 2D Physics** и назначьте 6 слоёв:

| Слой | Имя | Назначение |
|------|-----|------------|
| 1 | `player` | Тело игрока, Hitbox и Hurtbox игрока |
| 2 | `terrain` | Статическая геометрия (TileMap, платформы, стены) |
| 3 | `enemies` | Тела врагов, Hurtbox врагов |
| 4 | `projectiles` | Снаряды игрока и врагов |
| 5 | `items` | Подбираемые предметы, ключи, улучшения |
| 6 | `triggers` | Зоны перехода между комнатами, точки сохранения |

<Insight title="Почему слои столкновений так важны">
Система Hitbox/Hurtbox работает корректно только при правильной настройке слоёв. Hitbox игрока находится на слое 1 (`player`) и проверяет столкновения со слоем 3 (`enemies`). Hurtbox врага находится на слое 3 и проверяет столкновения со слоем 1. Благодаря этому Hitbox игрока не может поразить самого игрока, а Hitbox врага не может поразить другого врага. Без этого разделения каждый снаряд поражал бы и врагов, и игрока, и другие снаряды — хаос вместо боевой системы.
</Insight>

<Callout type="warning" title="Частая ошибка: путаница layer и mask">
В Godot каждый CollisionObject2D имеет два свойства: **collision_layer** (на каком слое НАХОДИТСЯ объект) и **collision_mask** (с какими слоями объект СТОЛКИВАЕТСЯ). Частая ошибка — установить слой, но забыть маску, или наоборот. Результат: объекты проходят сквозь друг друга, и нет никаких ошибок в консоли. Всегда проверяйте оба свойства!
</Callout>

Пример настройки для игрока:

```gdscript
# Игрок: находится на слое 1, сталкивается со слоями 2 (terrain), 3 (enemies), 5 (items), 6 (triggers)
player.collision_layer = 1        # Бит 1 = player
player.collision_mask = 0b100110  # Биты 2,3,5,6

# Hurtbox игрока: находится на слое 1, маска = 0 (пассивная, проверяется Hitbox врага)
hurtbox.collision_layer = 1
hurtbox.collision_mask = 0

# Hitbox игрока: находится на слое 1, сталкивается со слоем 3 (enemies)
hitbox.collision_layer = 1
hitbox.collision_mask = 4  # Бит 3 = enemies
```

## 3.4 Настройка Input Map

Input Map позволяет абстрагировать клавиши управления от кода. Вместо проверки конкретных клавиш мы проверяем логические действия, а привязка клавиш настраивается в Project Settings. Это упрощает добавление поддержки геймпада и позволяет игроку переназначать клавиши.

Откройте **Project → Project Settings → Input Map** и добавьте 8 действий:

| Действие | Клавиши | Описание |
|----------|---------|----------|
| `move_left` | A, Стрелка влево | Движение влево |
| `move_right` | D, Стрелка вправо | Движение вправо |
| `jump` | Space, W, Стрелка вверх | Прыжок (и двойной прыжок) |
| `attack` | J, ЛКМ | Атака ближнего боя |
| `dash` | K, Shift | Рывок (после разблокировки) |
| `shoot` | L | Выстрел снарядом (после разблокировки) |
| `inventory` | I, Tab | Открыть инвентарь |
| `pause` | Escape | Пауза игры |

<Callout type="info" title="Дублирование клавиш">
Для каждого действия указывайте и клавишу WASD, и клавишу со стрелкой. Это стандарт в игровой индустрии: часть игроков предпочитает WASD, часть — стрелки. Не заставляйте игрока менять привычную раскладку.
</Callout>

Для добавления действия нажмите **Add New Action**, введите имя (например, `move_left`), затем нажмите **+** рядом с действием и добавьте событие **Key** с нужной клавишей. Повторите для каждой клавиши в столбце «Клавиши».

## 3.5 Создание структуры каталогов

Структура каталогов — это скелет проекта. Хорошая организация файлов упрощает навигацию, предотвращает конфликты при командной разработке и делает проект масштабируемым. Мы используем структуру, описанную в Главе 2.

Создайте следующие каталоги через FileSystem в Godot или через файловую систему ОС:

```
res://
├── scenes/
│   ├── player/         # Сцена игрока и компоненты
│   ├── enemies/        # Сцены врагов и босса
│   ├── rooms/          # Сцены комнат (13 комнат)
│   ├── items/          # Сцены подбираемых предметов
│   ├── ui/             # HUD, инвентарь, пауза
│   └── common/         # Общие сцены (damage_number, projectile)
├── scripts/
│   ├── managers/       # Autoload-менеджеры
│   ├── states/         # Состояния FSM игрока
│   ├── components/     # Переиспользуемые компоненты
│   └── autoload/       # Точка входа Autoload
├── resources/
│   ├── abilities/      # .tres-файлы способностей
│   ├── items/          # .tres-файлы предметов
│   └── enemies/        # .tres-файлы параметров врагов
├── assets/
│   ├── sprites/        # Спрайты персонажей и врагов
│   ├── tilesets/       # Тайлсеты для TileMap
│   ├── audio/          # Звуковые файлы (SFX и BGM)
│   └── fonts/          # Шрифты
└── project.godot
```

<Callout type="tip" title="Создание каталогов в Godot">
В Godot 4.x пустые каталоги не отображаются в FileSystem. Создайте каталог, затем добавьте в него хотя бы один файл (можно пустой `.gdkeep` файл), чтобы Godot увидел каталог. Альтернативно — создайте каталоги через файловую систему ОС и перезапустите Godot.
</Callout>

## 3.6 Регистрация Autoload-менеджеров

Autoload — это механизм Godot для создания глобальных синглтонов. Каждый менеджер будет доступен из любого скрипта по своему глобальному имени (например, `GameManager.pause_game()`). Порядок регистрации важен, потому что менеджеры могут ссылаться друг на друга при инициализации.

Откройте **Project → Project Settings → Autoload** и зарегистрируйте 6 менеджеров в следующем порядке:

| Порядок | Путь | Глобальное имя | Описание |
|---------|------|----------------|----------|
| 1 | `res://scripts/managers/game_manager.gd` | `GameManager` | Глобальное состояние, пауза, регистрация игрока |
| 2 | `res://scripts/managers/ability_manager.gd` | `AbilityManager` | Разблокировка и проверка способностей |
| 3 | `res://scripts/managers/inventory_manager.gd` | `InventoryManager` | Инвентарь, предметы, экипировка |
| 4 | `res://scripts/managers/scene_manager.gd` | `SceneManager` | Переходы между комнатами |
| 5 | `res://scripts/managers/save_manager.gd` | `SaveManager` | Сохранение и загрузка игры |
| 6 | `res://scripts/managers/audio_manager.gd` | `AudioManager` | Воспроизведение звуков и музыки |

<Callout type="danger" title="Порядок регистрации критически важен!">
SaveManager ссылается на GameManager, AbilityManager и InventoryManager при сохранении и загрузке. Если SaveManager загрузится раньше них, обращение к ещё не инициализированным менеджерам вызовет ошибку. Аналогично SceneManager ссылается на GameManager для получения ссылки на игрока. Всегда соблюдайте указанный порядок.
</Callout>

Пока файлы менеджеров ещё не созданы — мы реализуем их в Главе 4. Сейчас достаточно зарегистрировать пути, чтобы структура проекта была готова. Создайте пустые `.gd` файлы-заглушки с минимальным содержимым:

```gdscript
# game_manager.gd — заглушка (полная реализация в Главе 4)
extends Node
```

## 3.7 Настройка Audio Bus

Звук — важнейшая часть атмосферы метроидвании. Правильная настройка аудио-шин позволяет раздельно управлять громкостью звуковых эффектов и фоновой музыки, а также добавлять эффекты (например, Low-pass filter для приглушённого звука в паузе).

Откройте нижнюю панель **Audio** и создайте три шины:

1. **Master** — корневая шина (создана по умолчанию). Управляет общей громкостью игры
2. **SFX** — дочерняя шина Master. Для звуковых эффектов (удар, прыжок, подбор предмета). Установите громкость: **-6 dB**
3. **BGM** — дочерняя шина Master. Для фоновой музыки. Установите громкость: **-12 dB**

<Callout type="info" title="Почему SFX громче BGM">
В метроидвании звуковые эффекты дают моментальную обратную связь о действиях игрока — они должны быть отчётливо слышны. Фоновая музыка создаёт атмосферу, но не должна заглушать SFX. Отношение -6 dB / -12 dB — это стандартный баланс, при котором эффекты слышны чётко, а музыка создаёт фон, не отвлекая.
</Callout>

После настройки сохраните bus layout: нажмите **Save** на панели Audio и сохраните как `res://assets/audio/default_bus_layout.tres`. В `project.godot` укажите этот файл в настройке `audio/buses/default_bus_layout`.
