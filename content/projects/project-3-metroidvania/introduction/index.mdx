Проект 3 — Метроидвания — первый по-настоящему масштабный проект курса. Кликер дал основы GDScript, космический шутер — физику и столкновения. Теперь мы создаём полноценную 2D-метроидванию: взаимосвязанный мир, система способностей с разблокировкой, AI врагов, сохранение прогресса. Десятки сцен, сотни скриптов — хаос в архитектуре здесь не прощается.

Метроидвания — жанр из Metroid и Castlevania: Symphony of the Night. Его суть: большой взаимосвязанный мир, исследуемый нелинейно, и способности, открывающие ранее недоступные области. Получил двойной прыжок — добрался до верхних платформ. Нашёл дэш — пересёк пропасть. Цикл «исследование → открытие → возвращение» (backtracking) — сердцевина жанра.

## Почему именно Метроидвания?

После линейного космического шутера метроидвания — скачок в архитектурной сложности. Нет изолированных уровней — единый мир, где каждая комната связана с остальными. Как комнаты ссылаются друг на друга? Как глобальное состояние хранится между сценами? Как способности влияют на доступность областей? Всё это нужно продумать до первой строки кода.

Жанр объединяет критические навыки. State Machine через AnimationTree — необходимость: персонаж стоит, бежит, прыгает, атакует, получает урон, и состояния переключаются корректно. Система способностей — граф зависимостей: способность A открывает область B, где лежит C для области D. AI врагов на конечном автомате (патрулирование → преследование → атака → возврат) готовит к сложным поведенческим моделям.

<Insight title="Backtracking — архитектурный вызов">

Когда игрок получает способность и возвращается в пройденную зону, мир должен отреагировать: открыть пути, показать новые объекты. Система сохранений — не опция, а фундамент жанра.

</Insight>

## Git для геймдева

Масштабный проект требует системы контроля версий с первого дня. Без Git разработка метроидвании — поход без карты.

### .gitignore для Godot

```gitignore
# Godot 4
.godot/
*.tmp
*.import

# OS / IDE
.DS_Store
.vscode/

# Экспорт
export_presets.cfg
builds/
```

<Callout type="warning" title=".godot/ — строго в игнор">

Кэш импорта пересоздаётся при открытии проекта. Коммитить его — значит создавать бесконечные конфликты.

</Callout>

### Git LFS для бинарных ассетов

Бинарные файлы (спрайты, звуки) раздумают репозиторий. Git LFS хранит их отдельно:

```bash
git lfs install
git lfs track "*.png"
git lfs track "*.ogg"
git lfs track "*.wav"
git add .gitattributes
git commit -m "chore: configure Git LFS"
```

<Insight title="LFS окупается быстро">

Без LFS 20 итераций спрайта на 2 МБ = 40 МБ в истории. С LFS хранятся только указатели, файлы подгружаются по необходимости.

</Insight>

### Стратегия ветвления

- **`main`** — стабильная версия
- **`feature/имя`** — для системы (`feature/ability-system`, `feature/enemy-ai`)
- **`experiment/имя`** — для рискованных экспериментов

### Конвенция коммитов

- `feat:` — новая функциональность
- `fix:` — исправление бага
- `refactor:` — рефакторинг без изменения поведения
- `assets:` — добавление или замена ресурсов
- `chore:` — настройка проекта

```bash
git commit -m "feat: add dash ability with trail effect"
git commit -m "fix: enemy AI stuck on patrol path"
git commit -m "assets: add tileset for crystal cavern"
```

<Callout type="tip" title="Коммитьте часто">

Коммитьте после каждого логического шага. Сообщение должно отвечать на вопрос «что и зачем?».

</Callout>
