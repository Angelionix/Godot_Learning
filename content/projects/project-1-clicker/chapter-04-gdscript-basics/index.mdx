GDScript — это высокоуровневый скриптовый язык, созданный специально для Godot Engine. Его синтаксис похож на Python, что делает его одним из самых доступных языков для начинающих разработчиков игр. Однако не стоит путать его с Python: GDScript глубоко интегрирован в движок и предоставляет прямой доступ ко всем API Godot, включая систему узлов, сигналы, физику и рендеринг. В этой главе мы рассмотрим базовые конструкции языка, которые понадобятся для реализации нашего кликера.

## 4.1 Переменные и типы данных

GDScript поддерживает динамическую типизацию, но также позволяет явно указывать типы переменных, что рекомендуется для предотвращения ошибок. В нашей игре мы будем использовать явную типизацию везде, где это возможно — это хорошая привычка, которая поможет вам при переходе на C++ в будущих проектах, где статическая типизация обязательна.

Рассмотрим основные типы данных, которые нам понадобятся:

```gdscript
# Числовые типы
var currency: int = 0              # Целое число — основная валюта
var click_power: int = 1           # Целое число — доход за клик
var auto_click_power: int = 0      # Целое число — пассивный доход в секунду
var cost_multiplier: float = 1.5   # Число с плавающей точкой — множитель стоимости

# Строки
var game_title: String = "Кликер"
var upgrade_name: String = "Автокликер"

# Логический тип
var is_auto_click_active: bool = false

# Массивы (динамические списки)
var upgrades: Array = []                 # Нетипизированный массив
var costs: Array[int] = [10, 50, 200]   # Типизированный массив целых чисел

# Словари (ключ-значение)
var save_data: Dictionary = {
    "currency": 0,
    "click_power": 1,
    "auto_click_power": 0,
}
```

<Callout type="info" title="Почему int для валюты, а не float?">

Это осознанное архитектурное решение. Целые числа не подвержены проблемам точности с плавающей точкой — вы никогда не получите `currency = 0.99999999` вместо `1`. В idle-играх, где операции с валютой происходят тысячи раз, накопление ошибок округления float может привести к расхождению между отображаемой суммой и реальной. `int` гарантирует точность. Единственное место, где мы используем `float` — это вычисление стоимости (через `pow()`) и множители, но результат всегда конвертируется обратно в `int` через `int()`.

</Callout>

<Insight title="Подчёркивания в числах">

Обратите внимание на использование подчёркивания в числовых литералах (`1_000_000`) — это допустимый синтаксис GDScript, улучшающий читаемость больших чисел. Компилятор игнорирует подчёркивания, поэтому `1_000_000` и `1000000` — одно и то же число.

</Insight>

## 4.2 Функции

Функции в GDScript определяются ключевым словом `func`. Как и переменные, функции могут иметь явную типизацию параметров и возвращаемого значения. Функции — это строительные блоки вашей игры: каждая функция должна выполнять одну чётко определённую задачу.

```gdscript
# Функция без возвращаемого значения
func add_currency(amount: int) -> void:
    currency += amount
    currency_changed.emit(currency)

# Функция с возвращаемым значением
func calculate_upgrade_cost(level: int) -> int:
    return int(base_cost * pow(cost_multiplier, level))

# Функция форматирования больших чисел
func format_number(value: int) -> String:
    if value >= 1_000_000_000:
        return "%.2fB" % (value / 1_000_000_000.0)
    elif value >= 1_000_000:
        return "%.2fM" % (value / 1_000_000.0)
    elif value >= 1_000:
        return "%.1fK" % (value / 1_000.0)
    else:
        return "%d" % value
```

<Callout type="tip" title="Обратите внимание на типы">

- Функция `format_number` принимает `int`, но внутри использует деление на `float` для вычисления суффикса. Это корректно: `value / 1_000_000.0` даёт результат типа `float`, который форматируется с нужным числом знаков после запятой. Результат — строка с суффиксом (например, `"1.50M"`).
- Функция `calculate_upgrade_cost` использует `int()` для конвертации результата `pow()` (возвращает `float`) в целое число. Это необходимо, потому что `pow(10, 2.5)` вернёт `316.227...`, а нам нужно `316` — стоимость всегда целое число.

</Callout>

## 4.3 Сигналы

Сигналы (Signals) — это одна из ключевых концепций Godot, реализующая паттерн Observer (Наблюдатель). Сигнал позволяет одному узлу уведомлять другие узлы о произошедшем событии, не требуя прямой ссылки на них. Это создаёт слабую связанность между компонентами, что критически важно для поддерживаемости кода в проектах любого размера.

В Godot есть два вида сигналов:

1. **Встроенные** — определённые в классах узлов (например, `Button.pressed`, `Timer.timeout`)
2. **Пользовательские** — определённые вами (например, `currency_changed`)

```gdscript
# Пользовательский сигнал
signal currency_changed(new_amount: int)
signal upgrade_purchased(upgrade_name: String)

# Испускание сигнала
func add_currency(amount: int) -> void:
    currency += amount
    currency_changed.emit(currency)

# Подключение сигнала (в _ready)
func _ready() -> void:
    currency_changed.connect(_on_currency_changed)

# Обработчик сигнала
func _on_currency_changed(new_amount: int) -> void:
    currency_label.text = format_number(new_amount)
```

<Callout type="info" title="Преимущества сигналов перед прямым вызовом">

Источник сигнала не знает и не должен знать, кто и как на него реагирует. Вы можете:

- Подключить к одному сигналу **несколько обработчиков**
- Отключать их **динамически** во время работы
- Даже подключать **сигналы к сигналам**

В нашей кликер-игре сигнал `currency_changed` будет использоваться для обновления UI, проверки достижений и запуска визуальных эффектов — и все эти подсистемы не знают друг о друге.

</Callout>
