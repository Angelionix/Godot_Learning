Вы завершили разработку кликер-игры — пора показать её миру! В этом разделе мы разберём процесс экспорта игры из Godot Editor, настройку пресетов для разных платформ и подготовку дистрибутива. Это первый раз, когда вы публикуете свой проект, поэтому мы подробно рассмотрим каждый шаг. Навык экспорта понадобится вам в каждом последующем проекте курса, а по мере роста сложности игр будут добавляться новые нюансы — например, экспорт C++-расширений в Проекте 4 или WebGL-ограничения в Проекте 5. Сейчас мы закладываем фундамент.

## Зачем экспортировать?

Запуск игры из редактора (кнопка Play) — это запуск в отладочном режиме. Отладочный билд включает дополнительную информацию для профилировщика, не сжимает ресурсы и запускается только на вашем компьютере. Экспортированный билд — это то, что получит игрок: оптимизированный, сжатый, автономный исполняемый файл, который работает без установленного Godot Editor. Разница может быть значительной: отладочный билд кликера может занимать 50 МБ, тогда как экспортированный — 15 МБ, и работать заметно быстрее за счёт отсутствия отладочных проверок.

Кроме того, экспорт — это момент истины для вашего проекта. Многие проблемы проявляются только в экспортированном билде: отсутствующие ресурсы, неверные пути к файлам, проблемы с кодировкой, зависимость от специфичных настроек редактора. Если ваша игра работает в редакторе, но ломается после экспорта — это сигнал о том, что где-то нарушена архитектура (например, жёсткие пути к файлам вместо `res://`).

## Настройка Export Presets

Export Preset — это набор параметров для конкретной платформы: тип билда, сжатие, иконка, разрешения экрана и многое другое. Presets создаются один раз и сохраняются в файле `export_presets.cfg` внутри проекта. Мы настроим три пресета: Windows Desktop, Web (HTML5) и Android. Это покроет основные платформы для кликер-игры.

### Шаг 1: Установка экспортных шаблонов

Экспортные шаблоны (Export Templates) — это предсобранные версии Godot Engine для каждой платформы. Без них экспорт невозможен. Шаблоны скачиваются один раз для каждой версии Godot.

1. Откройте **Editor → Manage Export Templates**
2. Нажмите **Download and Install** (текущая версия будет выбрана автоматически)
3. Дождитесь завершения загрузки (~500 МБ для всех платформ)

Если загрузка через редактор не работает (например, из-за прокси), шаблоны можно скачать вручную с официального сайта Godot и распаковать в директорию `~/.local/share/godot/export_templates/4.3.stable/` (Linux) или `%APPDATA%\Godot\export_templates\4.3.stable\` (Windows). Имя папки должно точно соответствовать версии движка — если вы используете Godot 4.3.1, папка должна называться `4.3.1.stable`.

### Шаг 2: Создание пресета Windows Desktop

1. Откройте **Project → Export**
2. Нажмите **Add... → Windows Desktop**
3. Настройте параметры:

| Параметр | Значение | Объяснение |
|---|---|---|
| Name | Windows Desktop | Название пресета (отображается в списке) |
| Export Path | `builds/clicker-idle-windows/` | Директория для билда |
| Architecture | x86_64 | 64-битная версия — стандарт для современных ПК |
| Custom Features | (пусто) | Пока не нужны |
| Encryption Key | (пусто) | Шифрование скриптов нужно только для коммерческих проектов |

4. Перейдите на вкладку **Resources**:

| Параметр | Значение | Объяснение |
|---|---|---|
| Export Mode | Export all resources in the project | Все ресурсы включены |
| Filters to export non-resource files | `*.json` | Включить JSON-файлы (наши сохранения) |
| Filters to exclude from export | (пусто) | Пока нет файлов для исключения |

5. Перейдите на вкладку **Features**:

| Тег | Описание |
|---|---|
| `windows` | Автоматически добавляется Godot |
| `desktop` | Автоматически добавляется Godot |

Теги фич позволяют проверять платформу в коде через `OS.has_feature("windows")`. Это полезно для условной логики — например, отображать клавиатурные подсказки на ПК и тач-подсказки на мобильных устройствах.

6. Перейдите на вкладку **Application**:

| Параметр | Значение | Объяснение |
|---|---|---|
| Product Name | Clicker Idle | Отображаемое имя игры |
| File Description | Idle/Clicker game built with Godot | Описание в свойствах файла |
| Company Name | (ваше имя) | Имя разработчика |
| Icon | `res://assets/icon.ico` | Иконка приложения (см. ниже) |

### Шаг 3: Создание пресета Web (HTML5)

Web-экспорт позволяет запускать игру прямо в браузере — идеальный вариант для демонстрации кликера друзьям без необходимости скачивать файл.

1. Нажмите **Add... → Web (HTML5)**
2. Настройте параметры:

| Параметр | Значение | Объяснение |
|---|---|---|
| Name | Web (HTML5) | Название пресета |
| Export Path | `builds/clicker-idle-web/` | Директория для билда |

3. Вкладка **Resources** — аналогично Windows Desktop

4. Вкладка **Application**:

| Параметр | Значение | Объяснение |
|---|---|---|
| Product Name | Clicker Idle | Отображаемое имя в заголовке вкладки |
| Icon | `res://assets/icon.png` | PNG-иконка (не ICO, как для Windows) |

5. Вкладка **HTML5** — важные настройки для кликера:

| Параметр | Значение | Объяснение |
|---|---|---|
| VRAM Texture Compression | For Desktop | Сжатие текстур для браузера |
| Ensure Cross Origin Isolation Headers | Включено | Необходимо для SharedArrayBuffer |

Обратите внимание: Web-версия Godot использует WebGL 2.0 и имеет ограничения. Для нашего кликера они не критичны, но о них нужно знать. Во-первых, `FileAccess` работает ограниченно — `user://` хранится в localStorage браузера (лимит ~5–10 МБ). Наш SaveManager использует JSON-файлы, которые автоматически мапятся в localStorage при Web-экспорте — это работает без изменений кода. Во-вторых, нет доступа к файловой системе пользователя — FileDialog не работает в браузере. Микровызов №2 (экспорт/импорт сохранений) потребует другой подход для Web-версии. В-третьих, звук не воспроизводится до первого взаимодействия пользователя с страницей — это ограничение браузера, а не Godot.

### Шаг 4: Создание пресета Android (обзор)

Android-экспорт требует установки Android SDK и JDK — это более сложный процесс настройки окружения. Мы опишем его кратко, а полную инструкцию можно найти в официальной документации Godot.

1. Установите Android Studio (она включает Android SDK)
2. Установите JDK 17 (рекомендуется для Godot 4.x)
3. Создайте отладочный ключ хранилища (keystore):

```bash
keytool -keyalg RSA -genkeypair -alias androiddebugkey -keystore debug.keystore -storepass android -keypass android -dname "CN=Android Debug,O=Android,C=US" -validity 9999 -deststoretype pkcs12
```

4. В Godot: **Editor → Editor Settings → Export → Android** — укажите пути к Android SDK и debug keystore
5. Создайте пресет **Android** и настройте:

| Параметр | Значение |
|---|---|
| Package | `com.yourname.clickeridle` |
| Min SDK | 24 (Android 7.0) |
| Target SDK | 34 (Android 14) |
| Architectures | arm64-v8a, x86_64 |
| Screen | Portrait (наш кликер — вертикальная игра) |

Для кликер-игры особенно важна настройка ориентации экрана — наш UI спроектирован для вертикального расположения (монета вверху, магазин внизу). При ландшафтной ориентации интерфейс будет выглядеть некрасиво. Эта настройка задаётся в пресете экспорта и не требует изменений в коде.

## Настройка иконки приложения

Иконка — это первое, что видит пользователь. Плохая иконка (дефолтный логотип Godot) сигнализирует о непрофессиональном подходе. Для нашего кликера подойдёт золотая монета — та же, что используется как главная кнопка в игре.

### Требования к иконке

| Платформа | Формат | Размер | Примечание |
|---|---|---|---|
| Windows | ICO | 256x256 | Поддерживает несколько размеров в одном файле |
| Web | PNG | 128x128 | Отображается в заголовке вкладки |
| Android | PNG | 512x512 | Адаптивная иконка (adaptive icon) |

### Создание иконки в Godot

Вам не нужен внешний графический редактор — иконку можно создать прямо в Godot, используя те же素材, что и для кнопки клика:

1. Откройте сцену с кнопкой клика
2. Выберите текстуру монеты
3. Экспортируйте её как PNG через **Resource → Save as...** (если текстура — Resource) или через скриншот сцены
4. Для Windows ICO: используйте онлайн-конвертер или ImageMagick (`convert icon.png icon.ico`)

Для продакшн-проектов рекомендуется создавать иконку в векторном редакторе (Inkscape, Figma) с учётом guidelines платформы — например, Android требует «safe zone» для адаптивных иконок (центральные 66% изображения), а iOS — скруглённые углы. Но для учебного проекта достаточно простой PNG-иконки с золотой монетой.

## Процесс экспорта

После настройки всех пресетов экспорт выполняется в несколько кликов:

1. **Project → Export**
2. Выберите нужный пресет (например, «Windows Desktop»)
3. Нажмите **Export Project**
4. Укажите путь и имя файла (например, `builds/ClickerIdle_v1.0_Windows.exe`)
5. Снимите галочку **Export With Debug** — отладочный билд нужен только для тестирования проблем, специфичных для экспорта
6. Нажмите **Save**

Godot создаст исполняемый файл и файл `.pck` рядом с ним. PCK-файл содержит все ресурсы проекта (текстуры, звуки, скрипты, сцены), а исполняемый файл — движок Godot, скомпилированный под целевую платформу. При запуске исполняемый файл автоматически загружает PCK-файл из той же директории. Оба файла должны распространяться вместе — без PCK-файла исполняемый файл запустится, но покажет ошибку «Missing resource».

Для Web-экспорта Godot создаёт набор файлов: `index.html`, `<имя>.js`, `<имя>.wasm`, `<имя>.pck`. Все файлы нужно загрузить на веб-сервер — простое открытие `index.html` из файловой системы не сработает из-за CORS-ограничений браузера. Минимальный вариант — запустить локальный сервер: `python3 -m http.server 8000` в директории билда и открыть `http://localhost:8000` в браузере.

## Чеклист перед публикацией

Перед тем как отправлять билд кому-либо, пройдите по этому чеклисту:

- [ ] **Тест чистого билда** — удалите папку `user://` (или `~/.local/share/godot/app_userdata/Clicker Idle/` на Linux), запустите экспортированный билд и проверьте, что сохранение и загрузка работают с нуля. Частая ошибка: разработчик тестирует только на своей машине, где уже есть сохранение, и не замечает, что первый запуск падает.
- [ ] **Иконка установлена** — дефолтная иконка Godot неприемлема для публикации
- [ ] **Версия указана** — в Project Settings → Application → Config → Version задайте версию (например, `1.0.0`). Это поможет отличать билды друг от друга.
- [ ] **Window settings** — проверьте Project Settings → Display → Window: размер окна, resizable, mode. Для кликера рекомендуется окно 540x960 (пропорции мобильного экрана) с возможностью изменения размера.
- [ ] **Autoload порядок** — GameManager должен загружаться до SaveManager, иначе загрузка сохранения при старте не сработает. Проверьте в Project → Project Settings → Autoload.
- [ ] **Нет print-отладки** — удалите или закомментируйте отладочные `print()` перед публикацией. Они не влияют на производительность, но засоряют лог.
- [ ] **Файл .gdextension не нужен** — в этом проекте мы используем только GDScript, поэтому C++-расширения и файлы `.gdextension` отсутствуют. Начиная с Проекта 4, при экспорте нужно будет убедиться, что скомпилированные `.so`/`.dll` библиотеки включены в билд.

## Распространение

Способы распространения зависят от платформы и целевой аудитории. Для учебного проекта достаточно любого из перечисленных ниже вариантов, но для реальных проектов выбор платформы распространения влияет на стратегию монетизации и охват.

| Платформа | Формат | Аудитория | Сложность |
|---|---|---|---|
| Itch.io | ZIP (Windows), HTML (Web) | Независимые геймеры, геймдев-комьюнити | Низкая — загрузка ZIP или HTML5-билда |
| GitHub Releases | ZIP | Техническая аудитория, опенсорс | Низкая — прикрепить файл к релизу |
| Google Play | AAB | Массовый рынок Android | Высокая — аккаунт разработчика, проверка |
| Steam | EXE + depot | ПК-геймеры | Высокая — Steamworks SDK, магазинная страница |

**Рекомендация для первого проекта:** опубликуйте на Itch.io. Это бесплатно, не требует аккаунта разработчика, и платформа оптимизирована для инди-игр. Web-версия кликера работает прямо в браузере — идеальный формат для Itch.io. Вы также можете загрузить Windows-билд как скачиваемый файл. Itch.io автоматически генерирует страницу игры с скриншотами, описанием и кнопкой Play.

Для публикации на Itch.io:
1. Зарегистрируйтесь на [itch.io](https://itch.io)
2. Нажмите **Create new project**
3. Заполните название, описание, загрузите обложку
4. В секции **Uploads** загрузите ZIP с Windows-билдом (или выберите «This file will be played in the browser» для HTML5-билда)
5. Для HTML5: загрузите весь билд-архив как ZIP, установите галочку «This file will be played in the browser» и укажите `index.html` как точку входа
6. Установите цену (Free для учебного проекта)
7. Опубликуйте

## Почему это важно прямо сейчас

Может показаться, что раздел о публикации неуместен в первом проекте — ведь мы только учимся. Однако есть три причины, почему экспорт нужно осваивать с самого начала. Во-первых, психологический эффект: когда вы можете показать свою игру другу (дать ссылку на Itch.io или отправить EXE), мотивация продолжать обучение резко возрастает. Игра, которую никто не видит, быстро забрасывается. Во-вторых, раннее тестирование на реальных устройствах выявляет проблемы, которые невозможно заметить в редакторе: маленькие шрифты на мобильных, неочевидный UI без подсказок, проблемы с производительностью на слабых машинах. В-третьих, привычка экспортировать регулярно (а не только в конце) защищает от сюрпризов — если вы экспортируете после каждого крупного изменения, вы сразу замечаете, что именно сломало билд.

В последующих проектах мы будем расширять этот навык: в Проекте 2 добавится экспорт шейдеров, в Проекте 4 — C++-библиотеки и GDExtension, в Проекте 5 — 3D-ассеты и навигация, в Проекте 6 — compute-шейдеры. Но фундамент — пресеты, иконки, чеклист — закладывается именно здесь.
