## 7.1 Что мы создали

Проект «3D Приключение» — полноценная 3D action-adventure игра с C++ контроллерами, NPC с конечными автоматами, квестовой системой, боевой механикой на выносливости, циклом дня и ночи и навигацией в 3D-пространстве. Это первый проект, где C++ используется как основной язык программирования, а GDScript — для данных, UI и некритичных менеджеров.

## 7.2 Ключевые концепции

### 1. Полноценный 3D в Godot 4.x

Переход от 2D к 3D — это не просто «добавление оси Z». Vector3 заменяет Vector2, Quaternion заменяет углы Эйлера, Area3D работает с 3D-коллизиями, NavigationRegion3D запекает 3D-навигационную сетку. Рендерер Forward+ обязателен для доступа ко всем 3D-функциям Godot.

### 2. C++ как основной язык

Впервые C++ — не оптимизация, а необходимость. Контроллер персонажа, камера, NPC AI, инвентарь, квесты — всё на C++. GDScript используется только для данных (Resources), UI и менеджеров, работающих по событиям. Это разделение обосновано: 20 NPC, обновляющих навигацию каждый кадр, — неподъёмная нагрузка для GDScript.

### 3. CameraController с 4 режимами

Камера — не просто «привязка к персонажу». Четыре режима (Follow, Cinematic, Fixed, Transition) позволяют создавать кинематографичные моменты: плавный пролёт к NPC перед диалогом (Transition), статичная камера в арене (Fixed), следование за игроком (Follow). SpringArm3D предотвращает проваливание камеры в стены.

### 4. Боевая система на выносливости

Выносливость — стратегический ресурс, превращающий спам атак в осмысленный выбор. Лёгкое комбо (3 удара, нарастающий урон), тяжёлая атака (высокий урон, дорого), уклонение с i-frames (безопасность, но кулдаун), блок (дешёвый, но пробивается). Ритм боя: агрессия → отступление → восстановление → агрессия.

### 5. NPC FSM (6 состояний)

Конечный автомат с состояниями Idle → Patrol → Follow → Fight → Flee и Talk для мирных NPC. NavigationAgent3D обеспечивает перемещение по navmesh. Переходы управляются дистанцией до игрока, здоровьем и внешними событиями (диалог, оглушение).

### 6. Событийная квестовая система

event_index — обратный индекс от события к списку квестов — обеспечивает O(1) триггер вместо O(N) поллинга. При убийстве гоблина `on_event("kill", "goblin")` мгновенно находит все квесты с objective «убить гоблинов». 5 основных + 8 побочных квестов покрывают все типы целей: kill, collect, talk, reach.

### 7. Цикл дня и ночи

600-секундный полный цикл влияет на все подсистемы: враги получают +30% HP ночью, NPC меняют расписание, освещение плавно переходит от тёплого солнечного к холодному ночному. Сигналы `day_started` / `night_started` позволяют другим системам реагировать на смену времени.

### 8. Navigation3D

3D-навигация требует запекания навmesh для каждой зоны с уникальными параметрами: Деревня — крупная сетка, Катакомбы — мелкая для узких проходов, Башня — увеличенный радиус для крупных врагов. NavigationAgent3D обеспечивает перемещение NPC по navmesh.

## 7.3 Паттерны проектирования

| Паттерн | Где используется | Описание |
|---|---|---|
| **FSM** | NPCController, CombatController, QuestSystem | Конечный автомат для управления состояниями |
| **Strategy** | CameraController (4 режима камеры) | Инкапсуляция поведения в стратегии |
| **Observer** | Сигналы Godot (health_changed, quest_completed) | Уведомление подписчиков о событиях |
| **Data-View** | Resources (Data) + C++ (Logic) + Scenes (View) | Разделение данных, логики и представления |
| **Factory** | Spawner-узлы, enemy_scene из EnemyData | Создание объектов через конфигурацию |
| **Flyweight** | ItemData, EnemyData как разделяемые Resources | Разделение общих данных между экземплярами |
| **Double Buffer** | DayNightCycle (текущее время → следующее) | Плавный переход без артефактов |

## 7.4 C++ vs GDScript: производительность в 3D

| Подсистема | C++ | GDScript | Разница |
|---|---|---|---|
| Контроллер персонажа (_physics_process) | ~0.05 мс | ~0.5 мс | **10×** |
| 20 NPC AI (_physics_process) | ~0.3 мс | ~5.0 мс | **16×** |
| Инвентарь (has_item, O(1)) | ~0.001 мс | ~0.01 мс | **10×** |
| Квестовая система (on_event) | ~0.01 мс | ~0.1 мс | **10×** |
| Диалоговый менеджер (по событиям) | — | ~0.05 мс | Нет разницы |
| UI обновление (по сигналам) | — | ~0.1 мс | Нет разницы |

Вывод: C++ критически важен для систем, работающих каждый кадр (персонаж, NPC AI). GDScript достаточен для событийных систем (диалоги, UI, менеджеры). Граница очевидна: если `_process` / `_physics_process` обрабатывает 10+ объектов — нужен C++.

## 7.5 Частые ошибки в 3D-разработке

### 1. Углы Эйлера вместо кватернионов

```cpp
// ❌ НЕПРАВИЛЬНО: Gimbal lock при вращении
set_rotation(Vector3(pitch, yaw, 0.0));
// При yaw ~90° поворот по pitch и roll совпадают

// ✅ ПРАВИЛЬНО: Кватернионы
Quaternion target_quat = Quaternion(Vector3(0, 1, 0), target_yaw);
Quaternion new_quat = current_quat.slerp(target_quat, speed * delta);
```

### 2. Движение по мировым осям вместо камера-относительного

```cpp
// ❌ НЕПРАВИЛЬНО: W всегда двигает по Z мира
velocity.z = input.y * speed;

// ✅ ПРАВИЛЬНО: W двигает туда, куда смотрит камера
Vector3 cam_forward = -camera_pivot->get_global_basis().get_column(2);
cam_forward.y = 0.0; cam_forward.normalize();
velocity = cam_forward * input.y * speed;
```

### 3. Неактивация Camera3D

Если экран чёрный при запуске 3D-сцены, убедитесь, что Camera3D активна: `camera.current = true`. Без этого Godot рендерит сцену, но не отображает.

### 4. Слои коллизий в 3D

Частая ошибка: Hitbox игрока и Hurtbox игрока на одном слое. Результат: персонаж бьёт сам себя. Всегда проверяйте: Hitbox на слое `projectiles`, Hurtbox на слое `enemies`, маски наоборот.

### 5. NavMesh не запечён

NavigationAgent3D не будет работать без запечённого NavigationRegion3D. Запекайте вручную через кнопку «Bake NavMesh» в редакторе или программно через `bake_navigation_mesh()`.

### 6. Забытый `process_mode` для Autoload

Autoload, работающий при паузе (GameManager, AudioManager), должен иметь `process_mode = PROCESS_MODE_ALWAYS`. Иначе меню паузы «замёрзнет».

## 7.7 Мост к Проекту 6: Демо производительности

3D Приключение раскрывает потенциал C++ в Godot, но не затрагивает оптимизацию рендеринга и работы с памятью. Проект 6 «Демо производительности» углубится в:

| Тема | Что изучим | Почему это важно |
|---|---|---|
| **ECS архитектура** | Entity Component System vs OOP | Альтернатива иерархии узлов для 1000+ объектов |
| **MultiMesh** | Рендеринг 10 000+ одинаковых объектов | Инстансирование вместо 10 000 узлов |
| **Compute Shaders** | GPU-вычисления для систем частиц | Симуляция на GPU вместо CPU |
| **Spatial Hashing** | O(1) поиск соседей в 3D | Замена O(N²) проверок коллизий |
| **Профилирование** | Godot Profiler, Frame Profiler | Идентификация узких мест |

Тёмный Лорд повержен, но настоящие испытания производительности ещё впереди. В Проекте 6 мы столкнёмся с тысячами объектов на экране и узнаем, как Godot справляется с лимитами рендеринга — и как их преодолевать.
