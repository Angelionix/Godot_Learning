Tower Defense — это жанр, который идеально подходит для перехода от GDScript к C++/GDExtension. Почему? Потому что в этом жанре есть чётко выраженные подсистемы с различными требованиями к производительности. С одной стороны, пользовательский интерфейс, управление волнами и игровая логика не требуют сверхбыстрой обработки — им достаточно гибкости и удобства GDScript. С другой стороны, навигация десятков врагов по карте, симуляция сотен снарядов и расчёт путей — это именно те задачи, где C++ показывает свою силу, обеспечивая на порядок лучший результат.

В этом проекте мы создадим полноценную игру в жанре Tower Defense, начиная с чистого GDScript и постепенно перенося критичные к производительности подсистемы на C++ через механизм GDExtension. Этот подход — не просто учебное упражнение, а реальная практика, которую используют коммерческие проекты на Godot. Многие успешные игры применяют гибридную архитектуру: GDScript для прототипирования и UI, C++ для горячего кода. Мы пройдём весь путь от настройки среды сборки C++ до создания полностью функционального GDExtension-модуля.

Наш Tower Defense будет включать систему из 15 прогрессивных волн врагов, четыре типа башен с различными стратегиями атаки и тремя уровнями апгрейда, экономику с доходом от убийств и продажей башен, а также навигацию на основе NavigationRegion2D. По мере развития проекта мы выделим узкие места производительности, перенесём поиск пути и симуляцию снарядов на C++, и проведём бенчмарки, наглядно демонстрирующие преимущество скомпилированного кода. Этот проект — мост между удобным скриптингом и высокопроизводительным системным программированием.

## Цели обучения

1. Спроектировать data-driven архитектуру Tower Defense с ресурсами TowerData, EnemyData, WaveData и SpawnGroup
2. Реализовать систему из четырёх типов башен с различными механиками атаки: одиночная цель, область поражения, замедление, непрерывный урон
3. Создать три стратегии выбора цели (First, Last, Strongest) с паттерном Strategy
4. Построить менеджер волн на основе конечного автомата (FSM): Idle → Spawning → Active
5. Разработать экономическую систему с балансом доходов/расходов, продажей башен и бонусами за скорость
6. Освоить навигацию через NavigationRegion2D и NavigationAgent2D для движения врагов по маршруту
7. Настроить среду сборки C++ GDExtension: SCons, godot-cpp, файл .gdextension
8. Создать C++ классы PathFinder (A*) и ProjectileSimulator (пакетная обработка)
9. Провести бенчмарки GDScript vs C++ и проанализировать результаты
10. Организовать архитектуру проекта по слоям: Data, Logic, Presentation, Persistence

## Оценка времени

**35–50 часов** — это амбициозный проект, который сочетает полноценную игру на GDScript с переносом подсистем на C++. Рекомендуется сначала завершить GDScript-часть, убедиться в работоспособности всех систем, и только потом переходить к GDExtension. Это позволяет изолировать проблемы: если что-то не работает после переноса на C++, вы знаете, что ошибка в C++-коде, а не в логике.

## Почему именно Tower Defense?

Tower Defense — идеальный жанр для изучения гибридной GDScript/C++ архитектуры по трём причинам. Во-первых, чёткое разделение на «горячий» и «холодный» код: навигация и симуляция снарядов — горячий код, который выполняется каждый кадр для десятков объектов; UI и менеджеры — холодный код, который работает с низкой частотой. Во-вторых, масштабируемость: легко увеличивать количество врагов и снарядов, чтобы увидеть, как GDScript начинает тормозить, а C++ продолжает работать плавно. В-третьих, data-driven дизайн: все параметры вынесены в ресурсы, что позволяет менять баланс без перекомпиляции C++-кода. Это реальный паттерн, который используют коммерческие проекты на Godot.
