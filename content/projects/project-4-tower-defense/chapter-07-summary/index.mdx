## 7.1 Что мы построили

За этот проект вы создали полноценный Tower Defense с 4 типами башен, 15 волнами врагов, экономической системой и первым знакомством с C++ через GDExtension. Это самый сложный проект курса — и первый, где производительность стала критичным фактором, потребовавшим перехода от чистого GDScript к гибридной архитектуре GDScript + C++.

**Архитектура проекта:**
- **Data Layer** — TowerData, EnemyData, WaveData, SpawnGroup (Resource)
- **Logic Layer** — GameManager, WaveManager, EconomyManager, PathManager, TowerRegistry, AudioManager (Autoload)
- **Presentation Layer** — Tower, TowerLaser, EnemyBase, Projectile, TowerSlot (Node2D/CharacterBody2D/Area2D)
- **Performance Layer** — PathFinder, ProjectileSimulator (C++ GDExtension)

**Игровые механики:**
- 4 типа башен: Пулемёт, Взрывная, Замедляющая, Лазерная
- 4 типа врагов: Обычный, Быстрый, Танк, Босс
- 3 стратегии выбора цели: First, Last, Strongest
- Система замедления с сопротивлением (slow_resistance)
- Splash-урон с линейным falloff
- Экономика с продажей (70% от вложенного)
- 15 волн с нарастающей сложностью

## 7.2 Ключевые концепции

### 1. Data-driven дизайн
Данные отделены от логики. TowerData и EnemyData — это Resource с `@export`-полями, настраиваемыми в инспекторе. Новая башня или враг создаётся дублированием .tres файла без изменения кода. Это принцип **Open/Closed**: открыт для расширения, закрыт для изменения.

### 2. Factory pattern
TowerRegistry хранит словарь TowerData по ключу и создаёт башни по типу. Вместо `if type == "gun": ... elif type == "splash": ...` — один вызов `TowerRegistry.get_tower_data(key)`. Добавление нового типа башни требует одной строки в `_register_towers()`.

### 3. Strategy pattern
Выбор цели делегирован параметру `target_strategy` в TowerData. Башня не знает, как выбрать цель — она вызывает `_target_first()`, `_target_last()` или `_target_strongest()` на основе данных. Новая стратегия — новый блок в `match`, без подклассов.

### 4. FSM (Конечный автомат)
WaveManager использует три состояния: Idle → Spawning → Active. Каждое состояние обрабатывается в своём блоке `match`, переходы чётко определены. FSM делает логику волн читаемой и расширяемой.

### 5. Navigation2D
Враги движутся через NavigationAgent2D вместо ручного перемещения по waypoints. Навигация автоматически вычисляет путь, учитывает obstacles и обеспечивает плавное движение. Это основа для Navigation3D в следующем проекте.

### 6. C++ GDExtension
Первое знакомство с C++ в контексте Godot. GDExtension позволяет писать критичные по производительности компоненты на C++ и вызывать их из GDScript как обычные классы. PathFinder и ProjectileSimulator — примеры задач, где C++ даёт ×25 ускорение.

### 7. Экономическая система
EconomyManager с sell_ratio 0.7, формулами стоимости улучшения и signal-based обновлением UI. Простая, но реалистичная модель, где каждое решение имеет цену.

### 8. Object Pool (пул объектов)
ProjectileSimulator использует пул снарядов с предвыделенной памятью. Вместо `instantiate()/queue_free()` на каждый снаряд — переиспользование слотов в массиве. Это уменьшает нагрузку на GC и повышает производительность.

## 7.3 Таблица паттернов

| Паттерн | Где применён | Проблема, которую решает |
|---|---|---|
| Observer (Сигналы) | `balance_changed`, `wave_started`, `enemy_died`, `game_over`, `lives_changed` | Слабая связанность: HUD обновляется без прямой ссылки на EconomyManager |
| Strategy | `target_strategy` в TowerData (`first`, `last`, `strongest`) | Разные алгоритмы выбора цели без подклассов башни |
| State (FSM) | WaveManager: `Idle → Spawning → Active` | Управление фазами волны с чёткими переходами |
| Singleton (Autoload) | GameManager, WaveManager, EconomyManager, PathManager, TowerRegistry, AudioManager | Глобальный доступ к подсистемам без передачи ссылок |
| Factory | TowerRegistry + PackedScene | Создание башен по типу без switch/if-else |
| Data-View separation | TowerData (Resource) vs Tower (Node2D) | Данные отделены от отображения, баланс через .tres |
| Object Pool | ProjectileSimulator (C++) | Переиспользование объектов вместо instantiate/queue_free |

## 7.4 C++ vs GDScript — бенчмарк

| Задача | GDScript | C++ GDExtension | Ускорение | Когда использовать C++ |
|---|---|---|---|---|
| A* pathfinding (50 врагов) | 28 ms | 1.1 ms | ×25 | 50+ врагов с пересчётом пути |
| Пакетная обработка 200 снарядов | 12 ms | 0.4 ms | ×30 | 100+ активных снарядов |
| Splash-урон (30 врагов) | 8 ms | 0.6 ms | ×13 | Массовые AoE-атаки |
| Обновление UI | 0.1 ms | 0.08 ms | ×1.25 | Никогда — GDScript достаточен |
| Создание/удаление узлов | 0.5 ms | 0.4 ms | ×1.25 | Никогда — разница незначительна |

**Правило:** Если код вызывается реже 10 раз за кадр — GDScript. Если 100+ раз с вычислениями — C++.

## 7.5 Частые ошибки

| # | Ошибка | Симптом | Причина | Исправление |
|---|---|---|---|---|
| 1 | Враги не двигаются | Враги стоят на месте после спавна | NavigationRegion2D не запечён | Нажмите Bake в инспекторе NavigationRegion2D |
| 2 | Снаряды крашат игру | `get_current_health(): Node was deleted` | Цель умерла до попадания снаряда | Добавьте `is_instance_valid(target)` перед вызовом |
| 3 | Башня не атакует | Враги проходят мимо, башня не стреляет | Слои коллизий настроены неправильно | Проверьте: RangeArea mask = enemies, EnemyBody layer = enemies |
| 4 | Autoload null reference | `Invalid call. Nonexistent function 'spend' in base 'Nil'` | EconomyManager загружен после WaveManager | Измените порядок Autoload: EconomyManager перед WaveManager |
| 5 | GDExtension не загружается | Класс PathFinder не найден | Неправильный путь в .gdextension или библиотека не собрана | Проверьте путь к .so/.dll и запустите `scons` |
| 6 | Улучшение бесплатно | `upgrade()` возвращает true без списания золота | `can_afford()` и `spend()` в разных условиях | Используйте `spend()` который уже проверяет баланс |

## 7.7 Мост к Проекту 5: 3D Приключение

Проект 4 подготовил вас к переходу от 2D к 3D и от GDScript к гибридной разработке. Вот что изменится:

**C++ становится основным языком.** В Проекте 5 (3D Приключение) C++ будет использоваться не только для оптимизации, но и для сложных систем: 3D-навигация, инвентарь, система квестов. Вы будете писать больше C++ кода, но GDScript останется для UI и прототипирования.

**2D → 3D.** NavigationRegion2D станет NavigationRegion3D, Area2D — Area3D, CharacterBody2D — CharacterBody3D. Принципы те же, но добавляется третье измерение: высота, камера, освещение.

**Навигация.** PathFinder на A* будет расширен для 3D-пространства. Навигационные полигоны станут навигационными мешами (NavigationMesh), а waypoints станут 3D-точками.

**Паттерны углубляются.** Factory станет полноценным фабричным методом для создания 3D-объектов. Observer будет использоваться для системы событий квестов. FSM — для AI врагов с более сложным поведением (Patrol → Chase → Attack → Flee).
