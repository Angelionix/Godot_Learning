# Введение

Добро пожаловать во второй проект нашего курса! В этом проекте мы создадим полноценный 2D космический шутер — динамичную аркадную игру с вертикальной прокруткой, где игрок управляет космическим кораблём, уничтожает волны врагов, собирает бонусы и сражается с мощным боссом. Этот проект значительно углубит ваши знания GDScript и познакомит с новыми подсистемами Godot: 2D-физикой, столкновениями, шейдерами, системами частиц и паттернами проектирования, которые используются в реальной игровой индустрии.

Если первый проект (кликер-игра) познакомил вас с основами GDScript, сигналами и ресурсами, то этот проект научит вас создавать игры с реальным геймплеем, где объекты взаимодействуют друг с другом через физику и столкновения, где производительность имеет значение, а архитектура кода определяет, насколько легко будет добавлять новый контент. Космический шутер — это классический жанр, который наилучшим образом демонстрирует все эти аспекты.

**Цели обучения:**

1. Освоить 2D-физику Godot: CharacterBody2D, Area2D, слои и маски столкновений
2. Реализовать пул объектов (Object Pool) для оптимизации производительности
3. Создать систему волн врагов с нарастающей сложностью
4. Построить иерархию врагов через наследование сцен и скриптов
5. Разработать босс-файт с несколькими фазами и паттернами атак
6. Научиться работать с WeaponData как Resource для гибкой настройки оружия
7. Создать систему бонусов (pickups) и комбо-множителя очков
8. Применить шейдеры для визуальных эффектов (звёздное поле, взрывы)
9. Реализовать AudioManager с пулом каналов для звуковых эффектов
10. Спроектировать архитектуру с разделением данных, логики и представления

**Ориентировочное время выполнения:** 20–25 часов

Этот проект педагогически ценен тем, что он вводит сразу несколько критически важных концепций, которые нельзя обойти в реальной разработке. В отличие от кликер-игры, где производительность редко является проблемой, космический шутер заставляет задуматься об оптимизации: десятки снарядов на экране, непрерывное создание и удаление объектов, множество столкновений каждый кадр. Навыки, полученные в первом проекте — сигналы, ресурсы, архитектура — здесь получают практическое применение в условиях, приближённых к реальной разработке. Кроме того, этот проект является мостом к более сложным жанрам: система волн готовит к Tower Defense, босс с фазами — к Metroidvania, а Object Pool — к любому экшен-проекту.

# Глава 1: Геймдизайн

## 1.1 Концепция и видение

Наш космический шутер принадлежит к жанру Vertical Scrolling Shooter (STG) — классической аркадной жанровой традиции, восходящей к таким играм, как Space Invaders, 1942 и Dodonpachi. Основная фантазия игры — «Один против армии»: игрок — одиночный пилот, противостоящий подавляющим силам противника. Эта фантазия определяет всё: от количества врагов на экране до ощущения от каждой победы.

Жанр вертикального скроллинг-шутера выбран не случайно — он идеален для педагогических целей по нескольким причинам. Во-первых, он вводит физику и столкновения: игрок и враги используют CharacterBody2D, снаряды — Area2D, а корректная настройка слоёв столкновений критически важна для игрового процесса. Во-вторых, он требует оптимизации: непрерывный поток снарядов, врагов и эффектов заставляет применять паттерн Object Pool. В-третьих, он демонстрирует важность архитектуры данных: разные типы оружия, врагов и волн удобнее всего описывать через Resource, а не через жёстко закодированные значения.

Длительность игровой сессии составляет 3–5 минут на набор волн, с боссом каждые 5 волн. Это позволяет игроку быстро погружаться в игровой цикл, а разработчику — итеративно настраивать баланс без долгих тестовых прогонов.

## 1.2 Основной игровой цикл

Основной игровой цикл космического шутера строится на постоянном чередовании уклонения и атаки. Игрок должен одновременно избегать вражеских снарядов и уничтожать противников, создавая напряжённый, но увлекательный геймплей. Цикл можно представить следующим образом:

```
Уклонение от снарядов → Стрельба по врагам → Уничтожение → Очки/Бонус → Следующая волна → ...
```

Этот цикл работает на трёх уровнях вовлечённости, каждый из которых поддерживает мотивацию игрока:

**Краткосрочный уровень (секунды):** Уклонение от отдельного снаряда, уничтожение конкретного врага, подбор бонуса. Эти микро-действия создают моментальный эмоциональный отклик — облегчение при успешном уклонении, удовлетворение при точном попадании, радость при подборе улучшения. Каждое такое действие подкрепляется визуальной и звуковой обратной связью.

**Среднесрочный уровень (минуты):** Прохождение волны, достижение босса, получение улучшения оружия. Здесь игрок видит прогрессию — волны становятся сложнее, но его арсенал растёт. Комбо-система добавляет мотивацию играть агрессивно: быстрое уничтожение врагов увеличивает множитель очков.

**Долгосрочный уровень (полный прогон):** Прохождение всех волн, победа над боссом, установка рекорда. Этот уровень поддерживается системой сохранения лучшего результата и постоянным желанием побить собственный рекорд. Мастерство проявляется в способности проходить сложные волны без потери здоровья и набирать максимальное комбо.

## 1.3 Управление и ввод

Система управления должна быть отзывчивой и интуитивной. В космическом шутере даже малейшая задержка ввода может привести к гибели игрока, поэтому мы используем InputMap — встроенную систему Godot для маппинга действий на клавиши. Это позволяет легко менять раскладку и поддерживать геймпад.

| Действие | Клавиша | Описание |
|---|---|---|
| move_up | W / Стрелка вверх | Движение вверх |
| move_down | S / Стрелка вниз | Движение вниз |
| move_left | A / Стрелка влево | Движение влево |
| move_right | D / Стрелка вправо | Движение вправо |
| fire | Пробел / ЛКМ | Стрельба |
| bomb | Shift | Спецатака (бомба) |

Метод `Input.get_vector("move_left", "move_right", "move_up", "move_down")` автоматически обрабатывает все четыре направления и возвращает нормализованный вектор, готовый для использования в движении. Это значительно удобнее, чем вручную проверять каждую клавишу и комбинировать направления. Кроме того, при использовании InputMap легко добавить поддержку геймпада — просто добавьте соответствующие маппинги в настройках проекта.

## 1.4 Таблица врагов

Враги — основа challenge-составляющей нашего шутера. Мы определяем пять типов врагов, каждый из которых привносит уникальную механическую угрозу. Разнообразие врагов не только делает геймплей интереснее, но и заставляет игрока адаптировать тактику: против разведчиков эффективна стрельба веером, против танков — мощные одиночные выстрелы, против бомбардировщиков — агрессивное сближение.

| ID | Название | HP | Speed | Points | Поведение | Описание |
|---|---|---|---|---|---|---|
| scout | Разведчик | 10 | 180 | 50 | Прямое движение вниз | Слабый, быстрый, появляется стаями |
| fighter | Истребитель | 25 | 120 | 100 | Зигзаг + стрельба | Стандартный враг |
| tank | Тяжёлый корабль | 80 | 60 | 250 | Медленный + очереди | Танк, требует много попаданий |
| bomber | Бомбардировщик | 40 | 80 | 200 | Движение + мины | Оставляет опасные зоны |
| elite | Элитный истребитель | 60 | 150 | 400 | Круговой обход + стрельба | Сложный, появляется с 4-й волны |

Каждый тип врага описывается через `EnemyData` — ресурс, который определяет все параметры. Это значит, что геймдизайнер может настраивать баланс прямо в инспекторе, не касаясь кода. Поведение реализуется через метод `move_behavior()` в базовом скрипте врага, который переопределяется в дочерних скриптах (паттерн Template Method). Такой подход позволяет добавлять новые типы врагов минимальными усилиями: создаём новый скрипт, наследуем от `enemy_base.gd`, переопределяем `move_behavior()` и создаём `.tres`-файл с параметрами.

## 1.5 Таблица оружия игрока

Система оружия — один из ключевых элементов прогрессии игрока. Начиная с базового пистолета, игрок подбирает улучшения, которые меняют стиль игры: пулемёт требует точного прицеливания, дробовик эффективен против стай, лазер — против танков. Каждое оружие определяется как `WeaponData` Resource, что позволяет легко добавлять новые типы без изменения логики стрельбы.

| ID | Название | fire_rate | damage | bullet_speed | bullet_count | spread | Описание |
|---|---|---|---|---|---|---|---|
| pistol | Пистолет | 0.20 | 10 | 500 | 1 | 0 | Стартовое оружие |
| machinegun | Пулемёт | 0.08 | 8 | 550 | 1 | 0.05 | Быстрая стрельба |
| spreadgun | Дробовик | 0.30 | 8 | 450 | 3 | 0.3 | Три снаряда веером |
| laser | Лазер | 0.40 | 25 | 700 | 1 | 0 | Мощный одиночный выстрел |

Прогрессия оружия следует логике увеличения специализации: пистолет универсален, пулемёт лучше против быстрых целей, дробовик — против групп, лазер — против толстых. При подборе бонуса WEAPON оружие переключается на следующий уровень: pistol → machinegun → spreadgun → laser. После лазера дальнейшие подборы не дают эффекта — это максимальный уровень. При смерти игрока оружие сбрасывается на пистолет, что добавляет вес потере жизни и мотивирует играть осторожно.

## 1.6 Система волн

Система волн — это «пульс» игры, определяющий её темп и нарастание сложности. Каждая волна определяется через `WaveData` Resource с массивом `SpawnEntry`, что делает настройку полностью декларативной. Волны спроектированы так, чтобы вводить новые механики постепенно: первые три волны обучают базовым взаимодействиям, затем добавляются новые типы врагов, а к десятой волне игрок сталкивается со всеми типами одновременно.

**Таблица волн:**

| Волна | Враги | Количество | Интервал (сек) | Особенности |
|---|---|---|---|---|
| 1 | scout | 5 | 2.0 | Обучающая: только разведчики |
| 2 | scout + fighter | 8 | 1.8 | Появляются истребители |
| 3 | fighter | 6 | 1.5 | Истребители с зигзагом |
| 4 | scout + fighter + tank | 10 | 1.5 | Первый танк |
| 5 | fighter + tank | 8 | 1.2 | Минибосс: двойной танк |
| 6 | fighter + bomber | 10 | 1.3 | Бомбардировщики с минами |
| 7 | scout + elite | 12 | 1.0 | Элита появляется |
| 8 | fighter + tank + bomber | 12 | 1.0 | Смешанный состав |
| 9 | elite + bomber + tank | 14 | 0.8 | Сложная волна |
| 10 | Все типы | 16 | 0.7 | Хаос перед боссом |
| BOSS | Босс | 1 | — | 3 фазы, см. ниже |

Обратите внимание на закономерности: интервал спавна уменьшается с каждой волной (2.0 → 0.7 сек), количество врагов растёт (5 → 16), а состав становится всё более разнообразным. Это создаёт ощущение нарастающего давления, которое достигает пика на 10-й волне перед появлением босса. После уничтожения босса игра может либо завершиться победой, либо перейти к циклу повышенной сложности — это решение остаётся за дизайнерами.

## 1.7 Босс-файт: Крейсер «Тёмная Звезда»

Босс — это кульминация игрового опыта, момент максимального напряжения и триумфа. Крейсер «Тёмная Звезда» спроектирован по классической формуле «три фазы»: каждая фаза вводит новые механики, заставляя игрока адаптироваться на ходу. Фазы активируются при достижении пороговых значений здоровья, а не по таймеру, что означает, что более skilled-игроки быстрее переходят к сложным фазам.

| Параметр | Значение |
|---|---|
| HP | 500 |
| Скорость | 60 |
| Очки | 5000 |

**Фазы босса:**

| Фаза | HP диапазон | Атаки | Скорость | Описание |
|---|---|---|---|---|
| 1: Разогрев | 100%–66% | Одиночные выстрелы каждые 1.5с | 60 | Предсказуемые паттерны, изучение |
| 2: Нападение | 66%–33% | Очереди по 5 снарядов + зигзаг-движение | 90 | Увеличенная агрессия |
| 3: Ярость | 33%–0% | Круговой обстрел (12 снарядов) + спавн 2 разведчиков каждые 5с | 120 | Максимальная сложность |

Первая фаза — это фаза обучения: босс двигается медленно и стреляет предсказуемо, давая игроку возможность изучить его паттерны. Вторая фаза усиливает давление: веерные атаки требуют более активного уклонения, а зигзаг-движение босса делает прицеливание сложнее. Третья фаза — это проверка мастерства: круговой обстрел ограничивает безопасные зоны, а спавн разведчиков добавляет отвлекающий фактор. Визуальная обратная связь при смене фаз (вспышка оранжевого цвета, звуковой сигнал) чётко коммуницирует игроку об изменении ситуации.

## 1.8 Система бонусов (pickups)

Бонусы добавляют стратегическое измерение в геймплей: игрок должен решать, стоит ли рисковать, собирая бонус посреди вражеского огня. Шанс дропа настроен так, чтобы бонусы появлялись достаточно часто для поддержания интереса, но не настолько часто, чтобы обесценивать их.

| Тип | Шанс дропа | Эффект | Длительность |
|---|---|---|---|
| HEALTH | 15% | +25 HP | Мгновенный |
| WEAPON | 8% | Следующий уровень оружия | Перманентный до смерти |
| SHIELD | 5% | Неуязвимость | 3 секунды |
| BOMB | 3% | Урон всем врагам на экране | Мгновенный |

Тип бонуса определяется случайно при спавне с весовыми коэффициентами: HEALTH — самый частый, BOMB — самый редкий. Это создаёт момент радости при нахождении редкого бонуса и устойчивый прогресс через частые лечения. Щит длится всего 3 секунды, что заставляет игрока действовать решительно, пока он активен — например, прорваться через плотный огонь, чтобы добить танка.

## 1.9 Система очков и комбо

Система очков и комбо — это «соус» шутера, который превращает простое уничтожение врагов в увлекательную игру с цифрами. Без комбо каждый враг даёт фиксированное количество очков, и единственная стратегия — выживание. С комбо возникает мотивация играть агрессивно: быстрое уничтожение врагов увеличивает множитель, что поощряет рискованные манёвры ради дополнительных очков.

- Базовые очки за каждого врага (см. таблицу врагов)
- Комбо-множитель: убийства в течение 2 секунд умножают очки
- Комбо: x1 → x2 → x3 → x4 (максимум)
- Комбо сбрасывается после 2 секунд без убийства
- Лучший результат сохраняется между сессиями

Например, если игрок уничтожает истребителя (100 очков) с комбо x3, он получает 300 очков вместо 100. Это означает, что агрессивная игра может дать в 4 раза больше очков, чем осторожная. Механика комбо также создаёт микро-цели: «удержать комбо до конца волны» или «набрать x4 к боссу». Сохранение рекорда через `FileAccess` обеспечивает долгосрочную мотивацию вернуться и побить свой результат.

## 1.10 Визуальный стиль и звук

Визуальный стиль нашего шутера — это пиксель-арт в космической стилистике. Выбор пиксель-арта не только эстетический, но и практический: маленькие спрайты (16x16 — 64x64) легко создавать, они хорошо смотрятся при масштабировании и не требуют больших текстурных атласов. Палитра ограничена для обеспечения визуальной ясности: игрок всегда выделяется на фоне врагов, а вражеские снаряды всегда заметны.

- Арт-стиль: Пиксель-арт, спрайты 16x16 — 64x64, тёмный космический фон
- Цветовая схема: тёмно-синий (#0a0a2e) фон, голубой (#00ffff) игрок, красный (#ff3333) враги, жёлтый (#ffcc00) снаряды
- Параллакс-звёздное поле (3 слоя: дальний/тусклый, средний/средний, ближний/яркий)
- Звуковой дизайн: shoot, explosion_small, explosion_large, pickup, boss_phase, boss_death, player_hit, combo

Параллакс-звёздное поле создаёт ощущение глубины и движения. Три слоя звёзд двигаются с разной скоростью: дальние звёзды — медленно (скорость 20), средние — средне (скорость 60), ближние — быстро (скорость 120). Это простая, но эффективная техника, которая мгновенно создаёт ощущение космического пространства. Звуковые эффекты дополняют визуальную обратную связь: выстрел даёт ощущение силы, взрыв — удовлетворения, подбор бонуса — награды.

## 1.11 Микровызовы

Микровызовы — это дополнительные задания, которые расширяют базовый проект. Каждый вызов помечен уровнем сложности и может быть реализован независимо от других. Рекомендуется сначала завершить базовый проект и убедиться в работоспособности всех систем, прежде чем браться за микровызовы.

| Уровень | Вызов | Описание |
|---|---|---|
| 🟢 Лёгкий | Авто-прицеливание | Добавить режим самонаведения для снарядов: при выстреле снаряд плавно поворачивает к ближайшему врагу. Требует расширения WeaponData полем `homing_strength` (0 = нет наведения, 1 = сильное наведение) и модификации Bullet._physics_process() для интерполяции направления к ближайшему врагу из группы "enemies". Это расширение базового проекта, которое углубляет понимание векторной математики и слоёв столкновений: снаряд должен находить цель через `get_tree().get_nodes_in_group()` и вычислять кратчайший поворот через `Vector2.angle_to()` |
| 🟡 Средний | Система достижений | Реализовать 6 достижений с уведомлениями: «Первая кровь» (убить первого врага), «Комбо-мастер» (достичь x4), «Босс-слейер» (убить босса), «Без единой царапины» (пройти волну без урона), «Арсенал» (собрать все 4 типа оружия), «100K Club» (набрать 100 000 очков). # Глава 2: Архитектура

## 2.1 Обзор архитектуры

Архитектура нашего шутера строится на четырёх слоях, аналогично первому проекту, но с более жёстким разделением из-за специфики экшен-игры. В игре, где каждый кадр на счету, критически важно, чтобы производительный код не смешивался с игровой логикой, а логика — с представлением. Это не просто теоретический принцип: смешение этих слоёв приводит к коду, который невозможно оптимизировать, трудно тестировать и болезненно модифицировать.

**Data Layer (Слой данных):** `WeaponData`, `WaveData`, `SpawnEntry`, `EnemyData` — все они наследуют `Resource` и хранятся как `.tres`-файлы. Этот слой полностью декларативен: он описывает, *что* существует, но не *как* это работает. Геймдизайнер может настраивать баланс, не открывая ни одного скрипта. Это критически важно для итеративной разработки: изменение скорости пули с 500 до 450 не должно требовать модификации кода.

**Logic Layer (Слой логики):** `GameManager`, `WaveManager`, `ObjectPool` — глобальные менеджеры (Autoload), которые управляют состоянием игры. GameManager ведёт счёт и комбо, WaveManager контролирует волны, ObjectPool управляет жизненным циклом объектов. Эти менеджеры ничего не знают о визуале: GameManager не знает, как выглядит счёт, WaveManager не знает, как выглядит враг. Они оперируют данными и генерируют сигналы.

**Presentation Layer (Слой представления):** `Player`, `Enemy`, `Bullet`, `Pickup`, `HUD` — сцены, которые игрок видит на экране. Этот слой реагирует на сигналы логического слоя и обновляет визуал. HUD обновляет счёт при получении сигнала `score_changed`, а не опрашивает GameManager каждый кадр. Это более эффективно и лучше разделяет ответственности.

**Audio Layer (Слой звука):** `AudioManager` — централизованный менеджер воспроизведения звуков с пулом каналов. Он отделён от остальных слоёв, потому что аудио имеет свои особенности: ограниченное количество одновременно воспроизводимых звуков, раздельные шины для музыки и эффектов, необходимость предотвращать звуковое перегрузку.

Разделение слоёв особенно критично в экшен-игре по нескольким причинам. Во-первых, производительность: ObjectPool работает с Node-объектами на низком уровне, и его код должен быть максимально простым и быстрым. Если бы ObjectPool знал о логике волн или визуале HUD, каждый вызов `release()` тянул бы за собой зависимости, которые замедляют выполнение. Во-вторых, тестируемость: WaveManager можно тестировать изолированно, проверяя, что волна генерирует правильное количество врагов, без необходимости запускать всю игру. В-третьих, итеративность: геймдизайнер может настраивать `.tres`-файлы, не рискуя сломать логику.

## 2.2 Дерево сцен

Дерево сцен — это структурный каркас игры. Каждая сцена — это самостоятельный, переиспользуемый компонент с чётко определённой ответственностью. Правильная организация дерева сцен определяет, насколько легко будет добавлять новый контент и отлаживать проблемы. Ниже приведены полные ASCII-диаграммы для всех сцен проекта.

**main.tscn:**

```
Main (Node2D) [scripts/main.gd]
├── Background (ParallaxLayer) x3  — параллакс-звёзды
├── PlayArea (Node2D)
│   ├── Player (instanciated from player.tscn)
│   ├── EnemyContainer (Node2D)  — динамические враги
│   ├── BulletContainer (Node2D) — динамические снаряды
│   └── PickupContainer (Node2D) — динамические бонусы
├── ExplosionContainer (Node2D)  — эффекты
└── HUD (CanvasLayer) [scripts/hud.gd]
    ├── ScoreLabel (Label)
    ├── HealthBar (TextureProgressBar)
    ├── WaveLabel (Label)
    ├── ComboLabel (Label)
    └── BossHealthBar (TextureProgressBar) — visible only during boss
```

Контейнеры (EnemyContainer, BulletContainer, PickupContainer, ExplosionContainer) служат для организации динамических объектов. Вместо того чтобы добавлять объекты напрямую в Main, мы помещаем их в контейнеры. Это упрощает очистку (можно удалить всех врагов через `EnemyContainer.get_children()`) и отладку (в редакторе видно, сколько объектов каждого типа активно). Контейнеры также помогают с z-индексами: все снаряды отрисовываются на одном уровне, все враги — на другом.

**player.tscn:**

```
Player (CharacterBody2D) [scripts/player.gd]
├── Sprite2D
├── CollisionShape2D (RectangleShape2D)
├── Hitbox (Area2D) — layer: Player, mask: EnemyBullet + Pickup
│   └── CollisionShape2D
├── GunPosition (Marker2D) — позиция спавна снарядов
├── EngineParticles (GPUParticles2D)
└── ShieldVisual (ColorRect) — видимый щит, обычно скрыт
```

Обратите внимание на отдельный узел Hitbox (Area2D) внутри Player. Зачем он нужен, если у CharacterBody2D уже есть CollisionShape2D? Причина — в разделении столкновений: основная форма (CollisionShape2D) используется для физического столкновения с телами, а Hitbox (Area2D) — для обнаружения вражеских снарядов и бонусов. Area2D генерирует сигналы `area_entered` и `body_entered`, которые удобнее для обработки попаданий, чем ручная проверка в `_physics_process`. Marker2D GunPosition определяет точку, откуда появляются снаряды — это позволяет легко смещать позицию стрельбы без изменения кода.

**enemy_base.tscn:**

```
EnemyBase (CharacterBody2D) [scripts/enemy_base.gd]
├── Sprite2D
├── CollisionShape2D
├── Hitbox (Area2D) — layer: Enemy, mask: PlayerBullet
│   └── CollisionShape2D
└── GunPosition (Marker2D)
```

Структура enemy_base аналогична player: CharacterBody2D для физического движения, Area2D Hitbox для обнаружения снарядов игрока, Marker2D для позиции стрельбы. Конкретные враги наследуют эту сцену и могут добавлять дополнительные узлы: bomber добавляет MinePosition, boss добавляет несколько GunPosition для разных типов атак.

**bullet.tscn:**

```
Bullet (Area2D) [scripts/bullet.gd]
├── Sprite2D
└── CollisionShape2D
```

Снаряд использует Area2D, а не CharacterBody2D, потому что ему не нужна физика — он движется по прямой с постоянной скоростью и не взаимодействует со стенами. Area2D легче по производительности и генерирует сигналы столкновений автоматически. CollisionShape2D отключается при возврате в пул с помощью `set_deferred("disabled", true)`, чтобы неактивные снаряды не генерировали ложных столкновений.

**pickup.tscn:**

```
Pickup (Area2D) [scripts/pickup.gd]
├── Sprite2D
├── CollisionShape2D
└── AnimationPlayer (для покачивания)
```

AnimationPlayer создаёт эффект покачивания — лёгкое синусоидальное движение вверх-вниз, которое привлекает внимание игрока. Альтернативно, покачивание можно реализовать через код (как в нашем скрипте), но AnimationPlayer даёт более плавный результат и не требует вычислений каждый кадр.

**explosion.tscn:**

```
Explosion (Node2D)
├── MainFlame (GPUParticles2D)
├── Debris (GPUParticles2D)
└── Glow (Sprite2D) — с explosion.gdshader
```

Взрыв состоит из трёх компонентов: основное пламя (яркие, крупные частицы), обломки (мелкие, быстро разлетающиеся частицы) и свечение (шейдерный спрайт, который расширяется и затухает). Комбинация этих трёх слоёв создаёт эффект, который выглядит значительно лучше, чем каждый компонент по отдельности.

**hud.tscn:**

```
HUD (CanvasLayer) [scripts/hud.gd]
├── TopBar (HBoxContainer)
│   ├── ScoreLabel (Label)
│   └── WaveLabel (Label)
├── HealthBar (TextureProgressBar)
├── ComboLabel (Label)
├── BossHealthBar (TextureProgressBar)
└── MessageLabel (Label) — "Волна 3!", "БОСС!", etc.
```

HUD использует CanvasLayer, чтобы оставаться на месте независимо от движения камеры. HBoxContainer автоматически располагает ScoreLabel и WaveLabel в строку. BossHealthBar по умолчанию скрыт и появляется только во время босс-файта. MessageLabel показывает временные сообщения (номер волны, предупреждение о боссе) и автоматически скрывается через 2 секунды.

## 2.3 Диаграмма классов

Диаграмма классов показывает отношения между основными скриптами проекта. Понимание этих отношений критически важно для навигации по кодовой базе и предотвращения циклических зависимостей.

```
Resource (встроенный)
├── WeaponData          — данные оружия (fire_rate, damage, bullet_count)
├── EnemyData           — данные врага (health, speed, behavior)
├── WaveData            — данные волны (spawn_entries, interval)
└── SpawnEntry          — запись спавна (enemy_scene, count, delay)

Node (Autoload)
├── GameManager         — состояние игры (score, combo, pause)
├── WaveManager         — система волн (current_wave, enemies_alive)
├── ObjectPool          — пул объектов (pools, scenes)
└── AudioManager        — звуковое воспроизведение (sfx_library, channels)

CharacterBody2D
├── Player              — корабль игрока (weapons, health, shield)
└── EnemyBase           — базовый враг (data, behavior, fire_timer)
    ├── EnemyFighter    — зигзаг-движение
    ├── EnemyTank       — медленный + очереди
    ├── EnemyBomber     — сброс мин
    ├── EnemyElite      — круговой обход
    └── Boss            — 3 фазы, сложные паттерны

Area2D
├── Bullet              — снаряд (direction, speed, damage)
└── Pickup              — бонус (type, value)

CanvasLayer
└── HUD                 — интерфейс (score, health, wave, combo)
```

Ключевые отношения: Player содержит массив `WeaponData` и генерирует сигналы `health_changed`, `player_died`, `weapon_changed`. EnemyBase содержит `EnemyData` и генерирует сигнал `died`. WaveManager содержит массив `WaveData` и генерирует сигналы `wave_started`, `wave_completed`. ObjectPool не зависит от конкретных типов объектов — он работает с `Node` и `PackedScene`. GameManager не зависит от визуальных компонентов — он оперирует числами и генерирует сигналы.

## 2.4 Поток данных

Понимание потока данных — ключ к отладке и модификации архитектуры. Рассмотрим два ключевых сценария.

**Сценарий 1: Игрок стреляет и уничтожает врага**

```
Player._physics_process()
  → Player.shoot()
    → ObjectPool.get_instance(bullet_scene)   — получение снаряда из пула
    → Bullet инициализируется (position, direction, speed, damage)

Bullet._physics_process()
  → Bullet движется: position += direction * speed * delta

Bullet._on_area_entered(enemy_hitbox)
  → enemy.has_method("take_damage")?  → да
  → EnemyBase.take_damage(damage)
    → health -= damage
    → health <= 0?  → да
    → EnemyBase.die()
      → died.emit(points)               — сигнал
      → ObjectPool.get_instance(explosion_scene)  — эффект взрыва
      → spawn_pickup() if random check passes
      → ObjectPool.release(self)         — возврат врага в пул
  → Bullet.return_to_pool()
    → CollisionShape2D.set_deferred("disabled", true)
    → ObjectPool.release(self)           — возврат снаряда в пул

WaveManager._on_enemy_died(points)
  → enemies_alive -= 1
  → GameManager.add_score(points)
    → score += points * combo
    → combo += 1 (max 4)
    → score_changed.emit(score)
    → combo_changed.emit(combo)

HUD._on_score_changed(new_score)
  → ScoreLabel.text = "Очки: %d" % new_score
```

Этот поток демонстрирует слабую связанность: Player не знает о WaveManager, EnemyBase не знает о HUD, Bullet не знает о GameManager. Все взаимодействия происходят через сигналы и методы, что позволяет изменять любой компонент независимо от других.

**Сценарий 2: Система волн создаёт врагов**

```
WaveManager.start_next_wave()
  → WaveData = waves[current_wave]
  → wave_started.emit(wave_number)        — HUD показывает "Волна N"
  → _build_spawn_queue(wave)
    → для каждого SpawnEntry:
        → добавить N записей в _spawn_queue

WaveManager._process(delta)
  → _spawn_timer -= delta
  → _spawn_timer <= 0?
    → _spawn_next_enemy()
      → entry = _spawn_queue.pop_front()
      → enemy = ObjectPool.get_instance(entry.scene)  — из пула
      → enemy.global_position = случайная позиция за верхним краем
      → enemy.died.connect(_on_enemy_died)            — подключение сигнала
      → enemy._is_active = true
      → enemies_alive += 1
      → _spawn_timer = entry.delay

WaveManager._on_enemy_died(points)
  → enemies_alive -= 1
  → GameManager.add_score(points)
  → enemies_alive <= 0 AND _spawn_queue.is_empty()?
    → wave_completed.emit(wave_number)
    → timer(3.0).timeout → start_next_wave()          — следующая волна
```

Поток данных при спавне демонстрирует роль ObjectPool как фабрики: WaveManager запрашивает объекты через `get_instance()`, не зная, создаётся ли новый объект или переиспользуется существующий. Это позволяет прозрачно оптимизировать производительность, не меняя логику спавна.

## 2.5 Паттерны проектирования

Паттерны проектирования — это проверенные решения типичных проблем. В нашем проекте мы применяем несколько паттернов, каждый из которых решает конкретную задачу. Важно понимать не только *как* они реализованы, но и *почему* — какую проблему решает каждый паттерн.

| Паттерн | Где применён | Зачем |
|---|---|---|
| Observer (Сигналы) | died, wave_started, health_changed | Слабая связанность между объектами |
| Object Pool | Bullets, enemies, explosions, pickups | Оптимизация: без instantiate/queue_free в рантайме |
| Strategy | WeaponData + разные конфигурации снарядов | Разные оружия без подклассов |
| Template Method | enemy_base.gd + scene inheritance | Общая логика врага, вариации в наследниках |
| State | Boss phases (enum + match) | Разное поведение в разных фазах |
| Singleton (Autoload) | GameManager, WaveManager, ObjectPool, AudioManager | Глобальный доступ к менеджерам |
| Factory | ObjectPool.get_instance() как PackedScene factory | Создание объектов из пула |
| Data-View separation | WeaponData/WaveData vs UI components | Баланс в .tres, UI в сценах |

Паттерн Observer (реализованный через сигналы Godot) — самый часто используемый паттерн в проекте. Когда враг умирает, он испускает сигнал `died`, и WaveManager реагирует на него, уменьшая счётчик живых врагов. Враг не знает о WaveManager, WaveManager не знает о HUD — каждый компонент работает автономно. Это критически важно для расширяемости: если мы захотим добавить achievement-систему, которая отслеживает уничтожение определённого количества врагов, нам просто нужно подключить новый слушатель к сигналу `died`, не модифицируя ни EnemyBase, ни WaveManager.

Паттерн Object Pool — это оптимизационный паттерн, который критически важен для экшен-игр. Без него каждый выстрел создавал бы новый узел через `instantiate()`, а каждое попадание удаляло бы его через `queue_free()`. В бою с десятками снарядов на экране это приводит к фрагментации памяти и задержкам. Object Pool预先 создаёт объекты и переиспользует их, избегая накладных расходов на аллокацию памяти.

Паттерн Template Method реализован через метод `move_behavior()` в `enemy_base.gd`: базовый класс определяет структуру поведения (движение → стрельба → проверка границ), а дочерние классы переопределяют конкретные шаги. Это позволяет добавлять новые типы поведения, не дублируя общую логику.

## 2.6 Структура файлов проекта

Организация файловой структуры — это не просто эстетика, это практическая необходимость. Когда проект вырастает до десятков файлов, способность быстро найти нужный скрипт или ресурс экономит часы разработки. Наша структура следует простому правилу: каждый тип файла в своей папке, каждая сцена — рядом с соответствующим скриптом (если они не разделены по папкам).

│   ├── enemy_base.tscn
│   ├── enemy_scout.tscn      (наследует enemy_base)
│   ├── enemy_fighter.tscn     (наследует enemy_base)
│   ├── enemy_tank.tscn        (наследует enemy_base)
│   ├── enemy_bomber.tscn      (наследует enemy_base)
│   ├── enemy_elite.tscn       (наследует enemy_base)
│   ├── boss.tscn              (наследует enemy_base)
│   ├── bullet.tscn
│   ├── pickup.tscn
│   ├── explosion.tscn
│   └── hud.tscn
├── scripts/
│   ├── main.gd
│   ├── player.gd
│   ├── enemy_base.gd

## 2.7 Слои столкновений

Система столкновений Godot основана на 32 физическиx слоях. Каждый объект может находиться на одном или нескольких слоях (layer) и проверять столкновения с одним или несколькими слоями (mask). Правильная конфигурация слоёв — это не только логическая правильность, но и оптимизация: чем меньше пар объектов проверяют столкновения, тем выше производительность.

| Слой # | Название | Объекты |
|---|---|---|
| 1 | Player | Корабль игрока |
| 2 | PlayerBullet | Снаряды игрока |
| 3 | Enemy | Враги и боссы |
| 4 | EnemyBullet | Снаряды врагов |
| 5 | Pickup | Бонусы |

Матрица взаимодействий (layer → mask):

| | Player | PlayerBullet | Enemy | EnemyBullet | Pickup |
|---|---|---|---|---|---|
| Player | — | — | — | ✓ | ✓ |
| PlayerBullet | — | — | ✓ | — | — |
| Enemy | — | ✓ | — | — | — |
| EnemyBullet | ✓ | — | — | — | — |
| Pickup | — | — | — | — | — |

Обратите внимание на несколько важных деталей. PlayerBullet не проверяет столкновения с Player — это предотвращает «самоповреждение» от собственных снарядов. Enemy не проверяет столкновения с EnemyBullet — вражеские снаряды не должны вредить своим же. Enemy не проверяет столкновения с Enemy — враги не должны сталкиваться друг с другом (это было бы визуально странно и создало бы ненужные физические взаимодействия). Pickup не имеет масок — он проверяется другими объектами (Player проверяет Pickup), но сам ничего не проверяет.

Для настройки названий слоёв в Godot перейдите в Project → Project Settings → Layer Names → 2D Physics. Присвойте слоям 1–5 имена Player, PlayerBullet, Enemy, EnemyBullet, Pickup соответственно. После этого в инспекторе каждого узла столкновений вы будете видеть понятные названия вместо номеров.

# Глава 4: Основы 2D-физики Godot

## 4.1 CharacterBody2D

CharacterBody2D — это специализированный узел Godot для объектов, которые управляются скриптом и взаимодействуют с физическим миром. В отличие от RigidBody2D, который управляется физическим движком, CharacterBody2D даёт полный контроль над движением через свойство `velocity` и метод `move_and_slide()`.

Для нашего космического шутера мы настраиваем `motion_mode = MOTION_MODE_FLOATING` (значение 1). Этот режим убирает гравитацию и поведение «вверх/вниз» — корабль может свободно двигаться в любом направлении с одинаковой скоростью. Это логично для космического пространства, где нет гравитации.

Метод `move_and_slide()` автоматически обрабатывает столкновения: если объект сталкивается со стеной, он скользит вдоль неё вместо того, чтобы застревать. Это предотвращает «прилипание» корабля к границам экрана и обеспечивает плавное движение. Важно: `move_and_slide()` должен вызываться в `_physics_process()`, а не в `_process()`, потому что `_physics_process()` работает с фиксированным шагом (по умолчанию 60 FPS), что обеспечивает стабильное поведение физики.

Разница между `_process(delta)` и `_physics_process(delta)`:

- `_process` вызывается каждый визуальный кадр. Частота вызовов зависит от FPS, который может варьироваться. Подходит для обновления UI, анимаций, логики, не связанной с физикой.
- `_physics_process` вызывается с фиксированным шагом (по умолчанию 1/60 секунды). Подходит для физического движения, проверок столкновений, любой логики, которая должна быть детерминированной.

Параметр `delta` в обоих методах — это время, прошедшее с предыдущего вызова. Умножение на `delta` (например, `position += velocity * delta`) обеспечивает одинаковую скорость движения независимо от FPS.

## 4.2 Area2D и сигналы столкновений

Area2D — это узел, который определяет область в пространстве и генерирует сигналы, когда другие объекты входят в эту область или покидают её. В отличие от CharacterBody2D, Area2D не участвует в физическом разрешении столкновений — она только обнаруживает их. Это делает её идеальной для снарядов (которые должны пролетать сквозь всё, кроме целей) и бонусов (которые должны реагировать на приближение игрока).

Основные сигналы Area2D:

- `body_entered(body: Node2D)` — физическое тело вошло в область
- `body_exited(body: Node2D)` — физическое тело покинуло область
- `area_entered(area: Area2D)` — другая область вошла в эту область
- `area_exited(area: Area2D)` — другая область покинула эту область

Для корректной работы Area2D должна иметь CollisionShape2D дочерним узлом. Без формы столкновений Area2D не сможет обнаруживать ничего. Форма может быть любой: RectangleShape2D, CircleShape2D, CapsuleShape2D — выбор зависит от визуальной формы объекта.

Слои и маски настраиваются в инспекторе: layer определяет, на каком слое находится объект (где его будут искать другие объекты), mask определяет, с какими слоями объект проверяет столкновения. Для снарядов игрока: layer = PlayerBullet, mask = Enemy. Это значит, что снаряд находится на слое PlayerBullet (чтобы враги могли его обнаружить) и проверяет столкновения со слоем Enemy.

## 4.3 Ввод игрока

Godot предоставляет несколько способов обработки ввода. Для нашего шутера мы используем InputMap — систему маппинга действий на конкретные клавиши. Это предпочтительный подход, потому что он абстрагирует конкретные клавиши от игровой логики: код обращается к действию `move_up`, а не к клавише `W`, что позволяет легко менять раскладку.

Метод `Input.get_vector(negative_x, positive_x, negative_y, positive_y)` — это удобный способ получения 2D-вектора направления из четырёх действий. Он автоматически нормализует вектор (длина = 1), обрабатывает одновременное нажатие нескольких клавиш и даже применяет мёртвую зону для геймпада. Без этого метода нам пришлось бы писать примерно такой код:

```gdscript
var input := Vector2.ZERO
if Input.is_action_pressed("move_right"): input.x += 1
if Input.is_action_pressed("move_left"):  input.x -= 1
if Input.is_action_pressed("move_down"):  input.y += 1
if Input.is_action_pressed("move_up"):    input.y -= 1
input = input.normalized()
```

`Input.get_vector()` делает всё это в одну строку, с дополнительной обработкой геймпада.

# Глава 5: Реализация

## 5.1 WeaponData — модель данных оружия

WeaponData — это Resource, который описывает все параметры оружия. Использование Resource для данных оружия — это ключевой архитектурный решение: оно позволяет создавать новые виды оружия без написания кода, просто создавая новые `.tres`-файлы в редакторе. Геймдизайнер может настраивать баланс (скорострельность, урон, разброс), не открывая ни одного скрипта.

```gdscript
# scripts/weapon_data.gd
class_name WeaponData
extends Resource

@export var id: String = ""
@export var display_name: String = "Пистолет"
@export var bullet_scene: PackedScene
@export var fire_rate: float = 0.20
@export var bullet_speed: float = 500.0
@export var bullet_damage: int = 10
@export var spread: float = 0.0
@export var bullet_count: int = 1
@export var bullet_spacing: float = 15.0
```

Разберём каждое поле: `id` — уникальный идентификатор для программного доступа (например, "pistol", "machinegun"). `display_name` — название для UI. `bullet_scene` — PackedScene снаряда, который создаётся при выстреле. `fire_rate` — задержка между выстрелами в секундах (0.20 = 5 выстрелов в секунду). `bullet_speed` — скорость снаряда в пикселях/сек. `bullet_damage` — урон одного снаряда. `spread` — угол разброса в радианах (0 = идеальная точность). `bullet_count` — количество снарядов за один выстрел (1 для пистолета, 3 для дробовика). `bullet_spacing` — расстояние между параллельными снарядами в пикселях.

Для создания `.tres`-файла в редакторе: щёлкните правой кнопкой по папке `resources/weapons/` → New Resource → выберите WeaponData → задайте имя `pistol.tres`. Затем в инспекторе заполните все поля. Повторите для каждого типа оружия.

## 5.2 EnemyData — модель данных врага

EnemyData аналогичен WeaponData — это Resource для описания параметров врага. Важное отличие — поле `behavior`, которое определяет тип движения через enum. Это позволяет описать поведение декларативно, а реализация конкретных паттернов движения находится в скриптах-наследниках `enemy_base.gd`.

```gdscript
# scripts/enemy_data.gd
class_name EnemyData
extends Resource

enum Behavior { STRAIGHT, ZIGZAG, STRAFE, CIRCLE, BOMBING }

@export var id: String = ""
@export var display_name: String = ""
@export var health: int = 10
@export var speed: float = 100.0
@export var points: int = 50
@export var behavior: Behavior = Behavior.STRAIGHT
@export var bullet_scene: PackedScene
@export var fire_rate: float = 0.0  # 0 = не стреляет
@export var drop_chance: float = 0.15
@export var zigzag_amplitude: float = 100.0
@export var zigzag_frequency: float = 2.0
```

Поле `fire_rate` равно 0 для врагов, которые не стреляют (например, разведчики). Для истребителей это может быть 2.0 (один выстрел каждые 2 секунды), для танков — 1.0. Поле `drop_chance` определяет вероятность выпадения бонуса при уничтожении врага — 0.15 означает 15%. Поля `zigzag_amplitude` и `zigzag_frequency` используются только для поведения ZIGZAG и определяют амплитуду и частоту синусоидального движения соответственно.

## 5.3 WaveData и SpawnEntry — модель данных волны

WaveData описывает состав волны, а SpawnEntry — конкретную запись спавна внутри волны. В Godot 4.3 для корректной работы вложенных ресурсов в инспекторе необходимо, чтобы каждый ресурс имел собственный `class_name` и находился в отдельном файле. Если определить SpawnEntry как вложенный класс внутри WaveData, инспектор не сможет корректно отображать и редактировать массив таких объектов.

```gdscript
# scripts/wave_data.gd
class_name WaveData
extends Resource

@export var wave_number: int = 1
@export var spawn_entries: Array[SpawnEntry] = []
@export var spawn_interval: float = 2.0
@export var start_delay: float = 3.0
```

```gdscript
# scripts/spawn_entry.gd
class_name SpawnEntry
extends Resource

@export var enemy_scene: PackedScene
@export var count: int = 1
@export var delay_between: float = 1.0
```

Разделение SpawnEntry в отдельный файл — это не просто техническое требование, но и архитектурное преимущество. SpawnEntry становится переиспользуемым компонентом: его можно использовать не только в WaveData, но и в других контекстах (например, для описания волн босса или событий в кат-сценах). Типизированный массив `Array[SpawnEntry]` обеспечивает типобезопасность и автодополнение в редакторе.

Поле `wave_number` — это порядковый номер волны для отображения в HUD. `spawn_entries` — массив записей, каждая из которых определяет тип врага, количество и задержку. `spawn_interval` — базовый интервал между спавнами. `start_delay` — задержка перед началом волны (даёт игроку время подготовиться).

## 5.4 ObjectPool — пул объектов

Пул объектов — это критически важный компонент для оптимизации производительности в экшен-играх. Проблема, которую он решает: непрерывное создание и удаление объектов (через `instantiate()` и `queue_free()`) приводит к фрагментации памяти и задержкам. В бою, где каждую секунду создаются десятки снарядов и эффектов, это может вызвать заметные «фризы».

КРИТИЧЕСКОЕ ИСПРАВЛЕНИЕ: Оригинальная реализация ObjectPool содержала серьёзный баг — метод `release()` вызывал `remove_child()` и `add_child()` при каждом возврате объекта в пул. Это дорогостоящая операция, которая: (1) вызывает перестроение дерева сцены, (2) генерирует сигналы `tree_entered`/`tree_exited`, (3) может вызывать ошибки, если объект уже был дочерним узлом ObjectPool. ИСПРАВЛЕННАЯ версия оставляет объекты дочерними узлами ObjectPool на всё время и просто переключает видимость и обработку.

```gdscript
# scripts/object_pool.gd
extends Node

var _pools: Dictionary = {}  # String -> Array[Node]
var _scenes: Dictionary = {}  # String -> PackedScene
const INITIAL_POOL_SIZE: int = 20


func preload_scene(scene_path: String, count: int = INITIAL_POOL_SIZE) -> void:
    if _scenes.has(scene_path):
        return
    var scene: PackedScene = load(scene_path)
    _scenes[scene_path] = scene
    _pools[scene_path] = []
    for i in count:
        var instance: Node = scene.instantiate()
        instance.set_process(false)
        instance.set_physics_process(false)
        instance.visible = false
        add_child(instance)
        _pools[scene_path].append(instance)


func get_instance(scene_or_path: Variant) -> Node:
    var path: String = ""
    if scene_or_path is PackedScene:
        path = scene_or_path.resource_path
    elif scene_or_path is String:
        path = scene_or_path

    if not _pools.has(path) or _pools[path].is_empty():
        # Пул пуст — создаём дополнительный объект
        if not _scenes.has(path):
            push_error("ObjectPool: сцена не предзагружена: %s" % path)
            return null
        var instance: Node = _scenes[path].instantiate()
        add_child(instance)
        instance.set_process(true)
        instance.set_physics_process(true)
        instance.visible = true
        return instance

    var instance: Node = _pools[path].pop_back()
    instance.set_process(true)
    instance.set_physics_process(true)
    instance.visible = true
    return instance


func release(instance: Node) -> void:
    var path: String = _find_scene_path(instance)
    if path.is_empty():
        instance.queue_free()
        return
    instance.set_process(false)
    instance.set_physics_process(false)
    instance.visible = false
    # НЕ делаем remove_child/add_child — объект остаётся дочерним ObjectPool
    # Перемещаем только если объект был добавлен в другой контейнер
    if instance.get_parent() != self:
        instance.get_parent().remove_child(instance)
        add_child(instance)
    _pools[path].append(instance)


func _find_scene_path(instance: Node) -> String:
    for path in _scenes:
        if _scenes[path].resource_path == instance.scene_file_path:
            return path
    return ""


func warm_up() -> void:
    # Предзагрузка всех часто используемых сцен
    preload_scene("res://scenes/bullet.tscn", 50)
    preload_scene("res://scenes/enemy_scout.tscn", 15)
    preload_scene("res://scenes/enemy_fighter.tscn", 10)
    preload_scene("res://scenes/explosion.tscn", 15)
    preload_scene("res://scenes/pickup.tscn", 5)
```

Рассмотрим ключевые отличия исправленной версии. Метод `release()` больше не вызывает безусловно `remove_child()` + `add_child()`. Вместо этого он проверяет, является ли ObjectPool текущим родителем объекта. Если да — объект просто деактивируется и добавляется в массив свободных. Если нет (объект был добавлен в контейнер, например, EnemyContainer) — тогда и только тогда выполняется перемещение. Это означает, что для объектов, которые никогда не покидают ObjectPool, операция возврата в пул — это просто три вызова: `set_process(false)`, `set_physics_process(false)`, `visible = false`.

Метод `get_instance()` теперь принимает как `PackedScene`, так и `String` (путь к сцене). Это упрощает вызов: можно передавать как `weapon.bullet_scene` (PackedScene), так и `"res://scenes/explosion.tscn"` (String). В обоих случаях используется путь ресурса как ключ в словаре пулов.

Метод `warm_up()` предзагружает все часто используемые сцены с количеством, достаточным для типичного геймплея. Снарядов нужно больше всего (50), потому что в интенсивном бою одновременно может быть 20+ снарядов на экране. Взрывов и врагов — меньше, потому что они создаются и уничтожаются реже.

## 5.5 GameManager — состояние игры

GameManager — это глобальный менеджер состояния игры. Он отвечает за счёт, комбо-множитель, паузу и определение конца игры. GameManager не знает о визуальных компонентах: он оперирует числами и генерирует сигналы, на которые реагирует HUD. Это разделение позволяет менять внешний вид HUD без изменения логики подсчёта очков.

```gdscript
# scripts/game_manager.gd
extends Node

signal score_changed(new_score: int)
signal health_changed(new_health: int)
signal combo_changed(multiplier: int)
signal game_over
signal game_paused(is_paused: bool)

var score: int = 0
var high_score: int = 0
var combo: int = 1
var combo_timer: float = 0.0
const COMBO_TIMEOUT: float = 2.0
const MAX_COMBO: int = 4

var is_paused: bool = false
var is_game_over: bool = false


func _ready() -> void:
    load_high_score()


func _process(delta: float) -> void:
    if combo_timer > 0:
        combo_timer -= delta
        if combo_timer <= 0:
            reset_combo()


func add_score(points: int) -> void:
    var multiplied: int = points * combo
    score += multiplied
    score_changed.emit(score)
    # Увеличиваем комбо
    combo = mini(combo + 1, MAX_COMBO)
    combo_timer = COMBO_TIMEOUT
    combo_changed.emit(combo)


func reset_combo() -> void:
    combo = 1
    combo_timer = 0.0
    combo_changed.emit(combo)


func game_over() -> void:
    is_game_over = true
    if score > high_score:
        high_score = score
        save_high_score()
    game_over.emit()


func toggle_pause() -> void:
    is_paused = not is_paused
    get_tree().paused = is_paused
    game_paused.emit(is_paused)


func save_high_score() -> void:
    var file: FileAccess = FileAccess.open("user://highscore.dat", FileAccess.WRITE)
    if file:
        file.store_32(high_score)
        file.close()


func load_high_score() -> void:
    if FileAccess.file_exists("user://highscore.dat"):
        var file: FileAccess = FileAccess.open("user://highscore.dat", FileAccess.READ)
        if file:
            high_score = file.get_32()
            file.close()


func reset_game() -> void:
    score = 0
    combo = 1
    combo_timer = 0.0
    is_game_over = false
    is_paused = false
    score_changed.emit(score)
    combo_changed.emit(combo)
```

Комбо-система работает следующим образом: при каждом убийстве врага `add_score()` увеличивает множитель на 1 (до максимума 4) и перезапускает таймер на 2 секунды. Если в течение 2 секунд не было нового убийства, `_process()` сбрасывает комбо до 1. Это создаёт динамику «риск-награда»: для поддержания высокого комбо нужно играть агрессивно, но агрессивная игра повышает риск получения урона.

Сохранение рекорда через `FileAccess` — это простой, но надёжный способ. Мы используем `store_32()` / `get_32()` для записи/чтения 32-битного целого числа. Файл сохраняется в директории `user://`, которая на разных ОС отображается в соответствующее место для пользовательских данных (на Linux — `~/.local/share/godot/appname/`, на Windows — `%APPDATA%/godot/appname/`).

## 5.6 WaveManager — система волн

WaveManager управляет потоком врагов: определяет, какие враги появляются, в каком количестве и с каким интервалом. Он построен на системе очереди: при старте волны все запланированные враги добавляются в `_spawn_queue`, а затем извлекаются по одному с заданным интервалом. Когда все враги спавнены и уничтожены, волна считается завершённой.

```gdscript
# scripts/wave_manager.gd
extends Node

signal wave_started(wave_number: int)
signal wave_completed(wave_number: int)
signal all_waves_completed
signal boss_spawned

@export var waves: Array[WaveData] = []

var current_wave: int = 0
var enemies_alive: int = 0
var _spawn_queue: Array[Dictionary] = []
var _spawn_timer: float = 0.0
var _wave_active: bool = false


func _process(delta: float) -> void:
    if not _wave_active:
        return
    if _spawn_queue.is_empty():
        return

    _spawn_timer -= delta
    if _spawn_timer <= 0:
        _spawn_next_enemy()


func start_next_wave() -> void:
    if current_wave >= waves.size():
        all_waves_completed.emit()
        return

    var wave: WaveData = waves[current_wave]
    wave_started.emit(current_wave + 1)
    _build_spawn_queue(wave)
    _wave_active = true
    _spawn_timer = wave.start_delay
    current_wave += 1


func _build_spawn_queue(wave: WaveData) -> void:
    _spawn_queue.clear()
    for entry in wave.spawn_entries:
        for i in entry.count:
            _spawn_queue.append({
                "scene": entry.enemy_scene,
                "delay": entry.delay_between,
            })


func _spawn_next_enemy() -> void:
    if _spawn_queue.is_empty():
        return

    var entry: Dictionary = _spawn_queue.pop_front()
    var enemy: CharacterBody2D = ObjectPool.get_instance(entry.scene)

    # Спавн за верхним краем экрана
    var viewport: Rect2 = get_viewport().get_visible_rect()
    enemy.global_position = Vector2(
        randf_range(viewport.position.x + 40, viewport.end.x - 40),
        viewport.position.y - 50
    )

    # Подключаем сигнал смерти
    if not enemy.died.is_connected(_on_enemy_died):
        enemy.died.connect(_on_enemy_died)

    enemy._is_active = true
    enemies_alive += 1
    _spawn_timer = entry.delay


func _on_enemy_died(points: int) -> void:
    enemies_alive -= 1
    GameManager.add_score(points)

    if enemies_alive <= 0 and _spawn_queue.is_empty():
        _wave_active = false
        wave_completed.emit(current_wave)
        # Задержка перед следующей волной
        get_tree().create_timer(3.0).timeout.connect(start_next_wave)
```

Важный аспект реализации: мы проверяем `enemies_alive <= 0 and _spawn_queue.is_empty()` для определения завершения волны. Оба условия должны быть истинны: все враги должны быть и спавнены (очередь пуста), и уничтожены (счётчик живых равен нулю). Это предотвращает преждевременный переход к следующей волне, когда часть врагов ещё не появилась.

Подключение сигнала `died` выполняется с проверкой `is_connected()`, чтобы избежать дублирования подключений. Это важно при переиспользовании объектов из пула: если объект уже был подключен, повторное подключение вызовет ошибку. В Godot 4.3+ можно использовать `FLAG_ONE_SHOT` или проверку `is_connected()` — мы выбрали второй вариант как более явный.

## 5.7 Player — корабль игрока

Скрипт игрока — один из самых комплексных в проекте. Он объединяет движение, стрельбу, получение урона, неуязвимость, щит и бомбы. Несмотря на это, код остаётся читаемым благодаря чёткому разделению ответственности внутри `_physics_process()` и выделению каждой операции в отдельный метод.

```gdscript
# scripts/player.gd
extends CharacterBody2D

signal health_changed(new_health: int)
signal player_died
signal weapon_changed(weapon: WeaponData)

@export var speed: float = 300.0
@export var max_health: int = 100
@export var weapons: Array[WeaponData] = []
@export var starting_weapon_index: int = 0

var health: int
var weapon: WeaponData
var weapon_index: int = 0
var fire_cooldown: float = 0.0
var invincible_timer: float = 0.0
var shield_timer: float = 0.0
var bomb_count: int = 3

@onready var sprite: Sprite2D = $Sprite2D
@onready var gun_position: Marker2D = $GunPosition
@onready var engine_particles: GPUParticles2D = $EngineParticles


func _ready() -> void:
    health = max_health
    if weapons.size() > 0:
        weapon = weapons[weapon_index]


func _physics_process(delta: float) -> void:
    # Движение
    var input_dir: Vector2 = Input.get_vector("move_left", "move_right", "move_up", "move_down")
    velocity = input_dir * speed
    move_and_slide()
    clamp_to_screen()

    # Стрельба
    fire_cooldown = maxf(0, fire_cooldown - delta)
    if Input.is_action_pressed("fire") and fire_cooldown <= 0:
        shoot()

    # Бомба
    if Input.is_action_just_pressed("bomb") and bomb_count > 0:
        use_bomb()

    # Неуязвимость (мерцание)
    if invincible_timer > 0:
        invincible_timer -= delta
        sprite.modulate.a = 0.5 if Engine.get_frames_drawn() % 6 < 3 else 1.0
    else:
        sprite.modulate.a = 1.0

    # Щит
    if shield_timer > 0:
        shield_timer -= delta
        $ShieldVisual.visible = true
    else:
        $ShieldVisual.visible = false

    # Двигательные частицы — активны только при движении
    engine_particles.emitting = velocity.length_squared() > 100


func clamp_to_screen() -> void:
    var viewport: Rect2 = get_viewport().get_visible_rect()
    var margin: float = 16.0
    global_position.x = clampf(global_position.x, viewport.position.x + margin, viewport.end.x - margin)
    global_position.y = clampf(global_position.y, viewport.position.y + margin, viewport.end.y - margin)


func shoot() -> void:
    if weapon == null:
        return
    fire_cooldown = weapon.fire_rate

    var bullet_offset: float = -weapon.bullet_spacing * (weapon.bullet_count - 1) / 2.0
    for i in weapon.bullet_count:
        var bullet: Area2D = ObjectPool.get_instance(weapon.bullet_scene)
        bullet.global_position = gun_position.global_position + Vector2(bullet_offset + i * weapon.bullet_spacing, 0)

        var angle: float = 0.0
        if weapon.bullet_count > 1:
            angle = -weapon.spread / 2.0 + weapon.spread * i / float(weapon.bullet_count - 1)
        bullet.direction = Vector2.from_angle(angle - PI / 2)
        bullet.speed = weapon.bullet_speed
        bullet.damage = weapon.bullet_damage

    AudioManager.play_sfx("shoot")


func take_damage(amount: int) -> void:
    if invincible_timer > 0 or shield_timer > 0:
        return
    health = maxi(0, health - amount)
    health_changed.emit(health)
    invincible_timer = 1.0  # 1 секунда неуязвимости

    if health <= 0:
        die()


func heal(amount: int) -> void:
    health = mini(max_health, health + amount)
    health_changed.emit(health)


func activate_shield(duration: float) -> void:
    shield_timer = duration


func upgrade_weapon() -> void:
    weapon_index = mini(weapon_index + 1, weapons.size() - 1)
    weapon = weapons[weapon_index]
    weapon_changed.emit(weapon)


func use_bomb() -> void:
    bomb_count -= 1
    AudioManager.play_sfx("bomb")
    # Наносит урон всем врагам на экране
    var enemies: Array[Node] = get_tree().get_nodes_in_group("enemies")
    for enemy in enemies:
        if enemy.has_method("take_damage"):
            enemy.take_damage(50)


func die() -> void:
    player_died.emit()
    engine_particles.emitting = false
    # Визуальный эффект смерти
    var explosion: Node2D = ObjectPool.get_instance("res://scenes/explosion.tscn")
    explosion.global_position = global_position
    explosion.scale = Vector2(1.5, 1.5)
    ObjectPool.release(self)
    GameManager.game_over()
```

Рассмотрим ключевые аспекты реализации. Метод `clamp_to_screen()` ограничивает позицию игрока в пределах видимой области с отступом 16 пикселей от краёв. Это предотвращает выход корабля за экран и использует `clampf()` — встроенную функцию Godot 4 для ограничения значения в диапазоне.

Система неуязвимости после получения урона (invincibility frames, или i-frames) реализована через таймер и мерцание спрайта. `Engine.get_frames_drawn() % 6 < 3` создаёт эффект мерцания, переключая прозрачность спрайта каждые 3 кадра. Это классическая техника, которая визуально коммуницирует игроку: «вы временно неуязвимы».

Стрельба поддерживает несколько снарядов за выстрел (для дробовика). Формула `bullet_offset` центрирует группу снарядов: если `bullet_count = 3` и `bullet_spacing = 15`, снаряды появятся на позициях -15, 0, +15 от центра. Разброс (`spread`) распределяется равномерно: первый снаряд отклоняется на `-spread/2`, последний — на `+spread/2`.

## 5.8 Bullet — снаряд

Снаряд — один из самых часто создаваемых объектов в игре, поэтому его скрипт должен быть максимально простым и эффективным. Мы используем Area2D вместо CharacterBody2D, потому что снаряду не нужна физика — он движется по прямой с постоянной скоростью. Area2D легче и генерирует сигналы столкновений автоматически.

```gdscript
# scripts/bullet.gd
extends Area2D

var direction: Vector2 = Vector2.UP
var speed: float = 400.0
var damage: int = 10
var lifetime: float = 3.0


func _physics_process(delta: float) -> void:
    position += direction * speed * delta
    lifetime -= delta
    if lifetime <= 0:
        return_to_pool()


func _on_body_entered(body: Node2D) -> void:
    if body.has_method("take_damage"):
        body.take_damage(damage)
    return_to_pool()


func _on_area_entered(area: Area2D) -> void:
    if area.has_method("take_damage"):
        area.take_damage(damage)
    return_to_pool()


func return_to_pool() -> void:
    set_process(false)
    set_physics_process(false)
    visible = false
    # Отключаем коллизии на время нахождения в пуле
    $CollisionShape2D.set_deferred("disabled", true)
    ObjectPool.release(self)


# Вызывается при извлечении из пула — сброс состояния
func _enter_tree() -> void:
    $CollisionShape2D.disabled = false
    lifetime = 3.0
```

Ключевой момент: при возврате в пул мы отключаем `CollisionShape2D` через `set_deferred("disabled", true)`. Префикс `set_deferred` означает, что изменение применяется в конце текущего кадра, а не немедленно. Это необходимо, потому что изменение формы столкновений во время обработки физики может вызвать ошибки. Без отключения неактивные снаряды в пуле генерировали бы ложные столкновения.

Метод `_enter_tree()` вызывается каждый раз, когда узел добавляется в дерево сцены. При извлечении из пула объект уже находится в дереве, но если он был перемещён между контейнерами, `_enter_tree()` сработает. Это надёжное место для сброса состояния: мы включаем коллизии и устанавливаем начальное время жизни. Альтернативный подход — добавить метод `reset()` и вызывать его из ObjectPool, но `_enter_tree()` работает автоматически.

## 5.9 EnemyBase — базовый враг

EnemyBase — это базовый скрипт для всех врагов, реализующий общую логику: движение вниз, получение урона, смерть, дроп бонусов, визуальную обратную связь. Конкретные типы врагов наследуют этот скрипт и переопределяют метод `move_behavior()` для реализации уникальных паттернов движения (паттерн Template Method).

```gdscript
# scripts/enemy_base.gd
extends CharacterBody2D

signal died(points: int)

@export var data: EnemyData

var health: int = 10
var max_health: int = 10
var speed: float = 100.0
var points: int = 50
var _target: Node2D = null
var _is_active: bool = false
var _fire_timer: float = 0.0
var _behavior_time: float = 0.0


func _ready() -> void:
    if data:
        apply_data(data)


func apply_data(enemy_data: EnemyData) -> void:
    health = enemy_data.health
    max_health = enemy_data.health
    speed = enemy_data.speed
    points = enemy_data.points


func _physics_process(delta: float) -> void:
    if not _is_active:
        return

    _behavior_time += delta

    # Движение вниз (базовое поведение)
    velocity = Vector2.DOWN * speed
    move_behavior(delta)
    move_and_slide()

    # Автоматическая стрельба
    if data and data.fire_rate > 0:
        _fire_timer -= delta
        if _fire_timer <= 0:
            shoot()
            _fire_timer = data.fire_rate

    # Удаление за нижним краем экрана
    var viewport: Rect2 = get_viewport().get_visible_rect()
    if global_position.y > viewport.end.y + 100:
        _return_to_pool()


func move_behavior(_delta: float) -> void:
    # Переопределяется в дочерних скриптах
    pass


func shoot() -> void:
    if data == null or data.bullet_scene == null:
        return
    var bullet: Area2D = ObjectPool.get_instance(data.bullet_scene)
    bullet.global_position = $GunPosition.global_position
    bullet.direction = Vector2.DOWN
    bullet.speed = 200.0
    bullet.damage = 10


func take_damage(amount: int) -> void:
    health -= amount
    if health <= 0:
        die()
    else:
        flash_damage()


func die() -> void:
    died.emit(points)
    spawn_explosion()
    # Шанс дропа бонуса
    if data and randf() < data.drop_chance:
        spawn_pickup()
    _return_to_pool()


func flash_damage() -> void:
    var sprite_node: Sprite2D = $Sprite2D
    sprite_node.modulate = Color.RED
    var tween: Tween = create_tween()
    tween.tween_property(sprite_node, "modulate", Color.WHITE, 0.15)


func spawn_explosion() -> void:
    var explosion: Node2D = ObjectPool.get_instance("res://scenes/explosion.tscn")
    explosion.global_position = global_position
    var scale_factor: float = clampf(float(health) / 30.0, 0.5, 2.0)
    explosion.scale = Vector2.ONE * scale_factor


func spawn_pickup() -> void:
    var pickup: Area2D = ObjectPool.get_instance("res://scenes/pickup.tscn")
    pickup.global_position = global_position


func _return_to_pool() -> void:
    _is_active = false
    set_process(false)
    set_physics_process(false)
    visible = false
    ObjectPool.release(self)
```

Метод `move_behavior()` — это сердце паттерна Template Method. Базовый класс определяет структуру `_physics_process()` (движение → поведение → стрельба → проверка границ), а дочерние классы переопределяют только `move_behavior()`. Это гарантирует, что общая логика (например, проверка выхода за экран) не дублируется, при этом каждый тип врага имеет уникальное поведение.

Флаг `_is_active` критически важен при работе с пулом объектов. Когда враг возвращается в пул, `_is_active` устанавливается в `false`, и `_physics_process()` немедленно прекращает выполнение. Без этой проверки «спящие» враги продолжали бы двигаться и стрелять, даже будучи невидимыми. При извлечении из пула WaveManager устанавливает `_is_active = true`, активируя врага.

Визуальная обратная связь при получении урона (flash_damage) использует Tween для плавного возврата цвета от красного к белому. Это простой, но эффективный эффект, который мгновенно коммуницирует игроку: «вы попали». Метод `create_tween()` создаёт Tween, привязанный к текущему узлу — он автоматически освободится при удалении узла, предотвращая утечки памяти.

## 5.10 Вариации врагов

Каждый тип врага наследует `enemy_base.gd` и переопределяет метод `move_behavior()`. Это минимальное изменение, которое добавляет уникальное поведение без дублирования общей логики. Рассмотрим три ключевых вариации.

**Истребитель — зигзаг-движение:**

```gdscript
# scripts/enemy_fighter.gd
extends "res://scripts/enemy_base.gd"

var _zigzag_time: float = 0.0


func move_behavior(delta: float) -> void:
    _zigzag_time += delta
    var amplitude: float = data.zigzag_amplitude if data else 100.0
    var frequency: float = data.zigzag_frequency if data else 2.0
    var offset: float = sin(_zigzag_time * frequency) * amplitude
    velocity = Vector2.DOWN * speed + Vector2.RIGHT * offset * delta * 60
```

Зигзаг-движение использует синусоидальную функцию для бокового смещения. Параметры `zigzag_amplitude` (100) и `zigzag_frequency` (2.0) определяют размах и скорость бокового движения. Умножение на `delta * 60` нормализует скорость к 60 FPS, обеспечивая одинаковое поведение при разной частоте кадров. Визуально это создаёт волнообразное движение, которое значительно усложняет прицеливание игроку.

**Танк — медленный, но мощный:**

```gdscript
# scripts/enemy_tank.gd
extends "res://scripts/enemy_base.gd"
# Танк просто движется медленнее, стреляет очередями — всё настраивается через data
# Дополнительная логика не требуется: низкая скорость и высокий HP заданы в EnemyData
```

Танк — пример того, как паттерн Template Method позволяет создавать новые типы врагов без кода. Все его особенности (высокий HP = 80, низкая скорость = 60, частая стрельба) настраиваются через `tank_data.tres`. Нет необходимости переопределять `move_behavior()`, потому что танк использует базовое поведение — прямое движение вниз. Это demonstrates the power of data-driven design: иногда новые сущности создаются не кодом, а конфигурацией.

**Бомбардировщик — сброс мин:**

```gdscript
# scripts/enemy_bomber.gd
extends "res://scripts/enemy_base.gd"

var _mine_timer: float = 3.0


func move_behavior(delta: float) -> void:
    # Движение медленное, периодически сбрасывает мины
    _mine_timer -= delta
    if _mine_timer <= 0:
        _spawn_mine()
        _mine_timer = 3.0


func _spawn_mine() -> void:
    var mine: Area2D = ObjectPool.get_instance("res://scenes/bullet.tscn")
    mine.global_position = global_position
    mine.direction = Vector2.DOWN
    mine.speed = 50.0
    mine.damage = 20
    mine.lifetime = 5.0
```

Бомбардировщик добавляет новую механику: мины, которые медленно падают вниз и создают опасные зоны. Мины реализованы как медленные снаряды (speed = 50) с увеличенным временем жизни (5 секунд) и повышенным уроном (20). Это заставляет игрока не только уклоняться от снарядов, но и отслеживать мины на экране, добавляя ещё один уровень внимания к геймплею.

## 5.11 Boss — босс с фазами

Скрипт босса — самый сложный в проекте. Он реализует три фазы с различными паттернами атак и движения, используя `enum Phase` и `match` для переключения поведения. Ключевое слово `super` обеспечивает вызов базовой логики `take_damage()` из `enemy_base.gd`, а затем добавляет логику смены фаз.

```gdscript
# scripts/boss.gd
extends "res://scripts/enemy_base.gd"

enum Phase { WARMUP, ASSAULT, RAGE }

var current_phase: Phase = Phase.WARMUP
var _phase_thresholds: Array[float] = [0.66, 0.33]
var _circle_angle: float = 0.0
var _minion_timer: float = 0.0


func _ready() -> void:
    super._ready()
    health = 500
    max_health = 500
    speed = 60.0
    points = 5000


func take_damage(amount: int) -> void:
    super.take_damage(amount)
    var health_pct: float = float(health) / float(max_health)

    match current_phase:
        Phase.WARMUP:
            if health_pct <= _phase_thresholds[0]:
                enter_phase(Phase.ASSAULT)
        Phase.ASSAULT:
            if health_pct <= _phase_thresholds[1]:
                enter_phase(Phase.RAGE)


func enter_phase(phase: Phase) -> void:
    current_phase = phase
    match phase:
        Phase.ASSAULT:
            speed *= 1.5
            if data: data.fire_rate *= 0.6
        Phase.RAGE:
            speed *= 1.3
            if data: data.fire_rate *= 0.4

    # Визуальный сигнал смены фазы
    var tween: Tween = create_tween()
    tween.tween_property($Sprite2D, "modulate", Color.ORANGE, 0.3)
    tween.tween_property($Sprite2D, "modulate", Color.WHITE, 0.3)
    AudioManager.play_sfx("boss_phase")


func move_behavior(delta: float) -> void:
    match current_phase:
        Phase.WARMUP:
            # Медленное движение вправо-влево
            velocity = Vector2.DOWN * speed * 0.3 + Vector2.RIGHT * sin(_behavior_time * 0.5) * speed
        Phase.ASSAULT:
            # Зигзаг с большей амплитудой
            velocity = Vector2.DOWN * speed * 0.2 + Vector2.RIGHT * sin(_behavior_time * 1.5) * speed * 1.5
        Phase.RAGE:
            # Агрессивное круговое движение
            _circle_angle += delta * 2.0
            velocity = Vector2.RIGHT * cos(_circle_angle) * speed * 1.5 + Vector2.DOWN * speed * 0.1
            # Спавн миньонов
            _minion_timer -= delta
            if _minion_timer <= 0:
                _spawn_minions()
                _minion_timer = 5.0


func shoot() -> void:
    if data == null or data.bullet_scene == null:
        return

    match current_phase:
        Phase.WARMUP:
            # Одиночный выстрел вниз
            var bullet: Area2D = ObjectPool.get_instance(data.bullet_scene)
            bullet.global_position = $GunPosition.global_position
            bullet.direction = Vector2.DOWN
            bullet.speed = 200.0
            bullet.damage = 15
        Phase.ASSAULT:
            # Очередь из 5 снарядов веером
            for i in 5:
                var angle: float = -0.3 + 0.15 * i
                var bullet: Area2D = ObjectPool.get_instance(data.bullet_scene)
                bullet.global_position = $GunPosition.global_position
                bullet.direction = Vector2.from_angle(PI / 2 + angle)
                bullet.speed = 220.0
                bullet.damage = 12
        Phase.RAGE:
            # Круговой обстрел: 12 снарядов
            for i in 12:
                var angle: float = TAU * i / 12.0
                var bullet: Area2D = ObjectPool.get_instance(data.bullet_scene)
                bullet.global_position = global_position
                bullet.direction = Vector2.from_angle(angle)
                bullet.speed = 180.0
                bullet.damage = 10


func _spawn_minions() -> void:
    for i in 2:
        var minion: CharacterBody2D = ObjectPool.get_instance("res://scenes/enemy_scout.tscn")
        minion.global_position = global_position + Vector2(i * 60 - 30, 30)
        minion._is_active = true
        if not minion.died.is_connected(WaveManager._on_enemy_died):
            minion.died.connect(WaveManager._on_enemy_died)
        WaveManager.enemies_alive += 1
```

Рассмотрим ключевые аспекты босса. Вызов `super.take_damage(amount)` гарантирует, что базовая логика (уменьшение здоровья, проверка смерти) выполняется перед проверкой фаз. Без этого вызова здоровье босса не уменьшалось бы, потому что мы переопределили метод полностью.

Каждая фаза имеет уникальное движение: WARMUP — медленное покачивание, ASSAULT — агрессивный зигзаг, RAGE — круговое движение. Круговое движение в фазе RAGE использует `_circle_angle`, который непрерывно увеличивается, создавая орбитальное движение. Это делает босса непредсказуемым и вынуждает игрока постоянно перемещаться.

Круговой обстрел в фазе RAGE (`TAU * i / 12.0`) создаёт 12 снарядов, равномерно распределённых по кругу. `TAU` — это константа Godot, равная `2 * PI`. Каждый снаряд направлен под углом `360/12 = 30` градусов от предыдущего. Это создаёт «кольцо» снарядов, которое расширяется от босса, оставляя безопасные зоны между снарядами. Игрок должен найти и занять одну из этих зон, что требует быстрого чтения паттерна.

## 5.12 Pickup — бонусы

Бонусы (pickups) — это подбираемые предметы, которые выпадают из уничтоженных врагов с определённой вероятностью. Каждый бонус имеет тип, определяющий его эффект. Сценарий pickup прост: двигаться вниз (медленно, чтобы игрок успел подобрать), покачиваться для привлечения внимания и реагировать на столкновение с игроком.

```gdscript
# scripts/pickup.gd
extends Area2D

enum PickupType { HEALTH, WEAPON, SHIELD, BOMB }

@export var type: PickupType = PickupType.HEALTH
@export var value: int = 25

var _bob_time: float = 0.0


func _physics_process(delta: float) -> void:
    _bob_time += delta
    position.y += sin(_bob_time * 3.0) * 0.5


func _on_body_entered(body: Node2D) -> void:
    if not body.is_in_group("player"):
        return

    match type:
        PickupType.HEALTH:
            body.heal(value)
        PickupType.WEAPON:
            body.upgrade_weapon()
        PickupType.SHIELD:
            body.activate_shield(3.0)
        PickupType.BOMB:
            body.bomb_count += 1

    AudioManager.play_sfx("pickup")
    ObjectPool.release(self)
```

Покачивание (`sin(_bob_time * 3.0) * 0.5`) — это простой визуальный эффект, который делает бонусы заметными. Синусоида создаёт плавное движение вверх-вниз, а множитель 3.0 определяет скорость покачивания. Величина 0.5 пикселя — это едва заметное, но достаточное для привлечения внимания движение.

Проверка `body.is_in_group("player")` гарантирует, что бонусы подбирает только игрок. Это важно, потому что в область бонуса могут попасть и другие объекты (например, враги). Группа "player" назначается кораблю игрока в редакторе или через `add_to_group("player")` в `_ready()`.

Определение типа бонуса происходит при спавне. В методе `spawn_pickup()` в `enemy_base.gd` можно расширить логику, чтобы случайно определять тип:

```gdscript
# Расширенная версия spawn_pickup() для enemy_base.gd
func spawn_pickup() -> void:
    var pickup: Area2D = ObjectPool.get_instance("res://scenes/pickup.tscn")
    pickup.global_position = global_position
    # Случайный тип бонуса с весами
    var roll: float = randf()
    if roll < 0.50:
        pickup.type = Pickup.PickupType.HEALTH
    elif roll < 0.78:
        pickup.type = Pickup.PickupType.WEAPON
    elif roll < 0.93:
        pickup.type = Pickup.PickupType.SHIELD
    else:
        pickup.type = Pickup.PickupType.BOMB
```

Обратите внимание на распределение вероятностей: HEALTH — 50%, WEAPON — 28%, SHIELD — 15%, BOMB — 7%. Это соответствует таблице из раздела геймдизайна: здоровье — самый частый бонус, бомба — самый редкий.

## 5.13 HUD — интерфейс

HUD (Heads-Up Display) отображает игровую информацию: счёт, здоровье, номер волны, комбо и здоровье босса. HUD построен на реактивном принципе: он подписывается на сигналы GameManager и WaveManager и обновляется только при изменении данных, а не каждый кадр. Это эффективнее, чем опрос данных каждый кадр, и лучше разделяет ответственность.

```gdscript
# scripts/hud.gd
extends CanvasLayer

@onready var score_label: Label = $TopBar/ScoreLabel
@onready var wave_label: Label = $TopBar/WaveLabel
@onready var health_bar: TextureProgressBar = $HealthBar
@onready var combo_label: Label = $ComboLabel
@onready var boss_health_bar: TextureProgressBar = $BossHealthBar
@onready var message_label: Label = $MessageLabel


func _ready() -> void:
    GameManager.score_changed.connect(_on_score_changed)
    GameManager.combo_changed.connect(_on_combo_changed)
    WaveManager.wave_started.connect(_on_wave_started)
    WaveManager.boss_spawned.connect(_on_boss_spawned)
    boss_health_bar.visible = false


func update_health(current: int, maximum: int) -> void:
    health_bar.value = float(current) / float(maximum) * 100.0


func update_boss_health(current: int, maximum: int) -> void:
    boss_health_bar.value = float(current) / float(maximum) * 100.0


func _on_score_changed(new_score: int) -> void:
    score_label.text = "Очки: %d" % new_score


func _on_combo_changed(multiplier: int) -> void:
    if multiplier > 1:
        combo_label.text = "x%d КОМБО!" % multiplier
        combo_label.visible = true
    else:
        combo_label.visible = false


func _on_wave_started(wave_number: int) -> void:
    wave_label.text = "Волна: %d" % wave_number
    message_label.text = "Волна %d" % wave_number
    message_label.visible = true
    get_tree().create_timer(2.0).timeout.connect(func(): message_label.visible = false)


func _on_boss_spawned() -> void:
    boss_health_bar.visible = true
    message_label.text = "БОСС!"
    message_label.visible = true
    get_tree().create_timer(2.0).timeout.connect(func(): message_label.visible = false)
```

Метод `update_health()` вызывается из `main.gd` при получении игроком урона или лечении. Он преобразует текущее здоровье в процент для TextureProgressBar (0–100). Альтернативный подход — подписать HUD на сигнал `player.health_changed`, но это создало бы зависимость HUD от конкретного экземпляра Player. Текущий подход, где Main выступает посредником, более гибок.

MessageLabel показывает временные сообщения (номер волны, предупреждение о боссе) и автоматически скрывается через 2 секунды. Для этого используется `get_tree().create_timer(2.0).timeout`, который создаёт одноразовый таймер. Лямбда-функция `func(): message_label.visible = false` выполняется по истечении таймера. Это удобно, но стоит помнить, что при смене сцены таймер может не сработать — в таком случае лучше хранить ссылку на таймер и отменять его.

## 5.14 Main — корневая сцена

Main — это корневая сцена игры, которая связывает все компоненты воедино. Она не содержит игровой логики — только координацию: подключение сигналов, инициализацию пулов, запуск первой волны. Это «клей», который соединяет независимые компоненты в работающую игру.

```gdscript
# scripts/main.gd
extends Node2D

@export var player_scene: PackedScene

@onready var player: CharacterBody2D = $PlayArea/Player
@onready var hud: CanvasLayer = $HUD


func _ready() -> void:
    # Предзагрузка пулов
    ObjectPool.warm_up()

    # Подключаем сигналы игрока
    player.health_changed.connect(_on_player_health_changed)
    player.player_died.connect(_on_player_died)

    # Подключаем WaveManager
    WaveManager.all_waves_completed.connect(_on_all_waves_completed)

    # Старт первой волны
    get_tree().create_timer(2.0).timeout.connect(WaveManager.start_next_wave)


func _on_player_health_changed(new_health: int) -> void:
    hud.update_health(new_health, player.max_health)


func _on_player_died() -> void:
    # Показать экран Game Over
    pass  # TODO: реализовать экран Game Over


func _on_all_waves_completed() -> void:
    hud.message_label.text = "ПОБЕДА!"
    hud.message_label.visible = true
```

Метод `_ready()` выполняет три ключевые операции. Во-первых, `ObjectPool.warm_up()` предзагружает все часто используемые сцены, чтобы в момент первого выстрела или спавна врага пул уже содержал готовые объекты. Без warm_up первый выстрел вызвал бы `instantiate()` вместо переиспользования, что создало бы заметную задержку.

Во-вторых, мы подключаем сигналы игрока к методам Main. `health_changed` обновляет HUD, `player_died` инициирует экран Game Over. В-третьих, мы запускаем первую волну с задержкой в 2 секунды, давая игроку время освоиться после старта игры.

Метод `_on_all_waves_completed()` вызывается, когда WaveManager прошёл все волны. В текущей реализации он просто показывает сообщение «ПОБЕДА!», но в полной игре здесь должна быть кат-сцена, экран результатов или переход к циклу повышенной сложности.

## 5.15 AudioManager

AudioManager — это централизованный менеджер воспроизведения звуков с пулом каналов. Он решает две проблемы: (1) ограничение количества одновременно воспроизводимых звуков для предотвращения перегрузки, и (2) разделение музыки и эффектов на разные шины (bus) для независимой регулировки громкости.

```gdscript
# scripts/audio_manager.gd
extends Node

var _sfx_players: Array[AudioStreamPlayer] = []
var _sfx_library: Dictionary = {}
var _music_player: AudioStreamPlayer

const MAX_SFX_CHANNELS: int = 8
const SFX_PATH: String = "res://assets/audio/sfx/"


func _ready() -> void:
    _music_player = AudioStreamPlayer.new()
    _music_player.bus = "Music"
    add_child(_music_player)

    for i in MAX_SFX_CHANNELS:
        var player: AudioStreamPlayer = AudioStreamPlayer.new()
        player.bus = "SFX"
        add_child(player)
        _sfx_players.append(player)

    _load_sfx_library()


func _load_sfx_library() -> void:
    var dir: DirAccess = DirAccess.open(SFX_PATH)
    if dir == null:
        return
    dir.list_dir_begin()
    var file_name: String = dir.get_next()
    while file_name != "":
        if file_name.ends_with(".wav") or file_name.ends_with(".ogg"):
            var key: String = file_name.get_basename()
            _sfx_library[key] = load(SFX_PATH + file_name)
        file_name = dir.get_next()
    dir.list_dir_end()


func play_sfx(sfx_name: String, volume_db: float = 0.0) -> void:
    if not _sfx_library.has(sfx_name):
        return
    var player: AudioStreamPlayer = _get_available_player()
    if player == null:
        return
    player.stream = _sfx_library[sfx_name]
    player.volume_db = volume_db
    player.play()


func play_music(stream: AudioStream) -> void:
    _music_player.stream = stream
    _music_player.play()


func _get_available_player() -> AudioStreamPlayer:
    for player in _sfx_players:
        if not player.playing:
            return player
    return null
```

Метод `_load_sfx_library()` автоматически загружает все звуковые файлы из папки `assets/audio/sfx/`. Имя файла без расширения становится ключом в библиотеке: файл `shoot.wav` доступен как `AudioManager.play_sfx("shoot")`. Это удобно, потому что добавление нового звука не требует изменения кода — просто поместите файл в нужную папку.

Ограничение `MAX_SFX_CHANNELS = 8` предотвращает звуковое перегрузжение. Представьте ситуацию: 10 врагов уничтожаются одновременно, и каждый пытается воспроизвести звук взрыва. Без ограничения все 10 звуков играли бы одновременно, создавая неразборчивый шум и потенциально перегружая аудиосистему. С ограничением играют только первые 8, а остальные отбрасываются — игрок всё равно не заметит разницу.

Для настройки аудио-шины: откройте Audio-панель внизу редактора (Bottom Panel → Audio). Создайте две шины: "Master" (по умолчанию), "Music" и "SFX". Шины Music и SFX должны быть дочерними шины Master. Это позволяет регулировать общую громкость через Master и отдельно — музыку и эффекты.

# Глава 6: Шейдеры и визуальные эффекты

## 6.1 Шейдер звёздного поля

Шейдеры — это программы, выполняемые на видеокарте, которые позволяют создавать визуальные эффекты, невозможные или слишком медленные при обычном подходе. В Godot шейдеры пишутся на собственном шейдерном языке (похожем на GLSL) и присоединяются к узлам через ShaderMaterial.

Наш первый шейдер создаёт эффект прокручивающегося звёздного поля без использования текстуры со звёздами. Вместо этого он использует шумовую текстуру и пороговую функцию: пиксели со значением шума выше определённого порога становятся звёздами, остальные — прозрачными. Параметр `TIME` встроен в шейдерный язык Godot и автоматически увеличивается со временем, создавая анимацию скроллинга.

```glsl
// shaders/star_field.gdshader
shader_type canvas_item;

uniform float scroll_speed : hint_range(0.0, 500.0) = 100.0;
uniform vec2 tile_scale = vec2(3.0, 3.0);
uniform sampler2D noise_texture : repeat_enable, filter_nearest;

void fragment() {
    vec2 uv = UV * tile_scale;
    uv.y += TIME * scroll_speed / 500.0;

    float noise = texture(noise_texture, uv).r;
    float star = step(0.92, noise);

    vec3 color = mix(vec3(0.0), vec3(0.8, 0.9, 1.0), star);
    COLOR = vec4(color, star * 0.8);
}
```

Разберём шейдер построчно. `shader_type canvas_item` указывает, что это 2D-шейдер. `uniform`-переменные доступны для настройки из GDScript и инспектора. `hint_range(0.0, 500.0)` добавляет слайдер в инспекторе. `repeat_enable` обеспечивает тайлинг шумовой текстуры. `filter_nearest` отключает фильтрацию для чётких пикселей.

В функции `fragment()`: `UV * tile_scale` масштабирует UV-координаты для создания мозаичного эффекта. `uv.y += TIME * scroll_speed / 500.0` сдвигает текстуру вниз, создавая скроллинг. `step(0.92, noise)` — пороговая функция: возвращает 1.0, если noise >= 0.92, иначе 0.0. Это создаёт звёзды из самых ярких точек шума. `mix(vec3(0.0), vec3(0.8, 0.9, 1.0), star)` смешивает чёрный и голубой цвета на основе значения star. Финальный `COLOR` включает звёзды с полупрозрачностью 0.8.

Для использования шейдера создайте ShaderMaterial для ParallaxLayer, назначьте этот шейдер и укажите шумовую текстуру (FastNoiseLite, сгенерированную в Godot) в поле noise_texture. Для параллакс-эффекта создайте три ParallaxLayer с разной scroll_speed: 20 (дальний), 60 (средний), 120 (ближний).

## 6.2 Шейдер взрыва

Второй шейдер создаёт эффект взрыва — расширяющееся свечение с затуханием. Он применяется к спрайту (Glow-узел в explosion.tscn) и управляется параметром `progress`, который анимируется через Tween.

```glsl
// shaders/explosion.gdshader
shader_type canvas_item;

uniform float progress : hint_range(0.0, 1.0) = 0.0;
uniform vec4 glow_color : source_color = vec4(1.0, 0.6, 0.2, 1.0);

void fragment() {
    float dist = length(UV - 0.5) * 2.0;
    float ring = smoothstep(progress - 0.3, progress, dist)
               * smoothstep(progress + 0.1, progress, dist);
    float glow = exp(-dist * 3.0) * (1.0 - progress);
    float alpha = ring + glow;

    vec3 col = mix(glow_color.rgb, vec3(1.0), ring);
    COLOR = vec4(col, alpha);
}
```

Шейдер комбинирует два эффекта. Кольцо (`ring`) — это расширяющаяся окружность, созданная произведением двух `smoothstep`: один создаёт внутренний край, другой — внешний. Произведение даёт узкое кольцо, которое расширяется по мере увеличения `progress`. Свечение (`glow`) — это экспоненциально затухающий градиент от центра, который уменьшается с увеличением `progress`. Сумма `ring + glow` даёт финальный эффект: яркое кольцо с мягким свечением.

Для анимации взрыва в коде:

```gdscript
var tween: Tween = create_tween()
tween.tween_property(glow_sprite.material, "shader_parameter/progress", 1.0, 0.8)
tween.tween_callback(ObjectPool.release.bind(self))
```

Параметр `progress` анимируется от 0 до 1 за 0.8 секунды, создавая эффект расширения взрыва. По завершении анимации объект возвращается в пул.
