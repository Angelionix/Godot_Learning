# О курсе

Добро пожаловать в полный курс разработки игр на Godot Engine — проектно-ориентированный учебный курс, в котором обучение строится вокруг создания шести полноценных игровых проектов. От простейшей кликер-игры до масштабной 3D-демонстрации с тысячами объектов — каждый проект логически вытекает из предыдущего, постепенно наращивая сложность и вводя новые концепции. Курс спроектирован так, чтобы вы не просто читали теорию, а реально создавали игры, осваивая каждый навык через практику.

Уникальность этого курса — в постепенном переходе от GDScript к C++. Мы начинаем с GDScript, встроенного скриптового языка Godot, который идеально подходит для быстрого прототипирования и изучения основ. Затем, по мере роста сложности проектов, мы переходим к C++ через механизм GDExtension, осваивая его в тех областях, где производительность критически важна: pathfinding, ECS, многопоточность, compute-шейдеры. К концу курса вы будете свободно владеть обоими языками и понимать, когда какой применять.

Курс содержит более 13 400 строк детализированного контента, охватывающего геймдизайн, архитектуру и проверку кода для каждого из шести проектов. Каждый проект — это не набор разрозненных уроков, а цельная история создания игры от концепции до финального билда.

# Методология: Анти-Tutorial Hell

Классический подход к обучению программированию игр страдает от синдрома «Tutorial Hell» — ученик следует пошаговым инструкциям, получает работающий результат, но не понимает, как подступиться к собственному проекту. Этот курс построен на принципиально иной методологии, которая сознательно противостоит этому паттерну.

**Архитектура прежде кода.** Каждый проект начинается не с написания кода, а с проектирования: сначала геймдизайн-документ (какая игра, почему она работает, какие параметры), затем архитектура (какие классы, как они связаны, какой поток данных), и только потом — реализация. Это зеркально отражает реальный процесс разработки, где кодирование — финальный этап, а не первый. Ученик привыкает думать о структуре до того, как открывает редактор.

**Микровызовы вместо готовых решений.** Вместо того чтобы давать готовый код для каждой функции, курс предлагает микровызовы — задания на расширение базового проекта. Каждый вызов помечен уровнем сложности (🟢 лёгкий, 🟡 средний, 🔴 экспертный) и может быть выполнен независимо. Микровызовы требуют самостоятельного проектирования решений в рамках уже знакомой архитектуры, что формирует навык мышления, а не копирования.

**Финальные спринты как проверка автономности.** После каждого проекта предусмотрен спринт — задание создать свою версию игры с конкретными требованиями. Спринт проверяет, может ли ученик самостоятельно применить изученные паттерны и концепции без подсказок. Обязательные требования покрывают ключевые навыки проекта, бонусные — продвинутые и творческие задачи.

**Мосты между проектами.** Каждый проект заканчивается формализованным мостом к следующему, который показывает: какие навыки переносятся, какие концепции расширяются, и что появляется впервые. Это создаёт единую траекторию обучения, где каждый проект — не изолированный остров, а звено в цепочке прогрессии.

**Трёхглавная структура.** Каждый проект состоит из трёх глав, каждая из которых решает свою задачу. Глава 1 «Геймдизайн» отвечает на вопрос «что мы делаем и почему» — от концепции до таблиц балансировки. Глава 2 «Архитектура» отвечает на вопрос «как это устроено» — от диаграмм классов до потоков данных. Глава 3 «Код и верификация» отвечает на вопрос «как это реализовать и проверить» — от структуры файлов до чек-листов. Такое разделение гарантирует, что ученик понимает каждый аспект создания игры, а не только механику написания кода.

# Трёхглавная структура каждого проекта

Каждый проект курса следует единой трёхглавной структуре, которая обеспечивает целостное понимание процесса разработки. Эта структура не случайна — она отражает реальный профессиональный процесс создания игр, где проектирование предшествует кодированию.

## Глава 1: Геймдизайн

Геймдизайн-документ (ГДД) — это фундамент проекта. В этой главе определяется концепция игры, ключевая фантазия игрока, основной игровой цикл и петля обратной связи. Особое внимание уделяется числовой балансировке: таблицы врагов, оружия, апгрейдов, экономика — все параметры выверены и обоснованы. Без этого этапа разработка превращается в хаотичное добавление фич, которые не складываются в цельный опыт. Здесь же размещены микровызовы — задания на расширение проекта с указанием уровня сложности и ключевых навыков.

## Глава 2: Архитектура

Архитектурная глава описывает внутреннее устройство игры: четырёхслойную модель (Data → Logic → Presentation → Persistence), дерево сцен с иерархией узлов, диаграммы классов и потоков данных. Ключевой элемент — секция паттернов проектирования, где каждый паттерн (Observer, Strategy, Singleton и др.) привязан к конкретному использованию в данном проекте. Это не абстрактная теория — ученик видит, как паттерн решает реальную задачу, и понимает, почему выбран именно он.

## Глава 3: Код и верификация

Заключительная глава — это пошаговая реализация: создание проекта, настройка структуры файлов, написание кода для каждого компонента с подробными комментариями. Каждый блок кода сопровождается чек-листом верификации — списком проверок, которые нужно выполнить, чтобы убедиться в корректности реализации. Для проектов с C++ (P4–P6) добавляются секции настройки среды сборки, создания GDExtension-биндингов и бенчмарков производительности.

# Проект 1: Кликер/Idle-игра

**Сложность:** ⭐ Начальная | **Язык:** GDScript | **Время:** 15–20 часов

Первый проект знакомит с фундаментальными концепциями GDScript и Godot Engine на примере создания кликер/idle-игры. Это идеальный стартовый проект: он достаточно прост для начинающих, но при этом охватывает все основные подсистемы, которые встретятся в любой игре — от обработки ввода до сохранения прогресса. Вы научитесь работать с переменными и типами данных, создавать функции с явной типизацией, использовать сигналы для слабой связанности компонентов, настраивать таймеры и обрабатывать пользовательский интерфейс через контейнеры компоновки.

**Структура проекта:**
- **Глава 1: Геймдизайн** — концепция «От одного клика до империи», экономика с экспоненциальным ростом, система достижений, оффлайн-прогресс, визуальный стиль
- **Глава 2: Архитектура** — 4-слойная модель (Data → Logic → Presentation → Persistence), диаграмма классов GameManager, поток данных клика и покупки, паттерны Observer/Strategy/Delegation/Singleton/Factory/Data-View
- **Глава 3: Код** — создание проекта, настройка Autoload, полная реализация GameManager, SaveManager, UI

**Микровызовы:** Критический удар (🟢), Экспорт сохранений (🟢), Система престижа (🟡), Менеджер автокликеров (🟡), Экран статистики с графиком (🔴)

**Спринт:** «Свой кликер» — 3 типа апгрейдов + престиж-система + настройки

**Мост к P2:** Сигналы → подсистемы оружия/врагов; PackedScene → снаряды/взрывы; Timer → кулдаун оружия; Resource → конфигурация оружия/врагов/уровней

# Проект 2: Космический шутер

**Сложность:** ⭐⭐ Начально-средняя | **Язык:** GDScript | **Время:** 20–25 часов

Второй проект значительно углубляет знания GDScript, вводя физические взаимодействия, оптимизацию и визуальные эффекты. Вы создадите динамичный космический шутер с системой оружия, различными типами врагов, босс-файтами и эффектами частиц. Ключевой концепцией этого проекта является паттерн Object Pool — техника оптимизации, без которой невозможна ни одна экшен-игра с большим количеством создаваемых и уничтожаемых объектов.

**Структура проекта:**
- **Глава 1: Геймдизайн** — 6 типов оружия, 5 типов врагов, система волн, босс «Тёмная Звезда» с фазами, система комбо и бонусов
- **Глава 2: Архитектура** — 4 слоя + Audio-слой, слои столкновений (collision layers/masks), паттерны Object Pool/Template Method/State (фазы босса)
- **Глава 3: Код** — настройка слоёв столкновений, реализация ObjectPool, WaveManager, AudioManager, полная боевая система

**Микровызовы:** Авто-прицеливание (🟢), Система достижений (🟡), Кооперативный режим (🔴)

**Спринт:** «Свой шутер» — Ракетница + Камикадзе/Телепортер + мини-босс

**Мост к P3:** CharacterBody2D → платформерная физика; Сигналы → FSM персонажа; PackedScene → предметы/способности; Resource → данные уровней/предметов; Object Pool → снаряды Tower Defense; наследование сцен → вариации врагов/предметов

→ [Полный документ проекта](./project-2-space-shooter.md)

# Проект 3: Метроидвания

**Сложность:** ⭐⭐⭐ Средняя | **Язык:** GDScript | **Время:** 40–60 часов

Третий проект — это вершина 2D-разработки на GDScript. Метроидвания объединяет платформинг, исследование, боёвку и систему способностей, требуя сложной архитектуры с конечными автоматами, деревьями анимаций и сохранением состояния целого мира. Это самый архитектурно сложный 2D-проект курса, который подготовит вас к переходу на C++ в следующем проекте.

**Структура проекта:**
- **Глава 1: Геймдизайн** — мир из 13 комнат в 4 биомах, 4 разблокируемых способности, боевая система Hitbox/Hurtbox, босс с 3 фазами
- **Глава 2: Архитектура** — 9-состоянийный FSM персонажа, AnimationNodeStateMachine, 5 глобальных менеджеров (Autoload), инвентарь и диалоги, сериализация мира
- **Глава 3: Код** — реализация State Machine, AbilityManager, SceneManager, SaveManager, боевой системы

**Микровызовы:** Wall Slide (🟢), Система комбо-атак (🟡), Процедурная генерация комнат (🔴)

**Спринт:** «Свая Метроидвания» — Двойной прыжок + комната-головоломка + мини-босс

**🌉 Мост к P4:** FSM → WaveManager в TD; инвентарь → экономика TD; сохранение мира → сериализация состояния; Autoload-менеджеры → гибридная архитектура GDScript/C++. **Прорыв:** переход на C++ через GDExtension

→ [Полный документ проекта](./project-3-metroidvania.md)

# Проект 4: Tower Defense

**Сложность:** ⭐⭐⭐⭐ Средне-продвинутая | **Язык:** GDScript + C++ | **Время:** 35–50 часов

Четвёртый проект — поворотная точка курса. Здесь мы начинаем переход от чистого GDScript к C++ через GDExtension. Tower Defense — идеальный жанр для этого перехода: игра имеет чётко выделенные системы, где производительность C++ оправдана (pathfinding для сотен юнитов, симуляция снарядов), и системы, где GDScript остаётся лучшим выбором (UI, поток игры). Вы научитесь создавать гибридные проекты, грамотно разделяя код между языками. Бенчмарки показывают: C++ pathfinding работает в 26 раз быстрее GDScript.

**Структура проекта:**
- **Глава 1: Геймдизайн** — 4 типа башен (Gun/Splash/Slow/Laser), 3 стратегии выбора цели, 15 волн, экономика, карта с NavigationRegion2D
- **Глава 2: Архитектура** — гибридная GDScript/C++ архитектура, паттерны Strategy (TargetStrategy), Factory (TowerRegistry), Data-View (TowerData vs Tower)
- **Глава 3: Код** — настройка SCons и GDExtension, реализация PathFinder на C++ (A*), ProjectileSimulator, бенчмарки

**Микровызовы:** Апгрейды башен (🟢), Система элементов (🟡), Динамический поиск пути на C++ (🔴)

**Спринт:** «Свой TD» — Замедляющая башня + два пути + бесконечный режим

**🌉 Мост к P5:** C++/GDExtension → C++ как основной язык; бенчмарки → Tracy Profiler; Strategy → AI FSM; Data-driven → ItemData/QuestData; Navigation2D → NavigationRegion3D. **Прорыв:** переход в 3D

→ [Полный документ проекта](./project-4-tower-defense.md)

# Проект 5: 3D Приключение

**Сложность:** ⭐⭐⭐⭐⭐ Продвинутая | **Язык:** C++ (GDExtension) + GDScript | **Время:** 50–70 часов

Пятый проект — это первый полностью 3D-проект курса, где C++/GDExtension играет основную роль с самого начала (в отличие от P4, где C++ добавлялся к существующему GDScript). Переход от 2D к 3D приносит новые вызовы: трёхмерные трансформации, камеры с коллизиями, навигация в 3D-пространстве, объёмное освещение. C++ критически важен для 3D-игр, потому что обработка 3D-физики, ИИ и боевой системы требует значительно больше вычислений.

**Структура проекта:**
- **Глава 1: Геймдизайн** — 5 зон с 15 областями, стамина-боёвка, 6-состоянийный NPC AI, диалоги с ветвлением, система квестов (5 основных + 8 побочных), цикл дня/ночи
- **Глава 2: Архитектура** — C++ как первичный язык, FSM для NPC на C++, ItemFactory, CombatController с комбо-цепочками, SpringArm3D-камера
- **Глава 3: Код** — C++ контроллеры (PlayerController, NPCController, QuestSystem), GDScript для UI и данных, 3D Hitbox3D/Hurtbox3D

**Микровызовы:** Парирование (🟢), Крафт зелий (🟡), Динамическая погода (🔴)

**Спринт:** «Свой квест» — Новая зона + NPC с квестом + предмет-способность

**🌉 Мост к P6:** C++ для 3D → основа ECS; 3D-рендеринг → MultiMesh; FSM для AI → boids-алгоритм; C++ HashMap → ECS-компоненты. **Прорыв:** экстремальная оптимизация (ECS + Data Locality даёт 20-кратное ускорение по сравнению с наивным C++)

→ [Полный документ проекта](./project-5-3d-adventure.md)

# Проект 6: Демо производительности

**Сложность:** ⭐⭐⭐⭐⭐+ Экспертная | **Язык:** C++ | **Время:** 40–60 часов

Заключительный проект курса — это демонстрация экстремальной оптимизации. Цель: рендерить 10 000+ сущностей на 60 FPS. Мы объединим все продвинутые техники C++: ECS-архитектуру, многопоточность, compute-шейдеры, MultiMesh для инстансированного рендеринга, пулы памяти и прямой доступ к RenderingServer. Прогрессия оптимизации измерима на каждом шаге: от 2 FPS (наивный GDScript) до 238 FPS (полная оптимизация) — общее ускорение в 119 раз. Это не просто учебный проект — это портфолио-демонстрация, которая покажет работодателям вашу способность решать реальные проблемы производительности.

**Структура проекта:**
- **Глава 1: Геймдизайн** — симуляция поля боя, целевые метрики и бюджет кадра, ECS-архетипы сущностей, boids-система, спектр оптимизаций
- **Глава 2: Архитектура** — ECS (Entity=ID, Component=data, System=logic), SoA вместо AoS, Job-система, Double Buffer для GPU↔CPU, паттерны Flyweight/Object Pool
- **Глава 3: Код** — ECS Registry и ComponentPool, compute-шейдеры через RenderingDevice, MultiMesh, кастомные аллокаторы, frustum culling + LOD

**Микровызовы:** Spatial Hash на C++ (🟢), LOD Threshold (🟢), GPU→CPU Feedback (🟡), Custom Memory Tracker (🟡), 40K Challenge (🔴)

**Спринт:** «Свой бенчмарк» — Рой (Swarm) + CPU vs GPU + отчёт

**Итоги курса:** Обобщение всех 6 проектов, рекомендации по дальнейшему развитию, ссылки на продвинутые темы

# Паттерны проектирования по проектам

Одна из ключевых особенностей курса — систематическое введение паттернов проектирования, где каждый паттерн впервые появляется в контексте конкретной задачи, а затем эволюционирует в последующих проектах. Ниже представлена сводная таблица, показывающая, где и как каждый паттерн применяется.

| Паттерн | P1 | P2 | P3 | P4 | P5 | P6 |
| --- | --- | --- | --- | --- | --- | --- |
| **Observer** | currency_changed, stats_updated | died, wave_started | health_changed, ability_unlocked | balance_changed, enemy_died | quest_state_changed | (встроен в ECS-системы) |
| **Strategy** | UpgradeType + match | WeaponData конфигурации | — | TargetStrategy (First/Last/Strongest) | Комбо-цепочки по оружию | BoidComponent веса по типу |
| **Singleton** | GameManager, SaveManager | +WaveManager, ObjectPool, AudioManager | +AbilityManager, InventoryManager, SceneManager | +EconomyManager, PathManager, TowerRegistry | C++ контроллеры + GDScript менеджеры | (заменён ECSWorld) |
| **Factory** | PackedScene.instantiate() | ObjectPool.get_instance() | — | TowerRegistry + PackedScene | ItemFactory, EnemySpawner | Registry.create() + emplace<T>() |
| **Delegation** | purchase_callback (Callable) | — | — | take_damage() делегация | — | — |
| **Data-View** | UpgradeData vs UpgradeItem | WeaponData/WaveData vs UI | ItemData vs InventoryUI | TowerData vs Tower | Все данные как Resource | Component vs System |
| **State / FSM** | — | Фазы босса (enum + match) | 9-состоянийный FSM персонажа | WaveManager FSM (Idle/Spawning/Active) | 6-состоянийный NPC AI на C++ | (заменён ECS Systems) |
| **Object Pool** | — | Ядро: пули, враги, эффекты | — | — | — | ECS entity pool (50K pre-allocated) |
| **Template Method** | — | enemy_base + move_behavior() | — | — | — | — |
| **Flyweight** | — | — | — | — | — | Shared BoidComponent (1 vs 5000) |
| **Double Buffer** | — | — | — | — | — | GPU↔CPU обмен данными |
| **ECS** | — | — | — | — | — | Основная архитектура |

**Наблюдения по прогрессии паттернов:**

Паттерн Observer — самый часто используемый в курсе: он появляется уже в P1 (сигналы Godot) и сопровождает ученика до P6. Singleton (Autoload) — второй по частоте, но в P6 он уступает место ECS-архитектуре, демонстрируя, что паттерны эволюционируют вместе с ростом сложности проекта. Стратегия (Strategy) — единственный паттерн, который присутствует в пяти из шести проектов, каждый раз в новом контексте: от выбора типа апгрейда в P1 до настройки весов boids в P6. Конечный автомат (FSM) появляется в P2 с простыми фазами босса, развивается в полноценную архитектуру в P3 (9 состояний персонажа) и P5 (6-состоянийный AI на C++), и в конечном итоге заменяется ECS-системами в P6 — важный урок о том, что паттерны не универсальны, а зависят от задачи.

**Примечание по GDExtension:** Начиная с проекта 4, курс активно использует GDExtension — механизм интеграции C++ кода в Godot. Для сборки C++ потребуется установить Python 3, SCons и C++ компилятор. Подробная инструкция по настройке среды содержится в главе 3 проекта 4. Проекты 1–3 не требуют C++ и могут быть выполнены с помощью только Godot Engine.

## Предполагаемые знания

Курс не требует предварительного опыта с Godot Engine или GDScript — мы начинаем с самых основ. Однако базовое понимание программирования (переменные, условия, циклы, функции) значительно ускорит прохождение. Если вы уже знакомы с Python, освоение GDScript пройдёт особенно быстро, учитывая сходство синтаксиса. Для проектов 4–6 желательно базовое знание C++ (классы, указатели, ссылки), хотя ключевые концепции объясняются по мере необходимости.

Рекомендуем выделять 1–2 часа в день или 5–8 часов на выходных. Не спешите переходить к следующему проекту, не экспериментировав с текущим: попробуйте добавить свои механики, изменить визуальный стиль, реализовать идеи из микровызовов. # Как пользоваться курсом

Каждый проект является отдельным документом, который можно изучать независимо. Однако для максимальной эффективности рекомендуем последовательное прохождение — проекты выстроены в единую траекторию, где каждый следующий опирается на навыки из предыдущего.

Каждый документ проекта содержит три главы: теоретические объяснения с примерами из реальной разработки (Глава 1: Геймдизайн), архитектурные решения с диаграммами классов и потоков данных (Глава 2: Архитектура), пошаговые инструкции по реализации с примерами кода и чек-листами верификации (Глава 3: Код). Кроме того, каждый проект включает микровызовы для самостоятельной работы, финальный спринт и мост к следующему проекту.
