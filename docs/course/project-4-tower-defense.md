# Проект 4: Tower Defense

| Курс разработки игр на Godot Engine | Часть 4 из 6 | Godot 4.x | GDScript → C++ |
| --- | --- | --- | --- |

## Введение

Tower Defense — это жанр, который идеально подходит для перехода от GDScript к C++/GDExtension. Почему? Потому что в этом жанре есть чётко выраженные подсистемы с различными требованиями к производительности. С одной стороны, пользовательский интерфейс, управление волнами и игровая логика не требуют сверхбыстрой обработки — им достаточно гибкости и удобства GDScript. С другой стороны, навигация десятков врагов по карте, симуляция сотен снарядов и расчёт путей — это именно те задачи, где C++ показывает свою силу, обеспечивая на порядок лучший результат.

В этом проекте мы создадим полноценную игру в жанре Tower Defense, начиная с чистого GDScript и постепенно перенося критичные к производительности подсистемы на C++ через механизм GDExtension. Этот подход — не просто учебное упражнение, а реальная практика, которую используют коммерческие проекты на Godot. Многие успешные игры применяют гибридную архитектуру: GDScript для прототипирования и UI, C++ для горячего кода. Мы пройдём весь путь от настройки среды сборки C++ до создания полностью функционального GDExtension-модуля.

Наш Tower Defense будет включать систему из 15 прогрессивных волн врагов, четыре типа башен с различными стратегиями атаки и тремя уровнями апгрейда, экономику с доходом от убийств и продажей башен, а также навигацию на основе NavigationRegion2D. По мере развития проекта мы выделим узкие места производительности, перенесём поиск пути и симуляцию снарядов на C++, и проведём бенчмарки, наглядно демонстрирующие преимущество скомпилированного кода. Этот проект — мост между удобным скриптингом и высокопроизводительным системным программированием.

### Цели обучения

1. Спроектировать data-driven архитектуру Tower Defense с ресурсами TowerData, EnemyData, WaveData и SpawnGroup
2. Реализовать систему из четырёх типов башен с различными механиками атаки: одиночная цель, область поражения, замедление, непрерывный урон
3. Создать три стратегии выбора цели (First, Last, Strongest) с паттерном Strategy
4. Построить менеджер волн на основе конечного автомата (FSM): Idle → Spawning → Active
5. Разработать экономическую систему с балансом доходов/расходов, продажей башен и бонусами за скорость
6. Освоить навигацию через NavigationRegion2D и NavigationAgent2D для движения врагов по маршруту
7. Настроить среду сборки C++ GDExtension: SCons, godot-cpp, файл .gdextension
8. Создать C++ классы PathFinder (A*) и ProjectileSimulator (пакетная обработка)
9. Провести бенчмарки GDScript vs C++ и проанализировать результаты
10. Организовать архитектуру проекта по слоям: Data, Logic, Presentation, Persistence

### Оценка времени

**35–50 часов** — это амбициозный проект, который сочетает полноценную игру на GDScript с переносом подсистем на C++. Рекомендуется сначала завершить GDScript-часть, убедиться в работоспособности всех систем, и только потом переходить к GDExtension. Это позволяет изолировать проблемы: если что-то не работает после переноса на C++, вы знаете, что ошибка в C++-коде, а не в логике.

### Почему именно Tower Defense?

Tower Defense — идеальный жанр для изучения гибридной GDScript/C++ архитектуры по трём причинам. Во-первых, чёткое разделение на «горячий» и «холодный» код: навигация и симуляция снарядов — горячий код, который выполняется каждый кадр для десятков объектов; UI и менеджеры — холодный код, который работает с низкой частотой. Во-вторых, масштабируемость: легко увеличивать количество врагов и снарядов, чтобы увидеть, как GDScript начинает тормозить, а C++ продолжает работать плавно. В-третьих, data-driven дизайн: все параметры вынесены в ресурсы, что позволяет менять баланс без перекомпиляции C++-кода. Это реальный паттерн, который используют коммерческие проекты на Godot.

# Глава 1: Геймдизайн

## 1.1 Концепция и видение

**Жанр:** Tower Defense / Strategy

**Ключевая фантазия:** «Стратег, защищающий последний рубеж» — Игрок стоит на защите последнего укрепления от непрекращающихся орд врагов. Каждый выбор размещения башни имеет значение: неправильная позиция — и враги прорвутся; экономная игра — и не хватит огневой мощи; слишком агрессивная — и не останется золота на критические апгрейды. Каждая волна — это маленькая битва, каждый босс — настоящее испытание, а победа над финальной волной — заслуженный триумф стратегического мышления.

**Целевая длительность сессии:** 10–20 минут на одну карту. За это время игрок проходит 15 волн, размещает и улучшает башни, адаптирует стратегию к меняющемуся составу врагов и либо побеждает, либо проигрывает. Короткая сессия делает игру доступной для быстрого матча, а прогрессия волн обеспечивает достаточную глубину для вдумчивой игры.

**Почему TD идеален для изучения C++ интеграции:** Tower Defense создаёт естественную границу между кодом, который выгодно переносить на C++, и кодом, который лучше оставить на GDScript. Управление волнами, экономика и UI работают на низкой частоте (раз в секунду или по событиям) — GDScript справляется легко. Но навигация 50+ врагов, симуляция 100+ снарядов и поиск пути на сетке — это задачи, которые в GDScript вызывают падение FPS ниже 30, а в C++ выполняются за миллисекунды. Этот контраст делает урок о производительности наглядным и убедительным.

## 1.2 Основной игровой цикл

Основной цикл Tower Defense строится на петле «подготовка → защита → награда → усиление». Игрок размещает башни между волнами, переживает атаку врагов, получает золото за убийства и тратит его на новые башни или апгрейды. Каждый виток этого цикла наращивает мощь защиты, но и враги становятся сильнее. Баланс между доходами и расходами — ключевая стратегическая задача.

```
┌──────────────────────────────────────────────────────────────┐
│                    ИГРОВОЙ ЦИКЛ TOWER DEFENSE                 │
│                                                               │
│   ┌──────────┐     ┌──────────┐     ┌──────────┐            │
│   │ ПОДГОТОВКА│────▶│  ВОЛНА   │────▶│ НАГРАДА  │            │
│   │          │     │ ВРАГОВ   │     │          │            │
│   │ Ставим   │     │ Башни    │     │ Золото   │            │
│   │ башни    │     │ атакуют  │     │ за       │            │
│   │ Апгрейд  │     │ врагов   │     │ убийства │            │
│   │ Продажа  │     │ Враги    │     │ Бонус    │            │
│   │ Стратегия│     │ идут к   │     │ за       │            │
│   │          │     │ базе     │     │ скорость │            │
│   └──────────┘     └──────────┘     └────┬─────┘            │
│        ▲                                  │                   │
│        │          ┌──────────┐            │                   │
│        └──────────│ УСИЛЕНИЕ │◀───────────┘                   │
│                   │          │                                 │
│                   │ Новые    │                                 │
│                   │ башни    │                                 │
│                   │ Апгрейды │                                 │
│                   │ Больше   │                                 │
│                   │ огня     │                                 │
│                   └──────────┘                                 │
│                                                               │
│   Конец: Волна 15 пройдена = ПОБЕДА                          │
│          Жизни = 0 = ПОРАЖЕНИЕ                                │
└──────────────────────────────────────────────────────────────┘
```

**Краткосрочный цикл (секунды):** Установить башню → увидеть, как она атакует → наблюдать гибель врага → получить золото. Этот микроцикл должен происходить каждые 5–10 секунд, постоянно давая игроку обратную связь. Визуальные эффекты выстрелов, взрывов и летающих снарядов делают этот цикл удовлетворяющим. Числа урона и золотые монеты, выпадающие из врагов, — ключевая обратная связь.

**Среднесрочный цикл (минуты):** Цикл волн — подготовка между волнами (10 секунд или досрочно), переживание волны (30–60 секунд), получение бонуса за волну. Каждая волна — это мини-испытание с чётким началом и концом. Игрок может пропустить подготовку и начать волну раньше за бонусное золото — это добавляет риск/награду.

**Долгосрочный цикл (вся игра):** Прогрессия через 15 волн с нарастающей сложностью. Разблокировка типов башен по мере накопления золота. Каждые 5 волн — босс, требующий комбинированной защиты. Финальная волна 15 — кульминация, где игрок должен использовать все изученные стратегии. Победа над финальным боссом — это триумф планирования и адаптации.

## 1.3 Карта и путь врагов

Карта Tower Defense — это не просто фон, а ключевой элемент геймдизайна. Форма пути определяет, где выгодно ставить башни, а где враги будут уязвимы. Мы используем S-образный маршрут, который заставляет врагов проходить мимо одних и тех же точек дважды, создавая «горячие зоны» для размещения башен.

**Размер карты:** 1280×720 пикселей, размер тайла 64×64 (20×11.25 тайлов). Навигационная область рисуется именно по коридору маршрута, а не по всей карте, что гарантирует, что враги идут по предназначенному пути.

**S-образный маршрут** определяется следующими ключевыми точками (waypoints):

| Точка | Позиция (px) | Описание |
|---|---|---|
| Spawn | (64, 360) | Точка появления врагов, левый край карты |
| WP1 | (320, 360) | Первый поворот, начало подъёма |
| WP2 | (320, 128) | Верхний поворот, горизонтальный переход |
| WP3 | (640, 128) | Середина верхнего коридора |
| WP4 | (640, 592) | Спуск вниз, нижний поворот |
| WP5 | (960, 592) | Переход вправо по нижнему коридору |
| WP6 | (960, 360) | Подъём к базе |
| Base | (1216, 360) | База игрока, конечная точка |

Такой S-образный маршрут создаёт два «горячих угла» — зоны, где враги проходят близко друг к другу на разных участках пути: район WP2–WP3 (верхний коридор) и район WP4–WP5 (нижний коридор). Башни, размещённые в этих зонах, могут поражать врагов на обоих участках пути, что делает их стратегически ценными.

**20 слотов для башен** расположены вдоль пути на расстоянии 64–128 пикселей от центра маршрута. Слоты сгруппированы так, чтобы в «горячих зонах» было больше возможностей для размещения (4–5 слотов), а на прямых участках — меньше (2–3 слота). Это создаёт естественные «точки выбора» для игрока: инвестировать в горячие зоны или равномерно распределить защиту.

**NavigationRegion2D** используется для определения проходимой области. Навигационный полигон рисуется по коридору маршрута шириной 64 пикселя (один тайл). NavigationAgent2D прикрепляется к каждому врагу и вычисляет путь через эту область. Waypoints используются как резервная система: если навигация недоступна, враги двигаются от точки к точки по прямой.

## 1.4 Система башен

Система башен — сердце Tower Defense. Мы реализуем четыре типа башен, каждый из которых имеет уникальную механику и стратегическую ценность. Каждая башня описывается ресурсом TowerData, что позволяет настраивать параметры без изменения кода. Башни могут быть улучшены до 3 уровня, что увеличивает урон, дальность и стоимость.

### Характеристики башен

| Тип | Стоимость | Урон | Скорость атаки | DPS | Дальность | Особенность |
|---|---|---|---|---|---|---|
| Gun Tower | 100 | 15 | 1.0/сек | 15 | 150px | Одиночная цель, поворот к цели |
| Splash Tower | 200 | 25 | 0.5/сек | 12.5 | 130px | Радиус взрыва 80px, эффективна против групп |
| Slow Tower | 150 | 5 | 0.8/сек | 4 | 160px | Замедление 50% на 2 сек, поддерживающая |
| Laser Tower | 350 | 40/сек | непрерывный | 40 | 180px | Непрерывный луч, самая дорогая |

**Формула DPS:** `dps = damage × attack_speed`

Для лазерной башни: `dps = damage_per_second` (непрерывный урон, нет кулдауна)

**Эффективность по золоту:** `dps_per_gold = dps / cost`

| Тип | DPS | Стоимость | DPS/Золото | Примечание |
|---|---|---|---|---|
| Gun Tower | 15 | 100 | 0.150 | Лучшая чистая эффективность |
| Splash Tower | 12.5 | 200 | 0.063 | Но поражает несколько целей |
| Slow Tower | 4 | 150 | 0.027 | Поддерживающая, ценность в дебаффе |
| Laser Tower | 40 | 350 | 0.114 | Высокий DPS, но дорогая |

Взрывная башня при попадании по 3+ целям в радиусе 80px обеспечивает фактический DPS 37.5+ (12.5 × 3), что делает её более эффективной, чем Gun Tower, против групп. Замедляющая башня ценна не прямым уроном, а увеличением времени нахождения врагов в зоне поражения других башен: замедление 50% удваивает эффективный DPS всех башен в радиусе.

### Система апгрейдов

Каждая башня может быть улучшена 2 раза (3 уровня всего). Апгрейд увеличивает урон и дальность, но стоит дополнительных золота. Продажа возвращает 70% от всей вложенной суммы (базовая стоимость + апгрейды).

| Уровень | Множитель стоимости | Множитель урона | Бонус дальности | Пример: Gun Tower |
|---|---|---|---|---|
| 1 (базовый) | 1.0× (100g) | 1.0× (15) | +0px (150) | 100g, 15 DPS, 150px |
| 2 | 0.6× (60g) | 1.5× (22.5) | +15px (165) | 160g всего, 22.5 DPS |
| 3 | 0.78× (78g) | 2.0× (30) | +30px (180) | 238g всего, 30 DPS |

Формула стоимости апгрейда: `upgrade_cost = int(base_cost × upgrade_cost_multiplier × 1.3^level)`

Для Gun Tower: уровень 2 = `int(100 × 0.6 × 1.3^1) = 78g` (округлённо до 60g для раннего баланса), уровень 3 = `int(100 × 0.6 × 1.3^2) = 101g` (округлённо до 78g). Мы используем упрощённые значения для лучшей играбельности.

### Стратегии выбора цели

Каждая башня может переключать стратегию выбора цели, что добавляет тактическую глубину. Стратегия определяет, какого врага башня будет атаковать при наличии нескольких в радиусе.

| Стратегия | Логика | Когда использовать |
|---|---|---|
| **First** | Атакует врага, прошедшего наибольший путь (ближе всего к базе) | По умолчанию, предотвращает прорыв |
| **Last** | Атакует врага, прошедшего наименьший путь (только что появился) | Для замедляющих башен, чтобы «подхватить» новых врагов |
| **Strongest** | Атакует врага с наибольшим текущим HP | Для лазерных башен против боссов и танков |

Стратегия First — наиболее интуитивная и безопасная: башня атакует того, кто ближе всего к базе, предотвращая прорыв. Стратегия Last полезна для замедляющих башен: замедляя только что появившихся врагов, мы даём другим башням больше времени на атаку. Стратегия Strongest оптимальна для лазерных башен, чей непрерывный урон эффективнее против единичной толстой цели, чем против группы слабых.

## 1.5 Система врагов

Враги — это вызов, который должен быть преодолён. Каждый тип врага требует своей контр-стратегии, и смешанный состав волн заставляет игрока комбинировать типы башен. Враги описываются ресурсом EnemyData, что позволяет легко добавлять новые типы.

### Характеристики врагов

| Тип | HP | Скорость | Награда | Поведение |
|---|---|---|---|---|
| Базовый | 50 | 80 px/s | 15g | Идёт по пути, стандартная цель |
| Быстрый | 30 | 160 px/s | 10g | Быстрый, частичная устойчивость к замедлению (30%) |
| Танк | 200 | 50 px/s | 40g | Медленный, много HP, приоритет для лазера |
| Босс | 800 | 60 px/s | 150g | Появляется каждые 5 волн, огромный HP |

### Анализ характеристик

**HP за золото:** `hp_per_gold = max_health / gold_reward`

| Тип | HP | Награда | HP/Золото | Время до базы* |
|---|---|---|---|---|
| Базовый | 50 | 15g | 3.33 | ~12 сек |
| Быстрый | 30 | 10g | 3.00 | ~6 сек |
| Танк | 200 | 40g | 5.00 | ~19 сек |
| Босс | 800 | 150g | 5.33 | ~16 сек |

*Время до базы рассчитано для маршрута длиной ~960px (от спавна до базы через S-образный путь).

**Ключевые наблюдения:**
- Быстрый враг добирается до базы за 6 секунд — у игрока мало времени на реакцию. Две Gun Tower с DPS 15 каждая нанесут 180 урона за 6 секунд, что достаточно для убийства (30 HP).
- Танк с 200 HP требует длительного огня: одна Gun Tower убьёт его за 200/15 = 13.3 секунды, но он дойдёт до базы за 19 секунд, так что одна башня справится, но едва. Лучше комбинировать с замедлением.
- Босс с 800 HP требует согласованного огня нескольких башен. Лазерная башня (40 DPS) + Gun Tower (15 DPS) + Splash Tower (12.5 DPS) = 67.5 DPS. Время убийства: 800/67.5 = 11.8 сек. Босс дойдёт до базы за 16 сек, так что запас есть, но нужен замедляющая башня для безопасности.

## 1.6 Система волн

Система волн определяет ритм и сложность игры. Каждая волна описывается ресурсом WaveData с массивом SpawnGroup. Прогрессия волн обеспечивает плавное нарастание сложности: сначала базовые враги для обучения, затем смешанные группы, требующие разных стратегий, и наконец боссы, проверяющие все навыки игрока.

## 1.7 Экономика и баланс

Экономика Tower Defense — это тонкий баланс между доходами и расходами. Игрок начинает с фиксированным количеством золота, достаточным для покупки двух-трёх базовых башен. Убийство врагов приносит золото, причём быстрые враги дают меньше, а танки — больше. Продажа башни возвращает 70% от всей вложенной стоимости — это позволяет корректировать стратегию, но наказывает за ошибочные решения.

### Стартовые параметры

| Параметр | Значение | Описание |
|---|---|---|
| Стартовое золото | 200g | Достаточно для 2 Gun Tower или 1 Splash + экономия |
| Жизни | 20 | Базовый враг отнимает 1, босс — 1 |
| Коэффициент продажи | 70% | Возврат от суммы всех вложений |
| Бонус за скорость | 20–100g | За досрочный запуск волны |

### Формулы экономики

**Доход за волну:** `wave_income = Σ(enemy_reward × count) + speed_bonus`

**Стоимость продажи:** `sell_value = total_invested × 0.7`, где `total_invested = base_cost + upgrade_1_cost + upgrade_2_cost`

**Чистый прирост за волну:** `net_gain = wave_income - tower_purchases - upgrade_costs`

## 1.9 Микровызовы

Микровызовы — это дополнительные задания, которые расширяют базовый проект. Каждый вызов помечен уровнем сложности и может быть реализован независимо от других. Рекомендуется сначала завершить базовый проект и убедиться в работоспособности всех систем, прежде чем браться за микровызовы.

| Уровень | Вызов | Описание |
|---|---|---|
| 🟢 Лёгкий | Апгрейды башен | Добавить систему 3 уровней апгрейда для каждой башни с увеличением урона (1.5×, 2.0×), дальности (+15px, +30px) и стоимости. Апгрейд выполняется кликом по установленной башне. Это расширение базового проекта, которое углубляет стратегический выбор: купить новую башню или улучшить существующую? |
| 🟡 Средний | Система элементов | 4 типа элементального урона (огонь, лёд, молния, яд) с взаимодействиями: лёд + огонь = пар (доп. урон по области), яд + огонь = усиленный яд (x2 длительность), молния + вода = цепная молния (прыжок к 2 соседним врагам). Каждый тип башни привязан к элементу, а комбинации создают синергетические эффекты. Требует расширения TowerData и добавления системы дебаффов на врагах. |
| 🔴 Сложный | Динамический поиск пути | Враги пересчитывают путь при установке/продаже башни, реализуя полноценный A* на C++. Если игрок перегораживает путь башнями, враги ищут обход. Если обхода нет — враги атакуют ближайшую башню. Это кардинально меняет геймплей: игрок должен оставлять коридоры, а не застраивать всё башнями. Требует PathFinder на C++ с интеграцией в NavigationRegion2D и обработкой тупиков. |

# Глава 2: Архитектура

## 2.1 Обзор архитектуры (4 слоя)

Архитектура Tower Defense строится на четырёх слоях, каждый из которых имеет чёткую зону ответственности. Такое разделение обеспечивает слабую связанность между системами и позволяет изменять один слой без каскадных изменений в остальных. Это особенно важно для Tower Defense, где количество параллельно работающих подсистем (башни атакуют, враги идут, снаряды летят, волны спавнятся) значительно выше, чем в большинстве других жанров.

**Data Layer (Слой данных):** TowerData, EnemyData, WaveData, SpawnGroup — все наследуют Resource и используют @export vars для настройки в редакторе. Никакой логики, только данные. TowerData хранит стоимость, урон, скорость атаки, дальность, радиус взрыва, фактор замедления и сцену снаряда. EnemyData хранит HP, скорость, награду, устойчивость к замедлению и сцену врага. WaveData хранит массив SpawnGroup, задержку старта и бонус за скорость. SpawnGroup связывает EnemyData с количеством и интервалом спавна.

**Logic Layer (Слой логики):** Глобальные менеджеры, управляющие игровыми системами через Autoload. GameManager (состояние игры, пауза, жизни, game over), WaveManager (FSM: Idle → Spawning → Active, управление очередью спавна), EconomyManager (баланс, доходы, расходы, продажа), PathManager (waypoints, NavigationRegion2D), AudioManager (SFX каналы, BGM), TowerRegistry (реестр определений башен для фабрики). Все менеджеры общаются через сигналы, обеспечивая слабую связанность.

**Presentation Layer (Слой представления):** Main, GameMap, Tower scenes, Enemy scenes, Projectile scenes, HUD, TowerShop — все визуальные компоненты. Этот слой отображает данные из Data Layer и реагирует на сигналы из Logic Layer, но не содержит бизнес-логики. HUD обновляет полоску золота, когда получает сигнал balance_changed, но не вычисляет доход самостоятельно. TowerShop показывает доступные башни на основе TowerRegistry, но не решает, может ли игрок позволить себе покупку — это делает EconomyManager.

**Persistence Layer (Слой хранения):** SaveManager (Autoload) — сериализует состояние игры в JSON, десериализует при загрузке. Каждый менеджер предоставляет методы get_save_data() и load_save_data(), а SaveManager координирует процесс сохранения/загрузки, собирая данные от всех менеджеров в единую структуру.

## 2.3 Диаграмма классов

Диаграмма классов показывает отношения между основными типами проекта. Автозагрузчики (Autoload) обеспечивают глобальный доступ к менеджерам, а сигналы — слабую связанность между ними. Data-ресурсы не содержат логики и используются менеджерами и компонентами представления. Стрелки показывают направления зависимостей: менеджеры зависят от данных, представление зависит от менеджеров, но менеджеры не зависят от представления.

## 2.5 Паттерны проектирования

Tower Defense — это жанр, который естественно реализует множество классических паттернов проектирования. Каждый паттерн решает конкретную проблему архитектуры, и понимание этих паттернов поможет вам не только в этом проекте, но и в будущих играх.

| Паттерн | Где применён | Зачем |
|---|---|---|
| Observer (Сигналы) | balance_changed, wave_started, enemy_died, game_over, lives_changed | Слабая связанность между системами. EconomyManager не знает о HUD, но HUD реагирует на изменение баланса через сигнал. |
| Strategy | TargetStrategy (First, Last, Strongest) в Tower._find_target() | Разные алгоритмы выбора цели без создания подклассов башни. Башня делегирует выбор цели стратегии, определённой в TowerData. |
| State (FSM) | WaveManager: Idle → Spawning → Active | Управление фазами волны. Каждое состояние имеет свою логику обновления, и переходы между состояниями чётко определены. |
| Singleton (Autoload) | GameManager, WaveManager, EconomyManager, PathManager, AudioManager, TowerRegistry, SaveManager | Глобальный доступ к подсистемам без передачи ссылок через дерево сцен. Все менеджеры доступны из любого скрипта. |
| Factory | TowerRegistry + PackedScene | Создание башен по типу без switch/if-else. TowerRegistry.get_tower_data(key) возвращает TowerData с PackedScene, которая инстанцируется. |
| Data-View separation | TowerData (Resource) vs Tower (Node2D) | Данные отделены от отображения. TowerData хранит параметры, Tower визуализирует и управляет поведением. Изменение данных не требует изменения кода. |
| Delegation | Projectile делегирует урон цели через target.take_damage() | Снаряд не знает, как враг получает урон — он просто вызывает метод. Это позволяет менять логику урона в одном месте. |

# Глава 3: Код и верификация

## 3.1 Data Layer — ресурсы данных

Data Layer содержит ресурсы, описывающие игровые объекты без какой-либо логики. Все ресурсы наследуют Resource и используют @export для настройки в инспекторе редактора. Это позволяет гейм-дизайнеру менять баланс, не трогая код, а программисту — ссылаться на типизированные данные вместо магических чисел. Каждый ресурс предоставляет вычисляемые свойства (например, get_dps()), которые инкапсулируют формулы.

### resources/tower_data.gd

Ресурс TowerData описывает все параметры одного типа башни. Конкретные башни (Gun, Splash, Slow, Laser) отличаются только значениями в этом ресурсе, а не кодом. Методы get_dps(), get_upgrade_cost(), get_damage_at_level() и get_range_at_level() инкапсулируют формулы баланса, чтобы код башни не содержал вычислений.

```gdscript
class_name TowerData
extends Resource

@export var tower_name: String = "Gun Tower"
@export var tower_scene: PackedScene
@export var projectile_scene: PackedScene
@export var cost: int = 100
@export var damage: float = 15.0
@export var attack_speed: float = 1.0  # атак в секунду
@export var attack_range: float = 150.0
@export var target_strategy: StringName = &"first"
@export var splash_radius: float = 0.0  # 0 = одиночная цель
@export var slow_factor: float = 1.0  # 1.0 = без замедления, 0.5 = 50% замедление
@export var slow_duration: float = 0.0  # секунды действия замедления
@export var projectile_speed: float = 300.0
@export var upgrade_cost_multiplier: float = 0.6
@export var upgrade_damage_multiplier: float = 1.5
@export var upgrade_range_bonus: float = 15.0
@export var icon: Texture2D
@export var description: String = ""


func get_dps() -> float:
        return damage * attack_speed


func get_upgrade_cost(current_level: int) -> int:
        if current_level <= 0:
                return cost
        var multiplier := upgrade_cost_multiplier
        for i in range(current_level):
                multiplier *= 1.3
        return int(cost * multiplier)


func get_damage_at_level(level: int) -> float:
        return damage * pow(upgrade_damage_multiplier, level)


func get_range_at_level(level: int) -> float:
        return attack_range + upgrade_range_bonus * level
```

### resources/enemy_data.gd

Ресурс EnemyData описывает все параметры одного типа врага. Метод get_health_per_gold() используется для анализа баланса: чем выше HP за золото, тем «дороже» враг для игрока. slow_resistance определяет, насколько враг устойчив к замедлению: 0 = полностью подвержен, 1 = полностью иммунен.

```gdscript
class_name EnemyData
extends Resource

@export var enemy_name: String = "Basic Enemy"
@export var enemy_scene: PackedScene
@export var max_health: float = 50.0
@export var move_speed: float = 80.0
@export var gold_reward: int = 15
@export var lives_cost: int = 1  # сколько жизней теряет игрок при достижении базы
@export var is_boss: bool = false
@export var slow_resistance: float = 0.0  # 0 = полностью подвержен, 1 = иммунен
@export var sprite_color: Color = Color.RED
@export var scale: float = 1.0


func get_health_per_gold() -> float:
        if gold_reward <= 0:
                return 0.0
        return max_health / float(gold_reward)
```

### resources/wave_data.gd

Ресурс WaveData описывает одну волну врагов. Массив spawn_groups определяет, какие враги и в каком количестве появляются. Методы get_total_enemies() и get_total_gold() используются WaveManager для отображения информации о волне и расчёта дохода.

```gdscript
class_name WaveData
extends Resource

@export var wave_number: int = 1
@export var spawn_groups: Array[SpawnGroup] = []
@export var start_delay: float = 5.0
@export var speed_bonus: int = 20


func get_total_enemies() -> int:
        var total := 0
        for group in spawn_groups:
                total += group.count
        return total


func get_total_gold() -> int:
        var total := 0
        for group in spawn_groups:
                if group.enemy_data:
                        total += group.enemy_data.gold_reward * group.count
        return total
```

### resources/spawn_group.gd

Ресурс SpawnGroup описывает одну группу врагов внутри волны. interval задаёт секунды между спавнами, а delay_after — паузу после последнего врага группы перед следующей группой.

```gdscript
class_name SpawnGroup
extends Resource

@export var enemy_data: EnemyData
@export var count: int = 5
@export var interval: float = 1.0  # секунд между спавнами
@export var delay_after: float = 2.0  # пауза после последнего врага группы
```

## 3.2 Logic Layer — глобальные менеджеры

Logic Layer содержит глобальные менеджеры, реализованные как Autoload. Каждый менеджер отвечает за свою подсистему и общается с другими через сигналы. Это обеспечивает слабую связанность: например, EconomyManager не знает о HUD, но HUD подписан на сигнал balance_changed и обновляет отображение при изменении баланса.

### scripts/game_manager.gd (Autoload)

GameManager управляет глобальным состоянием игры: жизни, пауза, поражение. Сигналы lives_changed и game_over используются другими системами для реагирования на изменения. Метод toggle_pause() переключает паузу через get_tree().paused, а process_mode = PROCESS_MODE_ALWAYS позволяет менеджеру работать даже в паузе.


### scripts/wave_manager.gd (Autoload)

WaveManager реализован как конечный автомат с тремя состояниями: Idle (ожидание между волнами), Spawning (спавн врагов текущей волны) и Active (все враги заспавнены, ожидание уничтожения). Переходы управляются таймерами и событиями. Метод request_skip() позволяет игроку досрочно запустить следующую волну за бонусное золото.

```gdscript
extends Node

signal wave_started(wave_number: int)
signal wave_completed(wave_number: int)
signal all_waves_completed()

enum State { IDLE, SPAWNING, ACTIVE }

var current_state: State = State.IDLE
var current_wave: int = 0
var max_waves: int = 15
var idle_timer: float = 0.0
var skip_requested: bool = false
var spawn_queue: Array[Dictionary] = []
var spawn_timer: float = 0.0
var wave_data_array: Array[WaveData] = []


func _ready() -> void:
        _load_wave_data()


func _load_wave_data() -> void:
        wave_data_array.clear()
        for i in range(1, max_waves + 1):
                var path := "res://resources/wave_%02d_data.tres" % i
                if ResourceLoader.exists(path):
                        var data := load(path) as WaveData
                        if data:
                                wave_data_array.append(data)


func _physics_process(delta: float) -> void:
        match current_state:
                State.IDLE:
                        idle_timer -= delta
                        if idle_timer <= 0.0 or skip_requested:
                                skip_requested = false
                                _start_wave()
                State.SPAWNING:
                        _process_spawn_queue(delta)
                State.ACTIVE:
                        if get_tree().get_nodes_in_group("enemies").is_empty():
                                _wave_completed()


func request_skip() -> void:
        if current_state == State.IDLE:
                skip_requested = true


func _start_wave() -> void:
        current_wave += 1
        if current_wave > max_waves:
                all_waves_completed.emit()
                current_state = State.IDLE
                return

        if current_wave > wave_data_array.size():
                current_state = State.IDLE
                return

        var wave: WaveData = wave_data_array[current_wave - 1]
        wave_started.emit(current_wave)
        GameManager.current_wave = current_wave

        _build_spawn_queue(wave)
        current_state = State.SPAWNING


func _build_spawn_queue(wave: WaveData) -> void:
        spawn_queue.clear()
        for group in wave.spawn_groups:
                for i in range(group.count):
                        spawn_queue.append({
                                "enemy_data": group.enemy_data,
                                "interval": group.interval,
                                "delay_after": group.delay_after if i == group.count - 1 else 0.0,
                        })
        spawn_timer = wave.start_delay


func _process_spawn_queue(delta: float) -> void:
        if spawn_queue.is_empty():
                current_state = State.ACTIVE
                return

        spawn_timer -= delta
        if spawn_timer <= 0.0:
                var entry: Dictionary = spawn_queue.pop_front()
                var data: EnemyData = entry["enemy_data"]
                _spawn_enemy(data)
                spawn_timer = entry["interval"]
                if entry["delay_after"] > 0.0:
                        spawn_timer += entry["delay_after"]


func _spawn_enemy(data: EnemyData) -> void:
        if not data or not data.enemy_scene:
                return
        var enemy: CharacterBody2D = data.enemy_scene.instantiate()
        var spawn_point: Marker2D = get_tree().get_first_node_in_group("spawn_point") as Marker2D
        var base_point: Marker2D = get_tree().get_first_node_in_group("base_point") as Marker2D

        if spawn_point:
                enemy.global_position = spawn_point.global_position
        if base_point and enemy.has_node("NavigationAgent2D"):
                var nav: NavigationAgent2D = enemy.get_node("NavigationAgent2D")
                nav.target_position = base_point.global_position

        enemy.add_to_group("enemies")
        var enemies_container := get_tree().get_first_node_in_group("enemies_container")
        if enemies_container:
                enemies_container.add_child(enemy)
        else:
                get_tree().current_scene.add_child(enemy)


func _wave_completed() -> void:
        wave_completed.emit(current_wave)
        EconomyManager.earn(wave_data_array[current_wave - 1].speed_bonus)
        current_state = State.IDLE
        idle_timer = 10.0  # секунд между волнами


func get_save_data() -> Dictionary:
        return {
                "current_wave": current_wave,
                "current_state": current_state,
        }


func load_save_data(data: Dictionary) -> void:
        current_wave = data.get("current_wave", 0)
        current_state = State.IDLE
```

### scripts/audio_manager.gd (Autoload)

AudioManager управляет звуковыми эффектами и фоновой музыкой. Использует пул из 8 AudioStreamPlayer для одновременного воспроизведения нескольких SFX. Если все каналы заняты, первый канал прерывается для воспроизведения нового звука. BGM воспроизводится через отдельный AudioStreamPlayer.

## 3.3 Presentation Layer — сцены и компоненты

Presentation Layer содержит визуальные компоненты, которые отображают данные из Data Layer и реагируют на сигналы из Logic Layer. Важно, что эти компоненты не содержат бизнес-логики: башня не решает, может ли игрок позволить себе покупку — это делает EconomyManager. Башня только получает данные и визуализирует атаку.

### scripts/tower.gd

Скрипт башни — один из самых сложных в проекте. Он управляет обнаружением врагов через Area2D, выбором цели по стратегии, атакой с созданием снарядов и визуализацией дальности. Ключевой момент: башня не создаёт снаряды напрямую в контейнере через хрупкую ссылку `get_parent().get_node("Projectiles")`, а использует группу "projectiles_container" для поиска контейнера.

```gdscript
extends Node2D

@export var tower_data: TowerData
@export var level: int = 0

var enemies_in_range: Array[CharacterBody2D] = []
var current_target: CharacterBody2D = null
var attack_timer: float = 0.0
var show_range: bool = false
var total_invested: int = 0

@onready var muzzle: Marker2D = %Muzzle
@onready var range_area: Area2D = %RangeArea
@onready var attack_cooldown: Timer = %AttackCooldown
@onready var turret_pivot: Node2D = %TurretPivot


func _ready() -> void:
        if tower_data:
                total_invested = tower_data.cost
                _setup_range()
        range_area.body_entered.connect(_on_range_entered)
        range_area.body_exited.connect(_on_range_exited)


func _setup_range() -> void:
        var shape := range_area.get_node("CollisionShape2D").shape as CircleShape2D
        if shape:
                shape.radius = tower_data.get_range_at_level(level)


func _physics_process(delta: float) -> void:
        if not tower_data:
                return
        attack_timer -= delta
        _find_target()
        if current_target:
                _rotate_turret_toward(current_target.global_position)
                if attack_timer <= 0.0:
                        _attack()
                        attack_timer = 1.0 / tower_data.attack_speed


func _on_range_entered(body: Node2D) -> void:
        if body.is_in_group("enemies") and body is CharacterBody2D:
                if not enemies_in_range.has(body):
                        enemies_in_range.append(body)


func _on_range_exited(body: Node2D) -> void:
        if body in enemies_in_range:
                enemies_in_range.erase(body)
                if body == current_target:
                        current_target = null


func _find_target() -> void:
        _clean_dead_enemies()
        if enemies_in_range.is_empty():
                current_target = null
                return
        match tower_data.target_strategy:
                &"first":
                        current_target = _target_first()
                &"last":
                        current_target = _target_last()
                &"strongest":
                        current_target = _target_strongest()
                _:
                        current_target = _target_first()


func _clean_dead_enemies() -> void:
        var to_remove: Array[CharacterBody2D] = []
        for e in enemies_in_range:
                if not is_instance_valid(e) or e.is_queued_for_deletion():
                        to_remove.append(e)
        for e in to_remove:
                enemies_in_range.erase(e)


func _target_first() -> CharacterBody2D:
        var best: CharacterBody2D = null
        var best_progress: float = -1.0
        for e in enemies_in_range:
                if e.has_method("get_path_progress") and e.get_path_progress() > best_progress:
                        best_progress = e.get_path_progress()
                        best = e
        return best


func _target_last() -> CharacterBody2D:
        var best: CharacterBody2D = null
        var best_progress: float = INF
        for e in enemies_in_range:
                if e.has_method("get_path_progress") and e.get_path_progress() < best_progress:
                        best_progress = e.get_path_progress()
                        best = e
        return best


func _target_strongest() -> CharacterBody2D:
        var best: CharacterBody2D = null
        var best_hp: float = -1.0
        for e in enemies_in_range:
                if e.has_method("get_current_health") and e.get_current_health() > best_hp:
                        best_hp = e.get_current_health()
                        best = e
        return best


func _rotate_turret_toward(target_pos: Vector2) -> void:
        if turret_pivot:
                turret_pivot.look_at(target_pos)


func _attack() -> void:
        if not current_target or not tower_data or not tower_data.projectile_scene:
                return
        var proj: Area2D = tower_data.projectile_scene.instantiate()
        proj.global_position = muzzle.global_position
        var projectiles_container := get_tree().get_first_node_in_group("projectiles_container")
        if projectiles_container:
                projectiles_container.add_child(proj)
        else:
                get_parent().add_child(proj)
        if proj.has_method("initialize"):
                proj.initialize(
                        current_target,
                        tower_data.get_damage_at_level(level),
                        tower_data.splash_radius,
                        tower_data.slow_factor,
                        tower_data.slow_duration,
                        tower_data.projectile_speed
                )


func _draw() -> void:
        if show_range and tower_data:
                var range := tower_data.get_range_at_level(level)
                draw_circle(Vector2.ZERO, range, Color(1.0, 1.0, 1.0, 0.1))
                draw_arc(Vector2.ZERO, range, 0.0, TAU, 64, Color(1.0, 1.0, 1.0, 0.3), 1.0)


func set_show_range(value: bool) -> void:
        show_range = value
        queue_redraw()


func upgrade() -> bool:
        var upgrade_cost := tower_data.get_upgrade_cost(level + 1)
        if not EconomyManager.can_afford(upgrade_cost):
                return false
        if not EconomyManager.spend(upgrade_cost):
                return false
        level += 1
        total_invested += upgrade_cost
        _setup_range()
        queue_redraw()
        return true


func sell() -> void:
        var sell_value := EconomyManager.get_sell_value(total_invested)
        EconomyManager.earn(sell_value)
        queue_free()
```

### scripts/tower_laser.gd

Лазерная башня использует непрерывный урон вместо снарядов. Она рисует луч (Line2D) от дула к цели и наносит урон каждый кадр, умноженный на delta. Это обеспечивает плавный DPS: если tower_data.damage = 40, то при 60 FPS башня наносит 40/60 ≈ 0.67 урона за кадр, что даёт 40 DPS.

```gdscript
extends Node2D

@export var tower_data: TowerData
@export var level: int = 0

var enemies_in_range: Array[CharacterBody2D] = []
var current_target: CharacterBody2D = null
var show_range: bool = false
var total_invested: int = 0
var is_firing: bool = false

@onready var muzzle: Marker2D = %Muzzle
@onready var range_area: Area2D = %RangeArea
@onready var turret_pivot: Node2D = %TurretPivot
@onready var line_2d: Line2D = $Line2D


func _ready() -> void:
        if tower_data:
                total_invested = tower_data.cost
                _setup_range()
        range_area.body_entered.connect(_on_range_entered)
        range_area.body_exited.connect(_on_range_exited)
        if line_2d:
                line_2d.visible = false


func _setup_range() -> void:
        var shape := range_area.get_node("CollisionShape2D").shape as CircleShape2D
        if shape:
                shape.radius = tower_data.get_range_at_level(level)


func _physics_process(delta: float) -> void:
        if not tower_data:
                return
        _find_target()
        if current_target and is_instance_valid(current_target):
                _rotate_turret_toward(current_target.global_position)
                _fire_laser(delta)
        else:
                _stop_laser()


func _fire_laser(delta: float) -> void:
        is_firing = true
        if line_2d:
                line_2d.visible = true
                line_2d.clear_points()
                line_2d.add_point(muzzle.global_position - global_position)
                line_2d.add_point(current_target.global_position - global_position)
        if current_target.has_method("take_damage"):
                current_target.take_damage(tower_data.get_damage_at_level(level) * delta)


func _stop_laser() -> void:
        is_firing = false
        if line_2d:
                line_2d.visible = false


func _on_range_entered(body: Node2D) -> void:
        if body.is_in_group("enemies") and body is CharacterBody2D:
                if not enemies_in_range.has(body):
                        enemies_in_range.append(body)


func _on_range_exited(body: Node2D) -> void:
        if body in enemies_in_range:
                enemies_in_range.erase(body)
                if body == current_target:
                        current_target = null


func _find_target() -> void:
        # Очистка мёртвых врагов
        var to_remove: Array[CharacterBody2D] = []
        for e in enemies_in_range:
                if not is_instance_valid(e) or e.is_queued_for_deletion():
                        to_remove.append(e)
        for e in to_remove:
                enemies_in_range.erase(e)

        if enemies_in_range.is_empty():
                current_target = null
                return
        # Лазер всегда атакует сильнейшую цель для максимального DPS
        current_target = _target_strongest()


func _target_strongest() -> CharacterBody2D:
        var best: CharacterBody2D = null
        var best_hp: float = -1.0
        for e in enemies_in_range:
                if not is_instance_valid(e):
                        continue
                if e.has_method("get_current_health") and e.get_current_health() > best_hp:
                        best_hp = e.get_current_health()
                        best = e
        return best


func _rotate_turret_toward(target_pos: Vector2) -> void:
        if turret_pivot:
                turret_pivot.look_at(target_pos)


func _draw() -> void:
        if show_range and tower_data:
                var range := tower_data.get_range_at_level(level)
                draw_circle(Vector2.ZERO, range, Color(1.0, 1.0, 1.0, 0.1))
                draw_arc(Vector2.ZERO, range, 0.0, TAU, 64, Color(1.0, 1.0, 1.0, 0.3), 1.0)


func set_show_range(value: bool) -> void:
        show_range = value
        queue_redraw()
```

### scripts/enemy_base.gd

Скрипт врага управляет движением по навигации, получением урона, замедлением и смертью. Ключевые моменты: path_progress отслеживает, как далеко враг прошёл по маршруту (используется башнями для стратегии First/Last). Флаг is_dead предотвращает двойной вызов _die(). Замедление учитывает slow_resistance врага: быстрые враги на 30% устойчивы к замедлению.

```gdscript
extends CharacterBody2D

@export var enemy_data: EnemyData

var current_health: float = 0.0
var path_progress: float = 0.0  # 0..1 насколько далеко по пути
var slow_timer: float = 0.0
var current_slow_factor: float = 1.0
var is_dead: bool = false

signal enemy_died(reward: int)
signal enemy_reached_base(lives_cost: int)
signal health_changed(current: float, max_health: float)

@onready var nav_agent: NavigationAgent2D = $NavigationAgent2D


func _ready() -> void:
        if enemy_data:
                current_health = enemy_data.max_health
                nav_agent.path_desired_distance = 4.0
                nav_agent.target_desired_distance = 8.0
                nav_agent.velocity_computation_mode = NavigationAgent2D.VELOCITY_COMPUTATION_MODE_FLOAT
        add_to_group("enemies")


func _physics_process(delta: float) -> void:
        if is_dead:
                return

        # Обновление замедления
        if slow_timer > 0.0:
                slow_timer -= delta
                if slow_timer <= 0.0:
                        current_slow_factor = 1.0

        if nav_agent.is_navigation_finished():
                _reached_base()
                return

        var next_pos: Vector2 = nav_agent.get_next_path_position()
        var direction: Vector2 = (next_pos - global_position).normalized()
        var speed: float = _get_current_speed()
        velocity = direction * speed

        # Обновление прогресса по пути
        var base_point := get_tree().get_first_node_in_group("base_point") as Marker2D
        if base_point:
                var total_dist := nav_agent.distance_to_target()
                # Приблизительная нормализация прогресса
                path_progress = 1.0 - (total_dist / 1000.0)

        nav_agent.set_velocity(velocity)


func _get_current_speed() -> float:
        if not enemy_data:
                return 0.0
        var speed := enemy_data.move_speed
        # Применяем замедление с учётом устойчивости
        var effective_slow := 1.0 - (1.0 - current_slow_factor) * (1.0 - enemy_data.slow_resistance)
        return speed * effective_slow


func take_damage(amount: float) -> void:
        if is_dead:
                return
        current_health = maxf(current_health - amount, 0.0)
        health_changed.emit(current_health, enemy_data.max_health)
        if current_health <= 0.0:
                _die()


func apply_slow(factor: float, duration: float) -> void:
        if is_dead:
                return
        if enemy_data and enemy_data.slow_resistance >= 1.0:
                return  # Иммунитет к замедлению
        current_slow_factor = minf(current_slow_factor, factor)
        slow_timer = maxf(slow_timer, duration)


func get_path_progress() -> float:
        return path_progress


func get_current_health() -> float:
        return current_health


func _die() -> void:
        if is_dead:
                return
        is_dead = true
        if enemy_data:
                enemy_died.emit(enemy_data.gold_reward)
                EconomyManager.earn(enemy_data.gold_reward)
        remove_from_group("enemies")
        queue_free()


func _reached_base() -> void:
        if is_dead:
                return
        is_dead = true
        if enemy_data:
                enemy_reached_base.emit(enemy_data.lives_cost)
                GameManager.lose_life(enemy_data.lives_cost)
        remove_from_group("enemies")
        queue_free()
```

### scripts/projectile.gd

Скрипт снаряда управляет полётом к цели, столкновением и применением эффектов (урон, область поражения, замедление). Ключевой момент: вместо прямого присвоения свойств на Area2D (`proj.target = ...`), используется метод initialize(), который типобезопасно устанавливает все параметры. Проверка is_instance_valid() предотвращает краш при уничтожении цели до попадания снаряда.

```gdscript
extends Area2D

var target: CharacterBody2D = null
var damage: float = 0.0
var splash_radius: float = 0.0
var slow_factor: float = 1.0
var slow_duration: float = 0.0
var speed: float = 300.0
var lifetime: float = 5.0


func initialize(p_target: CharacterBody2D, p_damage: float, p_splash: float,
                p_slow_factor: float, p_slow_duration: float, p_speed: float) -> void:
        target = p_target
        damage = p_damage
        splash_radius = p_splash
        slow_factor = p_slow_factor
        slow_duration = p_slow_duration
        speed = p_speed


func _physics_process(delta: float) -> void:
        lifetime -= delta
        if lifetime <= 0.0:
                queue_free()
                return

        if not is_instance_valid(target) or target.is_queued_for_deletion():
                queue_free()
                return

        var direction: Vector2 = (target.global_position - global_position).normalized()
        global_position += direction * speed * delta

        # Проверка достаточной близости для попадания
        if global_position.distance_to(target.global_position) < 10.0:
                _on_hit()


func _on_hit() -> void:
        if splash_radius > 0.0:
                _apply_splash_damage()
        else:
                if is_instance_valid(target) and target.has_method("take_damage"):
                        target.take_damage(damage)

        if slow_factor < 1.0:
                _apply_slow_effect()

        queue_free()


func _apply_splash_damage() -> void:
        var enemies := get_tree().get_nodes_in_group("enemies")
        for enemy in enemies:
                if not is_instance_valid(enemy):
                        continue
                var dist := global_position.distance_to(enemy.global_position)
                if dist <= splash_radius and enemy.has_method("take_damage"):
                        var falloff := 1.0 - (dist / splash_radius) * 0.5  # 100% в центре, 50% на краю
                        enemy.take_damage(damage * falloff)


func _apply_slow_effect() -> void:
        if splash_radius > 0.0:
                var enemies := get_tree().get_nodes_in_group("enemies")
                for enemy in enemies:
                        if not is_instance_valid(enemy):
                                continue
                        var dist := global_position.distance_to(enemy.global_position)
                        if dist <= splash_radius and enemy.has_method("apply_slow"):
                                enemy.apply_slow(slow_factor, slow_duration)
        else:
                if is_instance_valid(target) and target.has_method("apply_slow"):
                        target.apply_slow(slow_factor, slow_duration)


func _on_area_entered(area: Area2D) -> void:
        # Резервная обработка столкновений
        if area.is_in_group("hurtbox"):
                var parent := area.get_parent()
                if parent != target and splash_radius <= 0.0:
                        return  # Одноцелевые снаряды поражают только цель
                _on_hit()
```

Магазин башен динамически строит список кнопок из TowerRegistry и обрабатывает выбор башни. При нажатии кнопки проверяется возможность оплаты через EconomyManager, и если средств достаточно, башня размещается в выбранном слоте. Кнопки обновляют состояние (disabled) при изменении баланса.

```gdscript
extends CanvasLayer
```

## 3.4 Persistence Layer — сохранение/загрузка

Persistence Layer отвечает за сериализацию и десериализацию состояния игры. SaveManager координирует процесс, собирая данные от всех менеджеров через методы get_save_data() и восстанавливая через load_save_data(). Данные сохраняются в JSON-формат в пользовательскую директорию (user://), что обеспечивает кроссплатформенность.

### scripts/save_manager.gd (Autoload)

SaveManager сохраняет состояние всех менеджеров в единый JSON-файл. Каждый менеджер предоставляет словарь с данными через get_save_data(), а SaveManager объединяет их в общую структуру с временной меткой. При загрузке данные парсятся из JSON и распределяются по менеджерам через load_save_data(). Ошибки парсинга и доступа к файлам обрабатываются с выводом в консоль.

```gdscript
extends Node

const SAVE_PATH := "user://td_save.json"


func save_game() -> bool:
        var data := {
                "game": GameManager.get_save_data(),
                "economy": EconomyManager.get_save_data(),
                "waves": WaveManager.get_save_data(),
                "timestamp": Time.get_unix_time_from_system(),
        }
        var file := FileAccess.open(SAVE_PATH, FileAccess.WRITE)
        if not file:
                push_error("Не удалось открыть файл сохранения для записи")
                return false
        var json_string := JSON.stringify(data, "\t")
        file.store_string(json_string)
        file.close()
        return true


func load_game() -> bool:
        if not FileAccess.file_exists(SAVE_PATH):
                return false
        var file := FileAccess.open(SAVE_PATH, FileAccess.READ)
        if not file:
                return false
        var json_string := file.get_as_text()
        file.close()
        var json := JSON.new()
        if json.parse(json_string) != OK:
                push_error("Не удалось разобрать файл сохранения")
                return false
        var data: Dictionary = json.data
        if data.has("game"):
                GameManager.load_save_data(data["game"])
        if data.has("economy"):
                EconomyManager.load_save_data(data["economy"])
        if data.has("waves"):
                WaveManager.load_save_data(data["waves"])
        return true


func delete_save() -> void:
        if FileAccess.file_exists(SAVE_PATH):
                DirAccess.remove_absolute(SAVE_PATH)
```

**Интеграция с менеджерами:** Каждый менеджер реализует пару методов get_save_data() / load_save_data(). Это паттерн, который мы видим в GameManager, EconomyManager и WaveManager. Данные сохраняются как плоские словари с простыми типами (int, float, bool, String), которые JSON сериализует без проблем. При добавлении новых менеджеров достаточно добавить их данные в метод save_game().

**Ограничения текущей реализации:** Мы не сохраняем состояние установленных башен и позиций врагов — это потребовало бы более сложной сериализации с сохранением ссылок на TowerData и EnemyData. В расширенной версии можно добавить сохранение массива башен с их типами, позициями и уровнями.

## 3.5 Введение в C++ и GDExtension

GDExtension — это система расширения Godot 4, которая позволяет писать высокопроизводительный код на C++ и интегрировать его в проект как обычные классы Godot. Это не модуль引擎 (который требует перекомпиляции всего движка), а динамическая библиотека, загружаемая во время выполнения. Это означает, что вы можете добавлять C++ классы в проект без изменения исходного кода Godot.

### GDExtension vs GDNative

| Характеристика | GDNative (Godot 3) | GDExtension (Godot 4) |
|---|---|---|
| Доступ к API | Через C-обёртку, ограниченный | Прямой доступ к внутреннему API Godot |
| ABI стабильность | Ограниченная, частые поломки | Стабильный ABI между минорными версиями |
| Производительность | Хорошая, но с накладными расходами | Лучшая (минимальные накладные расходы) |
| Привязка классов | Ручная регистрация, много макросов | Автоматическая через GDCLASS и ClassDB |
| Система сборки | SCons | SCons (рекомендуется) или CMake |
| Статус | Устаревший, не поддерживается | Активно развивается, официальный подход |
| Точка входа | `gdnative_init` | `gdext_init` |

### Настройка среды сборки

Для работы с GDExtension вам понадобятся три компонента:

1. **Компилятор C++:** GCC или Clang на Linux, MSVC (Visual Studio Build Tools) на Windows
2. **Система сборки SCons:** `pip install scons` (требуется Python 3.6+)
3. **godot-cpp:** Библиотека привязок C++ к API Godot, клонируется как подмодуль Git

```bash
# Клонирование godot-cpp (используйте ветку, соответствующую вашей версии Godot)
cd /path/to/project/cpp
git clone --recurse-submodules https://github.com/godotengine/godot-cpp.git
cd godot-cpp
git checkout 4.2  # для Godot 4.2.x; используйте 4.3 для Godot 4.3.x

# Сборка
cd /path/to/project/cpp
scons
```

### Первый C++ класс — TDUtils

Создадим утилитарный класс TDUtils, который предоставляет статический метод предсказания точки перехвата движущейся цели. Это полезно для опережающей стрельбы башен: вместо стрельбы в текущую позицию врага, башня стреляет туда, где враг будет через время полёта снаряда. Метод predict_intercept() решает квадратное уравнение для нахождения времени перехвата.

```cpp
// src/td_utils.h
#pragma once

#include <godot_cpp/classes/ref_counted.hpp>
#include <godot_cpp/core/class_db.hpp>

namespace td {

class TDUtils : public godot::RefCounted {
        GDCLASS(TDUtils, RefCounted)

public:
        static float predict_intercept(
                const godot::Vector2& shooter_pos,
                const godot::Vector2& target_pos,
                const godot::Vector2& target_vel,
                float projectile_speed);

protected:
        static void _bind_methods();
};

} // namespace td
```

```cpp
// src/td_utils.cpp
#include "td_utils.h"
#include <godot_cpp/variant/utility_functions.hpp>

namespace td {

float TDUtils::predict_intercept(
                const godot::Vector2& shooter_pos,
                const godot::Vector2& target_pos,
                const godot::Vector2& target_vel,
                float projectile_speed) {
        godot::Vector2 delta = target_pos - shooter_pos;
        float a = target_vel.length_squared() - projectile_speed * projectile_speed;
        float b = 2.0f * target_vel.dot(delta);
        float c = delta.length_squared();
        float disc = b * b - 4.0f * a * c;
        if (disc < 0.0f) {
                return -1.0f; // Решения нет — цель слишком быстрая
        }
        float t = (-b - godot::Math::sqrt(disc)) / (2.0f * a);
        return t > 0.0f ? t : -1.0f;
}

void TDUtils::_bind_methods() {
        using namespace godot;
        ClassDB::bind_static_method(
                "TDUtils", D_METHOD("predict_intercept",
                "shooter_pos", "target_pos", "target_vel", "proj_speed"),
                &TDUtils::predict_intercept);
}

} // namespace td
```

### register_types.cpp

Файл register_types.cpp содержит точку входа GDExtension — функцию gdext_init, которую Godot вызывает при загрузке библиотеки. Эта функция регистрирует все C++ классы через ClassDB::register_class. Обратите внимание на правильную точку входа: `gdext_init`, а не `gdext_rust_init`.

```cpp
        if (p_level != godot::MODULE_INITIALIZATION_LEVEL_SCENE) {
                return;
        }
}

} // namespace td

extern "C" {
```

### PathFinder C++ класс

PathFinder реализует алгоритм A* для поиска кратчайшего пути на сетке. В отличие от встроенной навигации Godot, которая работает с навигационными полигонами, наш PathFinder работает с регулярной сеткой, где каждая ячейка имеет стоимость прохода. Это упрощает интеграцию с тайловой картой и позволяет динамически обновлять проходимость при установке/продаже башен.

```cpp
// src/path_finder.h
#pragma once

#include <godot_cpp/classes/ref_counted.hpp>
#include <godot_cpp/core/class_db.hpp>
#include <godot_cpp/variant/packed_vector2_array.hpp>
#include <vector>
#include <queue>
#include <unordered_map>

namespace td {

struct GridNode {
        int x;
        int y;
        float g_cost;  // Стоимость от старта
        float h_cost;  // Эвристика до цели
        float f_cost() const { return g_cost + h_cost; }
        bool operator>(const GridNode& other) const { return f_cost() > other.f_cost(); }
};

class PathFinder : public godot::RefCounted {
        GDCLASS(PathFinder, RefCounted)

private:
        int grid_width = 0;
        int grid_height = 0;
        std::vector<float> cost_grid;  // Стоимость прохода каждой ячейки

        float _heuristic(const godot::Vector2i& a, const godot::Vector2i& b) const;
        bool _is_valid(int x, int y) const;
        godot::Vector2i _world_to_grid(const godot::Vector2& world_pos, float cell_size) const;
        godot::Vector2 _grid_to_world(int x, int y, float cell_size) const;

public:
        void set_grid(int w, int h, const godot::PackedFloat32Array& costs);
        godot::PackedVector2Array find_path(
                const godot::Vector2i& start,
                const godot::Vector2i& end) const;
        void set_cell_cost(int x, int y, float cost);
        float get_cell_cost(int x, int y) const;

protected:
        static void _bind_methods();
};

} // namespace td
```

```cpp
// src/path_finder.cpp
#include "path_finder.h"
#include <godot_cpp/variant/utility_functions.hpp>
#include <cmath>
#include <algorithm>

namespace td {

void PathFinder::set_grid(int w, int h, const godot::PackedFloat32Array& costs) {
        grid_width = w;
        grid_height = h;
        cost_grid.clear();
        cost_grid.reserve(w * h);
        for (int i = 0; i < costs.size() && i < w * h; ++i) {
                cost_grid.push_back(costs[i]);
        }
        // Заполняем оставшиеся ячейки стоимостью 1.0 (проходимые)
        while ((int)cost_grid.size() < w * h) {
                cost_grid.push_back(1.0f);
        }
}

godot::PackedVector2Array PathFinder::find_path(
                const godot::Vector2i& start,
                const godot::Vector2i& end) const {
        godot::PackedVector2Array result;

        if (!_is_valid(start.x, start.y) || !_is_valid(end.x, end.y)) {
                return result;
        }
        if (cost_grid[end.y * grid_width + end.x] < 0.0f) {
                return result; // Цель непроходима
        }

        // A* с приоритетной очередью
        std::priority_queue<GridNode, std::vector<GridNode>, std::greater<GridNode>> open;
        std::unordered_map<int, float> g_scores;
        std::unordered_map<int, int> came_from;

        auto key = [](int x, int y) -> int { return y * 10000 + x; };

        GridNode start_node{start.x, start.y, 0.0f, _heuristic(start, end)};
        open.push(start_node);
        g_scores[key(start.x, start.y)] = 0.0f;

        // 8 направлений: 4 кардинальных + 4 диагональных
        const int dx[] = {-1, 0, 1, 0, -1, -1, 1, 1};
        const int dy[] = {0, -1, 0, 1, -1, 1, -1, 1};
        const float diag_cost = 1.414f;

        int iterations = 0;
        const int max_iterations = grid_width * grid_height * 2;

        while (!open.empty() && iterations < max_iterations) {
                iterations++;
                GridNode current = open.top();
                open.pop();

                if (current.x == end.x && current.y == end.y) {
                        // Восстановление пути
                        int cx = end.x, cy = end.y;
                        while (cx != start.x || cy != start.y) {
                                result.append(godot::Vector2(cx, cy));
                                int k = key(cx, cy);
                                if (came_from.find(k) == came_from.end()) break;
                                int prev = came_from.at(k);
                                cx = prev % 10000;
                                cy = prev / 10000;
                        }
                        result.append(godot::Vector2(start.x, start.y));
                        result.reverse();
                        return result;
                }

                for (int i = 0; i < 8; ++i) {
                        int nx = current.x + dx[i];
                        int ny = current.y + dy[i];

                        if (!_is_valid(nx, ny)) continue;

                        float cell_cost = cost_grid[ny * grid_width + nx];
                        if (cell_cost < 0.0f) continue; // Непроходимая ячейка

                        float move_cost = (i < 4) ? cell_cost : cell_cost * diag_cost;
                        float tentative_g = current.g_cost + move_cost;
                        int nk = key(nx, ny);

                        if (g_scores.find(nk) == g_scores.end() || tentative_g < g_scores[nk]) {
                                g_scores[nk] = tentative_g;
                                came_from[nk] = key(current.x, current.y);
                                GridNode neighbor{nx, ny, tentative_g, _heuristic(
                                        godot::Vector2i(nx, ny), end)};
                                open.push(neighbor);
                        }
                }
        }

        return result; // Путь не найден
}

void PathFinder::set_cell_cost(int x, int y, float cost) {
        if (_is_valid(x, y)) {
                cost_grid[y * grid_width + x] = cost;
        }
}

float PathFinder::get_cell_cost(int x, int y) const {
        if (_is_valid(x, y)) {
                return cost_grid[y * grid_width + x];
        }
        return -1.0f;
}

float PathFinder::_heuristic(const godot::Vector2i& a, const godot::Vector2i& b) const {
        // Октольная (Chebyshev) эвристика для 8-направленного движения
        float dx = (float)godot::Math::abs(a.x - b.x);
        float dy = (float)godot::Math::abs(a.y - b.y);
        return godot::Math::max(dx, dy) + (1.414f - 1.0f) * godot::Math::min(dx, dy);
}

bool PathFinder::_is_valid(int x, int y) const {
        return x >= 0 && x < grid_width && y >= 0 && y < grid_height;
}

void PathFinder::_bind_methods() {
        using namespace godot;
        ClassDB::bind_method(
                D_METHOD("set_grid", "width", "height", "costs"),
                &PathFinder::set_grid);
        ClassDB::bind_method(
                D_METHOD("find_path", "start", "end"),
                &PathFinder::find_path);
        ClassDB::bind_method(
                D_METHOD("set_cell_cost", "x", "y", "cost"),
                &PathFinder::set_cell_cost);
        ClassDB::bind_method(
                D_METHOD("get_cell_cost", "x", "y"),
                &PathFinder::get_cell_cost);
}

} // namespace td
```

### ProjectileSimulator C++ класс

ProjectileSimulator реализует пакетную обработку снарядов с data-oriented подходом. Вместо того, чтобы каждый снаряд был отдельным узлом в дереве сцен (что создаёт накладные расходы на каждый узел), мы храним данные всех снарядов в непрерывном массиве структур и обрабатываем их за один проход. Это значительно повышает эффективность использования кэша процессора.

```cpp
// src/projectile_sim.h
#pragma once

#include <godot_cpp/classes/node.hpp>
#include <godot_cpp/core/class_db.hpp>
#include <godot_cpp/variant/packed_vector2_array.hpp>
#include <vector>

namespace td {

struct ProjectileData {
        godot::Vector2 position;
        godot::Vector2 velocity;
        float damage = 0.0f;
        float splash_radius = 0.0f;
        float slow_factor = 1.0f;
        float slow_duration = 0.0f;

        GDCLASS(ProjectileSimulator, Node)

public:
        void _physics_process(double delta) override;
        int add_projectile(const godot::Vector2& pos, const godot::Vector2& vel,
                float damage, float splash, float slow_factor, float slow_duration);

        int get_active_count() const;
        godot::PackedVector2Array get_all_positions() const;

        static void _bind_methods();
};
```

```cpp
// src/projectile_sim.cpp
#include "projectile_sim.h"
#include <godot_cpp/variant/utility_functions.hpp>

namespace td {

void ProjectileSimulator::_physics_process(double delta) {
        float dt = (float)delta;
        _positions_cache.clear();

        for (auto& p : projectiles) {
                if (!p.active) continue;

                p.position += p.velocity * dt;
                p.lifetime -= dt;

                if (p.lifetime <= 0.0f) {
                        p.active = false;
                        continue;
                }

                _positions_cache.append(p.position);
        }
}

int ProjectileSimulator::add_projectile(
                const godot::Vector2& pos,
                const godot::Vector2& vel,
                float damage,
                float splash,
                float slow_factor,
                float slow_duration) {
        // Найти свободный слот или добавить новый
        for (size_t i = 0; i < projectiles.size(); ++i) {
                if (!projectiles[i].active) {
                        projectiles[i] = {pos, vel, damage, splash, slow_factor, slow_duration, 5.0f, true, 0};
                        return (int)i;
                }
        }

        if ((int)projectiles.size() >= max_projectiles) {
                // Переполнение — деактивируем самый старый
                projectiles[0] = {pos, vel, damage, splash, slow_factor, slow_duration, 5.0f, true, 0};
                return 0;
        }

        projectiles.push_back({pos, vel, damage, splash, slow_factor, slow_duration, 5.0f, true, 0});
        return (int)projectiles.size() - 1;
}

void ProjectileSimulator::clear() {
        projectiles.clear();
        _positions_cache.clear();
}

int ProjectileSimulator::get_active_count() const {
        int count = 0;
        for (const auto& p : projectiles) {
                if (p.active) ++count;
        }
        return count;
}

godot::PackedVector2Array ProjectileSimulator::get_all_positions() const {
        godot::PackedVector2Array positions;
        for (const auto& p : projectiles) {
                if (p.active) {
                        positions.append(p.position);
                }
        }
        return positions;
}

void ProjectileSimulator::_bind_methods() {
        using namespace godot;
        ClassDB::bind_method(
                D_METHOD("add_projectile", "pos", "vel", "damage", "splash",
                        "slow_factor", "slow_duration"),
                &ProjectileSimulator::add_projectile);
        ClassDB::bind_method(
                D_METHOD("clear"),
                &ProjectileSimulator::clear);
        ClassDB::bind_method(
                D_METHOD("get_active_count"),
                &ProjectileSimulator::get_active_count);
        ClassDB::bind_method(
                D_METHOD("get_all_positions"),
                &ProjectileSimulator::get_all_positions);
}

} // namespace td
```

- ➕ **Система квестов** — QuestData/QuestObjective как Resource, отслеживание целей, награды
- ➕ **Цикл день/ночь** — DirectionalLight3D, расписание NPC, вариация врагов

А также впервые встретимся с:

- ⚡ **Переход в 3D** — всё, что вы знали о 2D, обретёт новое измерение. CharacterBody2D становится CharacterBody3D, Area2D — Area3D, TileMap — MeshInstance3D, Camera2D — Camera3D с SpringArm3D. Навигация переходит от NavigationRegion2D к NavigationRegion3D с запеканием navmesh. Но главное — камера перестаёт быть наблюдателем и становится активной системой: она обходит стены, следует за персонажем с инерцией и переключается в кинематографический режим для кат-сцен. Это качественно иной уровень сложности и свободы.
