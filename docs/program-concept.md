# Концепция программы: Godot Learning Platform

> **Версия:** 1.0  
> **Дата:** 2026-06-02  
> **Статус:** Черновик  
> **Стек:** Next.js 16 + TypeScript + Tailwind CSS 4 + Prisma + SQLite/PostgreSQL

---

## 1. Видение

Godot Learning Platform — интерактивное веб-приложение для прохождения проектного курса разработки игр на Godot Engine. Платформа объединяет контент курса, инструменты практики и социальные функции в единой экосистеме, которая борется с «Tutorial Hell» через активное обучение.

## 2. Фазы разработки

### Фаза 1: MVP — Базовая платформа (6-8 недель)
Интерактивная читалка курсов с встроенным GDScript Playground, прогресс-трекингом и геймификацией. Полностью функциональна как самостоятельный продукт.

### Фаза 2: Godot Web Editor — Pro подписка (4-6 недель)
Интеграция Godot Web Editor для создания 2D-игр прямо в браузере. Cloud-сохранение проектов. Автопроверка домашних заданий через запуск сцен.

### ~~Фаза 3: Cloud Workspaces~~
*Отложена до лучших времён. C++ разработка требует нативного окружения, что дорого и сложно.*

### 3.2. Структура страниц

#### `/` — Главная (Landing)
- Герой-секция с анимацией (Godot-стилистика)
- Карта из 6 проектов с кратким описанием
- Кнопка «Начать бесплатно»
- Секция «Почему этот курс» (уникальные преимущества)
- Отзывы / социальные доказательства (заглушки для MVP)

#### `/learn` — Карта прогресса (Learning Path)
- Визуальная карта из 6 проектов, связанных линиями
- Каждый проект раскрывается в главы
- Цветовая индикация: 🟢 Пройдено / 🟡 В процессе / ⬜ Не начато
- Теги навыков под каждым проектом
- Общий прогресс-бар курса

#### `/learn/[project]/[chapter]` — Читатель урока
- MDX-рендеринг с подсветкой кода (GDScript + C++)
- Встроенные диаграммы Mermaid
- Сворачиваемые секции с подсказками
- Кнопка «Я выполнил задание» → прогресс обновляется
- Навигация: предыдущий/следующий раздел
- Боковая панель с оглавлением главы
- «Шпаргалка» — быстрый справочник по теме

#### `/challenge/[id]` — Челлендж
- Описание задачи + ожидаемый результат
- Monaco Editor с подсветкой GDScript
- Кнопка «Запустить» → выполнение через GDScript Playground (WASM)
- Кнопка «Проверить» → автопроверка по тест-кейсам
- Сравнение с референсным решением (после попытки)
- 3 уровня сложности: 🟢 Базовый / 🟡 Продвинутый / 🔴 Экспертный

#### `/dashboard` — Дашборд
- Радарная диаграмма навыков (GDScript, C++, 2D, 3D, Patterns, Optimization)
- Прогресс по каждому проекту
- Стрик (дни подряд)
- XP и уровень
- Бейджи
- Рекомендации: «Что делать дальше?»

#### `/profile` — Профиль
- Имя, аватар, дата регистрации
- Статистика: время обучения, выполненные челленджи
- Список бейджей
- Настройки (тема, уведомления)

### 3.3. Геймификация

| Элемент | Описание |
|---------|----------|
| **XP** | Опыт за: чтение глав (+10 XP), челленджи (+20-50 XP), спринты (+100 XP) |
| **Уровни** | Каждые 500 XP = новый уровень. 20 уровней: от «Новичок» до «Архитектор» |
| **Бейджи** | «Первый сигнал» (первый сигнал), «C++ мастер» (P4+), «3D исследователь» (P5), «Оптимизатор» (P6), «Стрик 7 дней», «Стрик 30 дней», «Все челленджи P1» |

| **Сертификат** | Генерируется по завершении всех 6 проектов |

```
┌─────────────────────────────────────────────┐

│  Создайте кнопку, которая при нажатии       │
│  увеличивает счётчик на 1 и выводит         │
│  значение в консоль.                        │
│                                             │
│  ┌─ Monaco Editor ───────────────────────┐  │
│  │ extends Control                        │  │
│  │                                        │  │
│  │ var counter = 0                        │  │
│  │                                        │  │
│  │ func _ready():                         │  │
│  │   $Button.pressed.connect(_on_press)   │  │
│  │                                        │  │
│  │ func _on_press():                      │  │
│  │   # Ваш код здесь...                   │  │
│  │   pass                                 │  │
│  └────────────────────────────────────────┘  │
│                                             │
│  [▶ Запустить]  [✓ Проверить]  [💡 Подсказка]│
│                                             │
│  Вывод: ✅ Тест 1 пройден (counter = 1)     │
│         ✅ Тест 2 пройден (counter = 5)     │
│         ✅ Тест 3 пройден (signal emitted)  │
└─────────────────────────────────────────────┘
```

**Техническая реализация:**
- Monaco Editor (от VS Code) с кастомной подсветкой GDScript
- GDScript WASM runtime для выполнения кода в браузере
- Тест-кейсы описываются в JSON: `{ input, expected, description }`
- Результат: pass/fail по каждому тесту
- Таймаут выполнения: 5 секунд

### 4.3. Жизненный цикл проекта

```
1. Ученик открывает главу → видит задание + кнопку "Открыть проект"
2. Нажимает → создаётся сессия:
   - Из шаблона копируется starter-project в S3
   - Генерируется уникальный sessionId
   - Открывается iframe с Godot Web Editor
3. Ученик работает в Godot:
   - Все изменения автосохраняются в S3 каждые 30 сек
   - Кнопка "Запустить" — тестирование в редакторе
4. Ученик нажимает "Сдать":
   - Проект экспортируется (zip)
   - Запускается автопроверка:
     a. Загрузка проекта в Godot headless
     b. Выполнение тест-сцен (GUT framework)
     c. Сравнение результатов с эталоном
   - Результат: pass/fail + фидбек
5. Проект сохраняется в портфолио ученика
```

### 4.4. Starter-шаблоны проектов

Каждый проект начинается с преднастроенного шаблона:

| Проект | Шаблон содержит |
|--------|----------------|
| P1: Кликер | Базовая UI-сцена, пустой скрипт Game.gd, ресурсы иконок |
| P2: Шутер | Игрок с движением, базовая пуля, звёздный фон |
| P3: Метроидвания | Персонаж с платформер-контроллером, пустой TileMap |
| P4: Tower Defense | Сетка, базовый тайл пути, пустой скрипт волны |

### 4.5. Автопроверка домашних заданий

**Механизм:**
1. В шаблон проекта встроены тестовые сцены (GUT — Godot Unit Test)
2. При сдаче — Godot headless запускает тестовые сцены
3. Тесты проверяют:
   - Существование определённых нодов в сцене
   - Корректность сигналов
   - Значения переменных
   - Поведение при определённых событиях

**Пример теста (GDScript):**
```gdscript
extends GutTest

func test_upgrade_button_increases_income():
  var game = load("res://scenes/game.tscn").instantiate()
  add_child(game)
  
  var initial_income = game.income_per_second
  game._on_upgrade_pressed()
  
  assert_gt(game.income_per_second, initial_income, 
    "Income should increase after upgrade")
  assert_eq(game.income_per_second, initial_income * 2,
    "Upgrade should double the income")
```

### 4.6. Ограничения и риски

| Риск | Влияние | Митигация |
|------|---------|-----------|
| SharedArrayBuffer не поддерживается в Safari | Часть пользователей не сможет использовать редактор | Чёткое предупреждение + fallback: скачивание проекта для локальной работы |
| Медленная загрузка WASM (~30-50 MB) | Долгое ожидание при открытии | Preloading, кеширование, загрузочный экран с прогрессом |
| Нет C++/GDExtension в браузере | Проекты 4-6 не работают в Web Editor | Инструкция по локальной установке + скачивание проекта |
| Ограничения WebGL для 3D | Проект 5 может работать медленно | Снижение качества + рекомендация использовать нативный редактор |
| Стоимость серверов | S3 storage + compute для автопроверки | Лимиты по подписке + квоты |
