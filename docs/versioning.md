# Политика версионирования Godot Learning Platform

> Документ описывает правила версионирования проекта в соответствии с Semantic Versioning (SemVer 2.0.0).

---

## Формат версии

Версия имеет формат **MAJOR.MINOR.PATCH**, где:

- **MAJOR** — увеличивается при несовместимых изменениях API или архитектуры
- **MINOR** — увеличивается при добавлении нового функционала с обратной совместимостью
- **PATCH** — увеличивается при исправлении багов с обратной совместимостью

Пример: `0.4.0` → MAJOR=0, MINOR=4, PATCH=0

---

## Единый источник правды

Версия приложения хранится в **одном месте** — файл `VERSION` в корне проекта.

Все остальные источники (`package.json`, UI, API) читают версию из этого файла.

### Чтение версии в package.json

Поле `version` в `package.json` обновляется автоматически при сборке или вручную при релизе. Оно должно всегда совпадать с содержимым `VERSION`.

### Отображение в UI

Версия отображается в Footer приложения. Компонент читает версию из константы, которая экспортируется из `lib/version.ts`.

## Правила изменения версии

### PATCH (0.4.0 → 0.4.1)

Увеличивается при:

- Исправлении багов (включая визуальные и CSS-фиксы)
- Обновлении текстового контента глав (опечатки, формулировки)
- Небольших рефакторингах, не меняющих поведение
- Обновлении зависимостей (patch-версии)
- Добавлении тестов для существующего функционала

### MINOR (0.4.0 → 0.5.0)

Увеличивается при:

- Добавлении нового проекта курса (новый набор глав)
- Добавлении новых страниц или разделов платформы
- Добавлении новых компонентов или фич (XP-система, достижения, прогресс-бар)
- Расширении API (новые эндпоинты)
- Добавлении нового MDX-компонента (Callout, Insight, MermaidDiagram и т.д.)
- Изменении навигации или структуры разделов
- Обновлении зависимостей (minor-версии)

При увеличении MINOR, PATCH сбрасывается в 0.

### MAJOR (0.4.0 → 1.0.0)

Увеличивается при:

- Публичном релизе (переход из разработки в production)
- Кардинальном изменении архитектуры (смена фреймворка, БД)
- Несовместимых изменениях API
- Удалении или перемещении существующих URL-маршрутов

При увеличении MAJOR, MINOR и PATCH сбрашиваются в 0.

---

## Статус Pre-release (0.x.x)

Пока MAJOR = 0, приложение считается в стадии разработки. Это означает:

- API может меняться без предупреждения
- Структура контента может перестраиваться
- MINOR-версии могут содержать несовместимые изменения
- Переход к 1.0.0 означает стабильный публичный релиз

---

## Процесс релиза

1. Определить тип изменений (PATCH / MINOR / MAJOR)
2. Обновить файл `VERSION`
3. Обновить `version` в `package.json` (должно совпадать с `VERSION`)
4. Обновить `lib/version.ts` (константа `APP_VERSION`)
5. Выполнить сборку (`npm run build`) и проверить, что всё работает
6. Закоммитить с сообщением: `chore(release): vX.Y.Z`
7. Добавить тег: `git tag vX.Y.Z`
8. Запушить: `git push && git push --tags`
