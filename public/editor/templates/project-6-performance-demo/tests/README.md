# Тесты проекта «Демо производительности»

## Структура

```
tests/
├── README.md              — Этот файл
└── test_performance.gd    — Тесты систем производительности
```

## Фреймворк

Тесты написаны с использованием **GUT 9.x** для **Godot 4.x**.

Все тестовые скрипты наследуются от `GutTest` и используют встроенные утверждения:

| Утверждение         | Описание                              |
|---------------------|---------------------------------------|
| `assert_true()`     | Проверяет, что значение `true`        |
| `assert_eq()`       | Проверяет равенство двух значений     |
| `assert_gt()`       | Проверяет, что первое > второго       |
| `assert_lt()`       | Проверяет, что первое < второго       |
| `assert_not_null()` | Проверяет, что значение не `null`     |

## Список тестов

| Тест                           | Что проверяет                                    |
|--------------------------------|--------------------------------------------------|
| `test_object_pool_reuse`       | Пул объектов повторно использует возвращённые объекты |
| `test_object_pool_size_limit`  | Пул объектов ограничивает максимальное количество |
| `test_batch_render_count`      | Батч-рендерер отслеживает количество объектов    |
| `test_memory_usage_within_limit`| Использование памяти ниже заданного порога      |
| `test_fps_above_threshold`     | FPS выше минимально допустимого порога           |
| `test_lod_system_switches`     | LOD-система переключает уровни детализации       |

## Запуск тестов

1. Установите GUT: https://github.com/bitwes/Gut
2. Скопируйте `.gutconfig.json` из `shared/` в корень проекта
3. Запустите через командную строку:
   ```bash
   godot --path . -s addons/gut/gut_cmdln.gd
   ```
   Или через редактор: сцена `addons/gut/GutScene.tscn`

## Зависимые скрипты

Для работы тестов (без заглушек) необходимо реализовать:

- `res://scripts/object_pool.gd` — пул объектов (переиспользование, лимиты)
- `res://scripts/pooled_object.gd` — объект, совместимый с пулом
- `res://scripts/batch_renderer.gd` — батч-рендеринг
- `res://scripts/performance_monitor.gd` — мониторинг FPS и памяти
- `res://scripts/lod_system.gd` — система уровней детализации

## Архитектура LOD

Система LOD определяет уровень детализации на основе расстояния до камеры:

```
Расстояние 0–10м   → LOD 0 (высокая детализация)
Расстояние 10–30м  → LOD 1 (средняя детализация)
Расстояние 30–100м → LOD 2 (низкая детализация)
Расстояние > 100м  → объект не рендерится
```

## Примечание

Все тесты содержат **заглушки** (assert_true(true)) и закомментированные реальные проверки.
После реализации соответствующих скриптов раскомментируйте тесты и удалите заглушки.

Тесты FPS и памяти могут требовать запуска в реальном игровом контексте,
поскольку в тестовой среде показатели Performance могут не отражать реальную ситуацию.
